compiler-dom

compiler-dom 没有另起一套编译管线。它做的事更具体：给 compiler-core 补上浏览器平台知识，再把同一棵 AST 交回 core 完成转换和代码生成。

入口：compile()目标：client render版本：Vue 3.5.41 · 11cd09cf
证据基线与阅读边界

本页逐项核对 commit 11cd09cf54a878ec70d3dcca14520b4c4ec267b9 中 packages/compiler-dom/src 与对应 __tests__。本文覆盖客户端模板的 parse、transform、generate；SFC block 切分、SSR 产物和 runtime-dom 指令内部实现只在接口交界处说明。

它负责

HTML 模式所需的平台判断、DOM 节点转换、原生指令分派、DOM runtime helper 注册和静态 HTML 序列化。

它复用

compiler-core 的 AST、结构指令、表达式处理、作用域追踪、静态提升、 patch flag 计算与代码生成。

它不负责

不切分 .vue 文件，不生成 SSR 字符串，也不实现 vModelText、withKeys 等运行时 helper。

01 / Assembly

compile() 与 parse()：一份平台默认值，两条入口

parse() 只产出 DOM 语义 AST；compile() 则装好平台插件后调用 baseCompile()，继续走 core 的 parse → transform → generate。

两层装配，不是两套编译器

DOM compile平台默认值 → 用户 options → 强制字段
→
core baseCompilecore 预设 → DOM/用户插件
→
CodegenResultast / code / preamble / map

字符串与 RootNode 走法不同

compile(string) 会把合并后的选项交给 core parser；若 src 已是 RootNode，baseCompile 直接跳过 parse。后一条路让上层工具复用已解析 AST。

parse() 不做转换

parse(template, options) 只合并 parserOptions 并调用 baseParse。返回节点没有 codegenNode；也不会执行 style、v-model 或 v-on 转换。

DEV 转换按构建常量装入

Transition children 校验与 HTML nesting 校验只在 __DEV__ 时进入数组；生产构建没有这两次遍历检查。 ignoreSideEffectTags 则开发、生产都执行，只是生产不报诊断。

浏览器版关闭 stringifyStatic

最后一层对象字面量把 transformHoist 固定为：浏览器构建 null，Node 构建 stringifyStatic。同名选项的最终值来自入口最后一层，调用方设置会被覆盖；这里不是可扩展槽。

选项组 最终顺序 / 胜者 调用方能否覆盖
普通 parser/codegen 选项 parserOptions → options 能；例如 isCustomElement、ns、错误回调。
nodeTransforms core 预设 → ignoreSideEffectTags → DOMNodeTransforms → 用户数组 只能追加，不能用同名覆盖或删掉平台转换。
directiveTransforms core 表 → DOM 表 → 用户表 能；用户同名键最后覆盖，包括 model/on。
transformHoist 浏览器 null；Node stringifyStatic 不能；DOM 入口最后写入。
prefixIdentifiers 进入 core 后重新计算：非浏览器且显式开启，或 mode: 'module' 不能靠传 false 关闭 module mode 的前缀；浏览器构建也会拒绝不支持的组合。
容易看漏的第二次合并：compile() 先组装 DOM 选项，baseCompile() 又把 core 预设放到节点数组前面、放到指令表底层。因此“DOMNodeTransforms 数组从 style 开始”不等于整个遍历从 style 开始。

ignoreSideEffectTags 刻意不放进导出的 DOMNodeTransforms。源码注释给出的理由是 compiler-ssr 会复用该数组生成组件 VNode fallback；副作用标签删除只应由客户端入口单独前置。

02 / Parser Options

HTML 不是“普通 XML”

core 实现 tokenizer 状态机；compiler-dom 选择 HTML 模式，并提供 namespace、标签分类与浏览器实体解码等平台判断。

平台直接提供的标签判断

  • isVoidTag：img、input 等无需结束标签。
  • isPreTag：pre 保留空白。
  • isIgnoreNewlineTag：pre/textarea 丢掉开标签后的一个换行。
  • isNativeTag：HTML/SVG/MathML 元素。
  • isBuiltInComponent：Transition、TransitionGroup。

调用方补入的判断

  • isCustomElement 不在 DOM 默认对象里，由用户 options 提供；命中后标签保持原生元素路径。
  • ns 可把整次解析的根上下文设为 SVG/MathML。
  • onError/onWarn 决定诊断是抛出还是收集。
  • 这些键因 options 后合并，可覆盖平台默认值。
所在上下文 内容模式 &amp; / {{ x }}
普通 HTML 元素 DATA：继续识别标签、实体与插值 实体解码；插值建 INTERPOLATION
HTML textarea/title RCDATA：内部标签只是文本 实体解码；Vue 仍识别插值
HTML script/style RAWTEXT：只寻找严格匹配的闭标签 实体不解码；插值不展开
SVG/MathML XML 上下文 不套用 HTML 特殊标签模式 例如 SVG 根下的 script 后代仍按元素解析
<pre> 与 v-pre 不是一回事： 前者由平台的 isPreTag 控制空白整理，仍会编译插值与指令；后者是 core parser 的 Vue 语法开关，会把整棵子树的指令和插值按普通属性、文本处理。

职责要分清：RCDATA/RAWTEXT 的状态机在 compiler-core tokenizer 中；parseMode: 'html' 和 inXML 决定是否启用它。compiler-dom 没有重写 tokenizer， 它提供的是让同一状态机按浏览器规则运行所需的平台上下文。

命名空间由父子关系决定

只查 tag 会得出错误结论：title 在 HTML 和 SVG 中都合法，它的解析规则取决于 parent.ns。所以 parser 每建一个元素都把父节点交给平台函数。

foreignObject 是 SVG 中的 HTML 岛

<svg><foreignObject><div> 中 div 必须回到 HTML 规则，否则浏览器创建的节点类型、class 设置和 hydration 对比都会出错。

MathML 有更细的集成点

annotation-xml 根据 encoding 切回 HTML，mtext/mi/mo/mn/ms 也允许 HTML 内容，但 mglyph/malignmark 是例外。这些是 HTML parser 标准事实，不应污染 compiler-core。

实体解码按构建分流

浏览器构建中，parser 收到 tokenizer 的原始片段后调用 decodeHtmlBrowser；这个函数复用一个临时 div，并区分文本与属性模式。 Node 构建中该选项是 undefined，core tokenizer 使用 entities 解码器。两条路都保留文本与属性的不同实体规则。

pre 的两条规则

进入 HTML pre 时 inPre++，关闭时才恢复；因此嵌套元素文本也不折叠。关闭 pre 时另删掉它直接首文本节点的一个 \n，嵌套 div 的首换行不删。

namespace 是逐子节点计算

parser 创建每个元素时调用 getNamespace(tag, parent, rootNamespace)。结果写入 ElementNode.ns，同时控制 tokenizer 是否处于 XML 上下文。

03 / Node Transforms

平台节点转换处理什么

只有无法由通用 AST 语义表达、且与客户端 DOM 行为直接相关的逻辑才放在这里。

同一节点的两阶段遍历

core enter结构转换；transformElement 登记 exit
→
DOM enter删除节点 / 改写 style / 登记校验 exit
→
children深度优先完成后代转换
→
reverse exit用户 → DOM → core codegen

这解释了一个表面矛盾：完整数组里 transformElement 排在 transformStyle 前面，但 style 仍来得及改写 props。 transformElement 真正构造 VNode props 的工作放在 exit；等它执行时， DOM enter 已改完节点。Transition 也把检查放进 exit，所以看到的是 v-if/v-for 已形成的结构，而不是原始标签文本。

transformStyle

把静态 style="color:red" 原位改成常量级 v-bind:style 对象。初次挂载仍交给 DOM style 设置；因值静态，更新期不会带 STYLE patch flag。动态 :style 不改写。

parseStringStyleCAN_STRINGIFY

Transition 校验

exit 阶段过滤注释与可折叠空白，再要求恰好一个目标；单个 v-for 仍可能产生多节点，v-if 则递归检查每个 branch。首个元素带 v-show 时，还会给 Transition 注入 persisted。

DEV onlychildren analysis

validateHtmlNesting

仅检查原生元素的直接 parent/child 组合；命中规则矩阵时走 onWarn，不改 AST。目标是提前指出浏览器可能隐式闭合或重排、进而造成 hydration 树不一致的写法。

DEV onlyhydration safety

ignoreSideEffectTags

客户端模板里的原生 script/style 会从 AST 删除；DEV 先报 X_IGNORED_SIDE_EFFECT_TAG，生产静默删除。它是组件模板边界，不是 HTML 消毒器，也不会替代对 v-html 内容的可信性检查。

template boundaryAST removal

这是“严格白名单优先、已知黑名单兜底”的规则判断，不是完整 HTML parser。对应测试分别覆盖 p > div、表格层级、同类标签嵌套， 以及 SVG foreignObject 中重新进入 HTML 的组合。

删节点后的控制流：context.removeNode() 会令 currentNode 变空，core 立即停止该节点的后代遍历和 exit；父级 traverseChildren 同时回退索引，保证 script/style 后面的兄弟节点不会被跳过。
04 / Directives

指令转换：编译期部分与运行时部分

DirectiveTransform 返回 props，也可要求保留 runtime directive。能完全静态展开的逻辑不会进入运行时。

指令 编译结果 关键边界
v-html 生成 innerHTML prop 必须有表达式；显式 children 被清空。
v-text 生成 textContent，动态值用 toDisplayString 必须有表达式；原 children 被删除。
v-show 保留 runtime vShow 指令 不删除 DOM，只通过 style 切换。
v-cloak noop transform 被消费，不保留为自定义运行时指令。
v-model 选择表单 helper 或组件 model props 依赖元素、type、value 与修饰符。
v-on 包装事件名与 handler 区分键修饰符、非键修饰符和 click 重写。
“消费”与“保留”：编译器认识一个指令，不代表一定生成运行时 directive。v-cloak 在编译时被消掉；v-show 必须留给 runtime；v-model 则根据元素在编译期选择专用 helper。

props 与 needRuntime 是两个独立字段

DirectiveTransformdir + element + context
↗
↘
props

交给 core 生成 VNode props。v-html/v-text 只返回这个字段； v-model 还会保留 onUpdate 写回函数。

needRuntime

登记 helper symbol，codegen 生成 withDirectives。它可与 props 同时存在；v-show 只有该字段，v-model 两者都有。

v-cloak 是第三种实际结果：noop transform 返回空 props，也不提供 needRuntime，因此只在编译期被消费。

先诊断，再给可检查产物

缺表达式时两者调用 onError，随后用空字符串占位；与 children 冲突时也先诊断，再把 children 数组清空。默认 onError 会抛出并中止流程；改用收集回调后，后续占位代码才会继续生成。

v-text 为何多一层 toDisplayString

textContent 接收展示文本。不能证明为编译期常量的表达式要经 toDisplayString 统一处理 null、对象等值；常量表达式则直接保留。 v-html 刻意不转义，内容可信性由调用方负责。

transform 返回的是 helper symbol，不是字符串 import。注册表把 symbol 映射成公开运行时名字；transform context 把用到的 symbol 记进 RootNode.helpers，generate 再按实际使用量生成 import 或浏览器版解构。没被选中的 helper 不出现在产物中。

05 / v-model

一个语法，多套原生控件协议

core 先生成 modelValue 与 update handler；DOM 再根据原生元素和 type 选择正确的运行时 helper。

baseTransform 返回值怎样被 DOM 层改写

core baseTransformmodelValue + onUpdate:modelValue
→
DOM 分派tag / type / dynamic v-bind
→
过滤 modelValue原生元素不重复设值
→
needRuntimehelper + value + modifiers

先让 core 生成写回函数

baseTransform 检查表达式可写性，并生成 onUpdate:modelValue: $event => x = $event。DOM 层只关心怎样从具体控件读到这个值。

组件 v-model 不进入 DOM 分派

<MyInput v-model="x"> 只需 modelValue prop 和 update event。只有原生元素才需处理 checked、selected、compositionend 等 DOM 细节。被 isCustomElement 命中的 Web Component 仍是 DOM 元素，会进入平台 helper 分派，不走组件路径。

动态 type 不能过早决定

<input :type="kind" v-model="x"> 可在 text/checkbox/radio 之间变化，编译期只能选 V_MODEL_DYNAMIC，让运行时根据真实 type 分派。无参数 v-bind="obj" 和动态参数 v-bind:[key] 也可能带来 type，同样走动态 helper。

file input 不是“尚未支持”

浏览器禁止程序为 file input 写入文件路径，所以它无法实现 v-model 的双向绑定。编译器直接报错， 避免用户得到一个看似有效却永远无法回填的模板。

同一语法的三种产物 
<input v-model="name">          → withDirectives(vnode, [[_vModelText, name]])
<input type="checkbox" v-model="tags"> → [[_vModelCheckbox, tags]]
<input :type="kind" v-model="value">    → [[_vModelDynamic, value]]

三者都保留 onUpdate:modelValue。运行时 directive 从 vnode.props 取出
assigner，监听真实 DOM 事件后调用它，最终执行“$event → 表达式写回”。

编译期可确定

静态 type、元素 tag、动态键是否存在，以及动态 :value 是否会与模型争夺写入；最后一项只在 DEV 构建执行检查。

必须留给运行时

动态 type、实际 DOM value、checkbox 集合与输入法组合状态； lazy/trim/number 修饰符随 runtime directive 参数一起生成。

错误回调后的边界

file input、非法元素、原生元素参数与 core 的不可写表达式会诊断； DEV 构建还会检查动态 value 冲突。若 onError 只收集不抛出，转换仍可能返回降级产物；不能把“有 code”误当成模板有效。

06 / v-on

事件修饰符如何分层

修饰符不是统一拼接；编译器先按语义分类，再决定事件名重写与 helper 包装顺序。

先分类，再改事件名，最后包装 handler

core transformOn事件 key + handler + 缓存语义
→
resolveModifiersoption / non-key / key
→
right / middleclick → contextmenu / mouseup
→
生成结果withModifiers → withKeys；option 后缀

事件选项

passive、once、capture 进入事件 key 后缀，由 patchEvent 注册选项。

非键修饰符

stop、prevent、self、系统键、鼠标键由 withModifiers 包装。

键名修饰符

enter、esc 等由 withKeys 包装，只在键盘事件场景生效。

DOM 层接着 core 的结果做

baseTransform 先把 @keyup 规范成事件 prop，检查 handler 表达式，并处理 cacheHandlers。DOM augmentor 只在这份结果上解释修饰符；没有修饰符时原样返回。

包装顺序是可见语义

先 withModifiers(handler, ['stop'])，再用 withKeys(..., ['enter']) 包外层。事件非 Enter 时根本不进入 stop/prevent，避免阻止不相关按键事件。

once/capture/passive 不是 handler guard

它们改变 addEventListener 的注册选项，因此被编码到 onClickOnceCapture 键名，runtime-dom 的 patchEvent 再解出后缀。

right 有两种意思

keyup.right 表示 ArrowRight，click.right 表示鼠标右键。resolveModifiers 必须先看事件类型；动态事件名无法提前确定，会保守地同时留下两类守卫。

click.right 必须改事件名

浏览器右键不会产生语义上的 click，而是 contextmenu；中键对应 mouseup。只在 handler 里检查 button 会因根本收不到事件而失效，所以必须在编译期重写 key。

一条指令的展开结果 
@keyup.enter.stop.once="submit"

key     → onKeyupOnce
handler → _withKeys(
            _withModifiers(_ctx.submit, ["stop"]),
            ["enter"]
          )
click.right / click.middle：这类修饰符不仅过滤 handler，还可能把事件名改为 contextmenu / mouseup。动态事件名无法静态确定时，需要生成条件表达式安全重写。

compiler-dom 的 v-on 转换本身没有新增 DOMErrorCodes。空表达式、非法 JS 等诊断沿用 core；DOM 层的失败模式主要是“分类错就选错事件或守卫”，所以测试直接断言 helper 嵌套、事件 key 和 patch flag，而不只看有没有生成函数。

07 / Static Stringification

何时把 VNode 树变成 HTML 字符串

core 的 cacheStatic 先把稳定 VNode/children 写成 CacheExpression；DOM 平台再把连续、足够有收益的缓存片段合并成 createStaticVNode(html, count)。

stringifyStatic(children, context, parent)

扫描连续缓存节点统计节点与属性收益
→
安全性检查namespace / attrs / interpolation
→
serializeHTML 转义与属性格式
→
StaticVNodehtml + top-level count
这里省略了两类已单独测试的保护分支：布尔属性为 false 时不输出；<option :value="1"> 因 number property 与字符串 attribute 语义不同而在 analyzeNode() 阶段退出。测试还分别断言 v-html 保留原始 HTML、v-text 转义、以及 SVG/MathML 属性序列化。

“能字符串化”还不够

很小的静态树用 createStaticVNode 反而增加 helper、HTML 字符串和管理成本。因此还要达到 20 节点或 5 个带属性元素的收益阈值。

必须是连续 chunk

中间若夹着动态或不可字符串化节点，不能把两侧 HTML 合成一次 innerHTML，否则动态 VNode 在 children 中的锚点与 patch 顺序会丢失。

第二个参数是顶层节点数

createStaticVNode(html, count) 可表示多个兄弟节点。runtime 在插入、移动或 hydration 时需要 count，才知道这一个 VNode 覆盖真实 DOM 中的哪段范围。

slot 内容保守退出

slot 在消费方的渲染上下文中执行，还可能携带 scopeId。声明方把它提前压成 DOM 字符串，会跳过必要的作用域附加过程。

手走测试中的最小达标 chunk 
Given：父 div 下连续 5 个 <span class="foo"/>

每个 span：analyzeNode → [nc=1, ec=1]
累加完成：nc=5, ec=5, currentChunk.length=5
阈值判断：nc < 20，但 ec >= 5 → 进入 stringifyCurrentChunk

结果：
_createStaticVNode(
  "<span class=\"foo\"></span>...共 5 个 span...",
  5 // 顶层 DOM 节点数，不是递归节点总数
)

父 div 的 children 已由 core 整体放入一个缓存数组；DOM 转换直接把数组里的
5 个候选替换成一个 staticCall。本例没有 5 个独立 cache 项，也不需要调整
后续 CacheExpression.index。
源码自己留下了未完项：analyzeNode() 的 TODO 明确写着还要继续覆盖“innerHTML 与逐节点创建结果不同”的结构，例子就是 <p> 内放非 phrasing content。stringifyStatic() 真正会检查的是已知表格标签黑名单、属性与常量类型、 v-once、slot 等退出条件。 validateHtmlNesting 只是独立的开发期警告：它只调用 onWarn()，不会阻止节点被字符串化，生产构建也不会注册这项 transform。因此，这个 TODO 仍是当前实现没有完全覆盖的边界。

父级未整体缓存时，合并项中只有第一个 CacheExpression 的 value 被替换为 createStaticVNode；其余位置从 children 与 context.cached 中移除。父级 children 已整体缓存时，则直接在该缓存数组内替换连续区间。topLevelCount 告诉 runtime 这段 HTML 会创建多少个顶层节点，以便正确插入和移动。

08 / End-to-end

把这条 input 编译到 render 函数

用同一条 input 模板同时穿过 parserOptions、style、v-model、v-on、 core props 分析和 generate；每一步只看数据发生了什么变化。

贯穿本节的输入 
const result = compile(
  `<input style="color:red"
          :type="kind"
          v-model.trim="name"
          @keyup.enter.stop.once="submit">`,
  { mode: 'module', prefixIdentifiers: true },
)

证据边界：仓库没有一条测试使用上面完全相同的 input。 transformStyle.spec.ts、vModel.spec.ts 与 vOn.spec.ts 分别证明三个转换分支；这里的完整 code 是固定版本 编译结果，不能据此宣称“同一 Demo 已有集成回归测试”。

40 不是魔法数字

动态 type/onUpdate/onKeyup 需要 PROPS（8）；原生事件在挂载和 hydration 阶段要处理，另带 NEED_HYDRATION（32）。按位或得到 40。

编译器生成的是 helper 与 props

code 里没有输入法、checkbox 或 addEventListener 的实现。编译器只选择 helper、排列参数并压缩动态键；runtime-dom 再根据这些字段操作真实元素。

这个例子不会触发 stringifyStatic

单个根 input 不满足静态提升与收益阈值，且含动态 type、model、event。静态字符串化只处理已由 core 判定可缓存的连续候选，不能跳过前置分析。

错误和警告从哪里返回

回调是否抛出决定控制流。默认 onError 立即抛错。改成收集模式时， v-html/v-text 会用空值继续，side-effect tag 已被删除，部分 v-model 错误也会留下可生成 AST。这样的 code 只便于诊断或编辑器继续分析，不代表语义有效。

诊断 构建条件 诊断后 AST 怎么办
v-html/v-text/v-show 缺表达式；前两者与 children 冲突 转换存在于所有构建 空表达式用空串；v-html/v-text 清空 children；v-show 仍登记 runtime
v-model 非法元素、原生参数、file input 所有构建 继续过滤原生 modelValue；file 不登记 runtime helper
v-model 与动态 :value 冲突 仅 __DEV__ 仍选择对应 v-model helper
Transition 多目标 整个 transform 仅 __DEV__ 先过滤注释和可折叠空白；多目标元素本身保留，再报告 error
script/style 副作用标签 删除总执行；error 仅 __DEV__ 节点已从 AST 删除，生产构建静默
非法 HTML nesting 整个 transform 仅 __DEV__ 走 onWarn，AST 不变

本 Demo 的 PROPS 让 renderer 只检查列出的三个动态键， NEED_HYDRATION 则确保原生事件在挂载或 hydration 时处理。 具体 DOM 写入属于 runtime-dom 的 patchProp.ts，不在本页展开。

#13169 测的是转换顺序

:type 简写先由 transformVBindShorthand 归一化为动态绑定。若 v-model 分派只识别完整 :type="x" 形态，就会误选 V_MODEL_TEXT，运行时切换 checkbox 后失效。

#3596 测的是动态写入冲突

:value="test" 每次 render 都可覆盖 v-model 管理的 DOM value，所以应警告；普通 value="test" 只是初始默认值，不会在后续更新中争夺写入权。

10 / Boundaries

已覆盖与未覆盖

本页覆盖 compiler-dom 的客户端主路径和主要分支；同一 input Demo 尚无单条集成测试，相邻包和未测试组合也不算已证明。

源码与测试能直接支持

  • DOM 入口如何分两层合并 core、平台与用户转换。
  • HTML/SVG/MathML、文本模式、实体、pre 与自定义元素的解析边界。
  • style、Transition、nesting、副作用标签及全部 DOM 指令预设。
  • v-model/v-on 的分派、helper 生成结果、主要错误路径与静态字符串化条件。
  • 固定输入由目标版本生成的 render code；它不是测试快照。

不要从本页外推

  • 用户覆盖 directive transform、追加 node transform 的任意组合没有专门的 compiler-dom 回归矩阵；合并顺序来自入口与 core 源码。
  • DEV/生产差异来自条件编译分支；现有单测主要在 DEV 语义下断言诊断。
  • stringifyStatic 对浏览器所有树修正规则并非穷尽，源码仍有明确 TODO。
  • vModelText、vShow、withKeys、patchEvent 的 DOM 操作属于 runtime-dom，本页只追到编译产物与消费接口。
  • SFC block 解析、资产 URL/scoped CSS 注入与 SSR 是其他编译器层。
两层职责：compiler-core 决定“怎样把模板编成 VNode 程序”，compiler-dom 决定“浏览器平台里这段模板是什么、应生成哪些 helper 与 props”；两者通过 ParserOptions、NodeTransform、DirectiveTransform 和 helper symbol 接起来。
