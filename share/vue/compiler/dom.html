compiler-dom

它不是另一套模板编译器，而是 compiler-core 的客户端平台配置：告诉 parser 什么是 HTML/SVG/MathML，并把 DOM 属性、事件、表单和静态 HTML 语义注入 transform。

入口：compile()目标：client render核心增量：parserOptions + DOM transforms
本页不需要对照仓库

下文直接嵌入 DOM 入口、命名空间、v-model、v-on 和静态字符串化的真实源码。阅读重点是“平台层给 core 增加了哪些事实”，而不是记住函数名。

01 / Assembly

compile() 只做平台装配

compiler-dom 调用 baseCompile，但会按明确优先级合并 parser options、节点转换、指令转换和静态提升回调。

compiler-dom compile()

parserOptionsnamespace / tag / entity
+
DOM transformsstyle / Transition / nesting
+
DOM directiveshtml / text / model / on / show
→
baseCompile共享三段管线

这个入口没有重写编译器

真正的 parse/transform/generate 仍由 baseCompile 完成。DOM 只提供 parserOptions 与插件，这使 compiler-ssr 可以复用同一份 AST 和通用指令语义。

开发校验不进生产包

Transition 子节点与 HTML nesting 的转换只在 __DEV__ 中装入。它们只产生警告，不应让生产渲染函数增加体积。

用户还能继续扩展

数组最后追加 options.nodeTransforms，指令表最后合并用户键。 因此平台默认值完整保留，同名指令又可被高层定制覆盖。

浏览器版不做静态 HTML 序列化

stringifyStatic 依赖编译期求值与更重的序列化逻辑，只装入 Node 构建。运行时编译优先保持包体积与启动速度。

ignoreSideEffectTags 单独前置

客户端模板里的 script/style 会被诊断并删除。它不放进共享 DOMNodeTransforms，因为 SSR 在组件 VNode fallback 中会复用后者。

DOM 指令覆盖 core

core 的 v-model/v-on 只建立通用 props；DOM 同名转换继续补充元素类型、修饰符和运行时 helper。

transformHoist

Node 构建可传入 stringifyStatic，把满足收益阈值的连续静态树压成 StaticVNode。

02 / Parser Options

HTML 不是“普通 XML”

parserOptions 把浏览器解析规则集中在平台层，core 只在需要时询问。

标签分类

  • isVoidTag：img、input 等无需结束标签。
  • isPreTag：pre 保留空白。
  • isNativeTag：HTML/SVG/MathML 元素。
  • isBuiltInComponent：Transition、TransitionGroup。
  • isCustomElement：由用户选项扩展。

文本模式

  • script/style 使用 RAWTEXT。
  • textarea/title 使用 RCDATA，仍解码实体。
  • SFC 根级非 template block 由 SFC mode 处理。
  • 浏览器构建通过 decodeHtmlBrowser 解码实体。

Namespace 切换是上下文计算

getNamespace(tag, parent, rootNamespace)

HTML遇到 svg / math
→
SVG / MathML继承父 namespace
→
Integration PointforeignObject / annotation-xml
→
返回 HTML后代按 HTML 规则解析

命名空间由父子关系决定

只查 tag 会得出错误结论：title 在 HTML 和 SVG 中都合法，它的解析规则取决于 parent.ns。所以 parser 每建一个元素都把父节点交给平台函数。

foreignObject 是 SVG 中的 HTML 岛

<svg><foreignObject><div> 中 div 必须回到 HTML 规则，否则浏览器创建的节点类型、class 设置和 hydration 对比都会出错。

MathML 有更细的集成点

annotation-xml 根据 encoding 切回 HTML，mtext/mi/mo/mn/ms 也允许 HTML 内容，但 mglyph/malignmark 是例外。这些是 HTML parser 标准事实，不应污染 compiler-core。

decodeEntities 根据构建分流

浏览器构建可利用原生 HTML 解码能力；Node 构建由 core tokenizer 所用的 entities 实现处理。条件常量让另一套实现可被 tree-shake。

不能仅凭当前 tag 判断 namespace：SVG 的 foreignObject 允许 HTML 内容，MathML 的文本集成点也会改变后代规则。parser 因而把 parent 传给平台函数，避免在 core 内硬编码这些标准细节。

为什么测试 namespace 很重要：命名空间错误不一定立刻报错，但会改变浏览器创建节点的 API、属性大小写和 hydration 后 DOM 形态。

04 / Directives

指令转换：编译期部分与运行时部分

DirectiveTransform 返回 props，也可要求保留 runtime directive。能完全静态展开的逻辑不会进入运行时。

指令 编译结果 关键边界
v-html 生成 innerHTML prop 必须有表达式；显式 children 被清空。
v-text 生成 textContent，动态值用 toDisplayString 必须有表达式；原 children 被删除。
v-show 保留 runtime vShow 指令 不删除 DOM，只通过 style 切换。
v-cloak noop transform 被消费，不保留为自定义运行时指令。
v-model 选择表单 helper 或组件 model props 依赖元素、type、value 与修饰符。
v-on 包装事件名与 handler 区分键修饰符、非键修饰符和 click 重写。
“消费”与“保留”：编译器认识一个指令，不代表一定生成运行时 directive。v-cloak 在编译时被消掉；v-show 必须留给 runtime；v-model 则根据元素在编译期选择专用 helper。
05 / v-model

一个语法，多套原生控件协议

core 先生成 modelValue 与 update handler；DOM 再根据原生元素和 type 选择正确的运行时 helper。

input/select/textarea 的分派

v-modelnode.tag + type + arg
↗
→
↘
vModelText

text/textarea；支持 lazy、trim、number。

Radio / Checkbox

checked 语义、数组/Set、多值与 looseEqual。

Select / Dynamic

option selected 或运行时依据动态 type 决定。

先让 core 生成写回协议

baseTransform 检查表达式可写性，并生成 onUpdate:modelValue: $event => x = $event。DOM 层只关心怎样从具体控件读到这个值。

组件 v-model 不进入 DOM 分派

<MyInput v-model="x"> 只需 modelValue prop 和 update event，这是组件协议。只有原生元素才需处理 checked、selected、compositionend 等 DOM 细节。

动态 type 不能过早决定

<input :type="kind" v-model="x"> 可在 text/checkbox/radio 之间变化，编译期只能选 V_MODEL_DYNAMIC，让运行时根据真实 type 分派。

file input 不是“尚未支持”

浏览器禁止程序为 file input 写入文件路径，所以它无法实现双向值协议。 编译器直接报错，避免用户得到一个看似有效却永远无法回填的模板。

同一语法的三种产物 
<input v-model="name">          → withDirectives(vnode, [[_vModelText, name]])
<input type="checkbox" v-model="tags"> → [[_vModelCheckbox, tags]]
<input :type="kind" v-model="value">    → [[_vModelDynamic, value]]

三者都保留 onUpdate:modelValue，运行时 directive 负责“DOM → $event”。

编译期可确定

静态 type、元素 tag、修饰符和冲突的 value 属性。

必须留给运行时

动态 type、实际 DOM value、checkbox 集合与输入法组合状态。

必须诊断

file input、非法元素、原生元素参数、不可写表达式与 value 冲突。

06 / v-on

事件修饰符如何分层

修饰符不是统一拼接；编译器先按语义分类，再决定事件名重写与 helper 包装顺序。

事件选项

passive、once、capture 进入事件 key 后缀，由 patchEvent 注册选项。

非键修饰符

stop、prevent、self、系统键、鼠标键由 withModifiers 包装。

键名修饰符

enter、esc 等由 withKeys 包装，只在键盘事件场景生效。

包装顺序是可见语义

先 withModifiers(handler, ['stop'])，再用 withKeys(..., ['enter']) 包外层。事件非 Enter 时根本不进入 stop/prevent，避免阻止不相关按键事件。

once/capture/passive 不是 handler guard

它们改变 addEventListener 的注册选项，因此被编码到 onClickOnceCapture 键名，runtime-dom 的 patchEvent 再解出后缀。

right 有两种意思

keyup.right 表示 ArrowRight，click.right 表示鼠标右键。resolveModifiers 必须先看事件类型；动态事件名无法提前确定，会保守地同时留下两类守卫。

click.right 必须改事件名

浏览器右键不会产生语义上的 click，而是 contextmenu；中键对应 mouseup。只在 handler 里检查 button 会因根本收不到事件而失效，所以必须在编译期重写 key。

一条指令的展开结果 
@keyup.enter.stop.once="submit"

key     → onKeyupOnce
handler → _withKeys(
            _withModifiers(_ctx.submit, ["stop"]),
            ["enter"]
          )
click.right / click.middle：这类修饰符不仅过滤 handler，还可能把事件名改为 contextmenu / mouseup。动态事件名无法静态确定时，需要生成条件表达式安全重写。

07 / Static Stringification

何时把 VNode 树变成 HTML 字符串

core 的 cacheStatic 先把稳定 VNode/children 写成 CacheExpression；DOM 平台再把连续、足够有收益的缓存片段合并成 createStaticVNode(html, count)。

stringifyStatic(children, context, parent)

扫描连续缓存节点统计节点与属性收益
→
安全性检查namespace / attrs / interpolation
→
serializeHTML 转义与属性格式
→
StaticVNodehtml + top-level count

“能字符串化”还不够

很小的静态树用 createStaticVNode 反而增加 helper、HTML 字符串和管理成本。因此还要达到 20 节点或 5 个带属性元素的收益阈值。

必须是连续 chunk

中间若夹着动态或不可字符串化节点，不能把两侧 HTML 合成一次 innerHTML，否则动态 VNode 在 children 中的锚点与 patch 顺序会丢失。

第二个参数是顶层节点数

createStaticVNode(html, count) 可表示多个兄弟节点。runtime 在插入、移动或 hydration 时需要 count，才知道这一个 VNode 覆盖真实 DOM 中的哪段范围。

slot 内容保守退出

slot 在消费方的渲染上下文中执行，还可能携带 scopeId。 声明方把它提前压成 DOM 字符串，会跳过必要的作用域附加过程。

优化前后 
优化前：5+ 个带属性的稳定 VNode 调用 + children 数组
优化后：return _createElementBlock("div", null, [
  ...(_cache[0] || (_cache[0] = [
    _createStaticVNode(
      "<span class=\"foo\"></span>...共 5 个 span...",
      5
    )
  ]))
])

createStaticVNode 仍位于组件实例 _cache 中；首次挂载由 innerHTML
批量创建，后续 render 复用缓存，更新阶段整段跳过。

适合字符串化

  • 原生稳定元素。
  • 静态属性、class、style。
  • 可字符串化常量插值。
  • 连续多个可缓存静态节点。

必须放弃

  • 组件、slot、运行时指令。
  • 可能改变 DOM 解析形态的内容。
  • 动态指令参数/运行时属性名与不可安全转义值。
  • 收益不足的微小片段。

父级未整体缓存时，合并项中只有第一个 CacheExpression 的 value 被替换为 createStaticVNode；其余位置从 children 与 context.cached 中移除。父级 children 已整体缓存时，则直接在该缓存数组内替换连续区间。topLevelCount 告诉 runtime 这段 HTML 会创建多少个顶层节点，以便正确插入和移动。

08 / Runtime Contract

客户端产物如何指导 patch

compiler-dom 的最终价值不只是生成 VNode，而是把动态性压缩成 runtime-core 可直接消费的快路径。

编译信息 示例 runtime 行为
PatchFlags.TEXT 只有插值文本变化 直接比较并更新 textContent。
CLASS / STYLE 动态 class/style 只调用对应模块 patch。
PROPS + dynamicProps 已知动态 id/title 仅遍历明确键。
FULL_PROPS 无参数 v-bind 或动态指令参数 执行完整 props diff。
Block dynamicChildren 稳定树里的少量动态节点 跳过中间静态层级。
NEED_HYDRATION 事件等仅在挂载/hydration 生效 进入相应挂载路径。
理解 compiler-dom 的最佳方式：同时打开 runtime-dom 的 patchProp.ts 与 runtime-core renderer。每个 patch flag、helper、props 形态都应在运行时找到对应消费者。
09 / Tests

平台测试保护浏览器真实行为

DOM 测试常常围绕浏览器解析会怎样改变节点，而非只比较字符串。

测试文件 核心场景
parse.spec.ts 实体、void/pre、原生/组件判定与 namespace 进出。
validateHtmlNesting.spec.ts 浏览器隐式闭合/重排导致的 hydration 风险。
stringifyStatic.spec.ts 收益阈值、HTML 转义、属性/样式、namespace 与放弃边界。
vModel.spec.ts text/radio/checkbox/select/dynamic helper 与非法组合。
vOn.spec.ts 键/非键修饰符、事件选项、right/middle 重写。
Transition.spec.ts 转换后 child 结构，而非仅源码标签数量。

#13169 测的是转换顺序

:type 简写先由 transformVBindShorthand 归一化为动态绑定。若 v-model 分派只识别完整 :type="x" 形态，就会误选 V_MODEL_TEXT，运行时切换 checkbox 后失效。

#3596 测的是动态写入冲突

:value="test" 每次 render 都可覆盖 v-model 管理的 DOM value，所以应警告；普通 value="test" 只是初始默认值，不会在后续更新中争夺写入权。

Issue 阅读提示：若 bug 只在浏览器或 hydration 出现，先检查 namespace、HTML nesting、属性序列化与 runtime helper 选择；若 AST 已经错误，再回到 compiler-core。
