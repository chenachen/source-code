compiler-core

模板编译的共享内核。它定义语言结构、AST 协议、转换插件模型和 JavaScript 生成器，并把大部分 DOM 与 SSR 平台规则留给上层；compiler-core 内仍保留少量 block/namespace 交界逻辑和 SSR codegen 节点协议。

00 / Vocabulary

先把几个容易混的词说清

后面会反复出现 AST、helper、block 和 cache。先约定它们在本页具体指什么，免得同一个词在不同阶段来回变义。

词 在 compiler-core 里的意思 谁创建，谁消费
模板 AST RootNode / ElementNode / DirectiveNode 等节点，记录模板结构、表达式和源码位置。它还不是运行时 VNode。 Parser 创建；transform 读取并原地修改。
codegen AST VNodeCall / JSCallExpression / CacheExpression 等“该怎样输出 JavaScript”的结构化描述。 transform 创建；generate 打印。
codegenNode 挂在模板节点上的桥。它把“用户写了什么”连到“最终该打印什么”。 通常在转换插件的退出阶段写入；genNode() 递归跟进。
TransformContext 一次 transform 的可变工作台：遍历游标、局部作用域、helper 引用计数、hoist/cache 槽位都放在这里。 transform() 创建；阶段结束后把 helper、组件、指令、 hoist 和 cache 等结果写回 RootNode。
helper 生成代码要调用的 Vue runtime 函数，以 Symbol 登记，例如 OPEN_BLOCK、TO_DISPLAY_STRING。 transform 按引用次数登记；generate 只导入最终仍被引用的 helper。
block / patchFlag block 决定动态后代的收集边界；patchFlag 和 dynamicProps 告诉 renderer 下次更新该看哪些部分。 transform 决定；renderer 消费，codegen 只负责把协议打印出来。
hoist / cache hoist 生成 _hoisted_n 声明；cache 生成当前组件实例的 _cache[n] 槽。两者生命周期不同，不能混称“静态提升”。 transform 分配；generate 输出；运行时使用 cache 槽。
职责边界：compiler-core 提供通用模板语法、AST、插件遍历和 JS 打印器；它通过 options 留出平台接口。哪些 HTML 标签是 void、SVG/MathML 命名空间怎样切换、 v-show 怎样落到 DOM、SFC 的 script/style 怎样拆开，都不是这一层独自决定的。
01 / Entry

baseCompile：三段管线的总装线

它不亲自实现每个转换，只负责校验模式、合并 options、排列插件并把阶段串起来。

baseCompile(source, options)

校验构建模式browser / module / scopeId
→
baseParse字符串建树；传入 RootNode 时跳过
→
transform基础转换 + 用户转换
→
generatecode / preamble / map

为聚焦主线，上方只省略了 browser/module、cacheHandlers 与 scopeId 的组合校验，以及 isTS 对 expression plugin 的补充；三阶段调用保持原样。代码中的三条编号注释是教程批注，不是源码原注释。

入口允许两种输入

单独编译模板时传字符串；SFC 若已得到 template AST，可传 RootNode 避免第二次 parse。这是 compiler-core 与 compiler-sfc 的性能接口。

运行时语义主要在 transform 定稿

Parser 会做语法归一化、元素分类和表达式预解析，但不决定 VNode 调用。transform 再把指令结果、作用域、patchFlag 和 codegenNode 定稿，因此 generate 不必重新解释 v-if 或 v-for。

数组追加，对象覆盖

nodeTransforms 依赖顺序，所以用数组追加；directiveTransforms 按名称查找，上层可用同名键替换默认语义。

返回值不只有 code

CodegenResult 还携带 AST、preamble 与 source map。测试可直接断言 AST 上的 patchFlag/hoist，构建工具则消费代码与映射。

本页主 Demo：直接取自 compile.spec.ts 
<div id="foo" :class="bar.baz">
  {{ world.burn() }}
  <div v-if="ok">yes</div>
  <template v-else>no</template>
  <div v-for="(value, index) in list">
    <span>{{ value + index }}</span>
  </div>
</div>

后文的主流程图、状态表和完整管线测试都追踪这份输入。
Parser 错误恢复等机制另用更小的反例，避免把异常分支硬塞进主线。

同一份数据到底怎么走

主 Demo：源码字符串到 render 函数

模板 sourceclass + interpolation + if + for
→

→
模板 ASTElement + If/For 前的指令节点
→
原地 TransformIfNode / ForNode + _ctx 前缀 + VNodeCall
→

时刻 主要数据 发生了什么 下一站能依赖什么
baseParse() 前 source、parser options 重置复用的 tokenizer 与 parser 临时状态。 每个回调的 offset 都指向本轮 source。
baseParse() 后 RootNode、Element、Directive、Interpolation v-if/v-else/v-for 仍是指令；bar.baz 等表达式保留源码位置；尚无 VNodeCall。 转换器可按模板结构和精确位置工作。
transform() 中 同一个 RootNode + TransformContext if/else 合为 IfNode；for 变成 ForNode；list 改为 _ctx.list，value/index 保持循环局部名。 父节点退出时可读取已经完成的分支、循环体和 VNodeCall。
transform() 后 codegenNode + RootNode 资源集合 根 VNodeCall 带 CLASS；IfNode 的两个分支 VNode 带不同 key；ForNode 带 UNKEYED_FRAGMENT，并登记所需 helper。 generate 只读这份已定稿 AST。
generate() 中 CodegenContext 的 code/line/column/offset 输出 helper 序言，再打印 _ctx.bar/_ctx.world/_ctx.ok/_ctx.list 与保持局部的 value/index。 得到 render 代码、source map 和同一 RootNode。
错误支线：默认 onError 会立刻抛异常，主链到此停止；IDE 等调用方可传入只收集错误的处理器，让 Parser 在可恢复位置继续建 AST。 “能够恢复”不等于“默认静默吞错”。

baseCompile() 也接受 RootNode。compiler-sfc 在模板未预处理、编译器选项兼容且 AST 尚未转换时可复用解析结果；module 模式会启用标识符前缀，而同名 directive transform 允许平台层覆盖基础实现。

02 / Parse

Tokenizer 与 Parser 如何协作

Tokenizer 负责识别边界并发事件，Parser 维护上下文并组装节点；中间没有一份完整 token 数组。

Tokenizer：单遍有限状态机

逐字符扫描，状态描述当前位于文本、标签名、属性名、指令参数、注释、CDATA 或插值。发现边界时直接调用 parser callbacks。

StateCharCodesParseModeEntityDecoder

Parser：事件驱动组装器

维护当前打开标签、属性、标签栈和全局 options。开始/结束事件创建 Element、Attribute、Directive、Text、Interpolation，并精确计算 location。

stackcurrentOpenTagcurrentPropcurrentOptions

以 div + v-bind + interpolation 为例

Text遇到 <
→
InTagNameonopentagname(div)
→
Directivebind + arg:id + value:x
→
Interpolation创建表达式节点
→
Close Tag弹栈并封闭 loc

输入 x<div> 时，< 先触发 ontext(0, 1)，状态转到 BeforeTagName；扫描到 > 才用起止 offset 触发 onopentagname。回调收到的是原字符串切片边界，不是另建的 token 对象。

当前状态 看到什么 动作 为什么这样处理
Text < 先提交前方文本，再转 BeforeTagName。 文本节点不会把标签起始符吞进去。
BeforeTagName 合法首字母 / / / 其他 分别进入开标签、闭标签；否则退回 Text，并重处理当前字符。 a < b 这类中间态仍能保留成连续文本。
InTagName 空白、/ 或 > 触发 onopentagname，终止字符交给属性状态重处理。 同一个终止字符既结束标签名，也决定后面是属性还是标签结束。
InterpolationOpen 开始分隔符只匹配一半 退回 Text/RCDATA，并重处理当前字符。 自定义多字符分隔符失败时不丢字。
InDirDynamicArg 先遇到 = 或标签边界 提交已有参数，同时报告缺少 ]。 诊断保留，后续属性和值仍可继续组装。
任一未完成标签状态 EOF 不发送半成品开/闭标签回调；Parser 报 EOF_IN_TAG。 编辑器中输入到一半的标签不会变成一个假的完整 ElementNode。

Tokenizer 只交付源码区间。Parser 才创建节点：开标签先写入 currentOpenTag，遇到 > 后把它追加到最近父节点并压栈； 插值直接追加到当前父节点。主 Demo 的最外层 div 因此先进入 root.children，后续节点再进入它的 children。 摘录省略了插值裁剪/实体解码和 SFC 根块 innerLoc 初始化。

先 reset，再解析

Parser 为了热路径性能复用了模块级 tokenizer、栈和当前属性。 reset() 会清 tokenizer、标签栈和属性缓冲；测试直接保证了 RCDATA 扫描状态不会串到下一轮。正常闭合元素时，Parser 还会退出相应的 pre/v-pre 区域。

ParserOptions 是平台接口

core 不硬编码“img 是空标签”或“svg 需命名空间”。compiler-dom 通过 options 注入这些知识，SFC 则选择 sfc 解析模式。

闭合元素时整理 children 空白

onCloseTag() 逐个整理已闭合元素的 children，按 <pre>、相邻节点和 whitespace 选项决定保留、折叠或删除空白。扫描结束后，baseParse() 再单独整理 root.children。

主 Demo 开头的实际交接 
<div id="foo" :class="bar.baz">{{ world.burn() }}…</div>

Tokenizer：open(div) → attr(id, foo) → directive(bind, class, bar.baz)
           → interpolation(world.burn()) → … → close(div)
Parser：   ElementNode.props[AttributeNode, DirectiveNode]
           ElementNode.children[InterpolationNode, …]
注意：这里的省略号只代表主 Demo 后续 children，不是模板源码。

闭标签不匹配时，Parser 怎样收拾现场

向栈里找，不只看栈顶

对 <div><span></div>，栈顶 span 对不上，但下一层 div 能对上。Parser 先把 span 隐式闭合并报缺失结束标签，再正常闭合 div。

找不到就是无效闭标签

后面再出现 </span> 时，开放栈里已经没有 span，因而报告 X_INVALID_END_TAG，不会凭空创建节点。

EOF 也会给开放元素补 loc

onend() 先按 tokenizer 状态报告具体 EOF 错误，再调用 onCloseTag() 收口仍开放的元素并补报缺失结束标签。

默认仍是失败即停

defaultOnError 直接 throw。上面多错误和恢复后的 AST，只有在测试、IDE 或调用方传入不抛异常的 onError 时才能拿到。

错误恢复的状态变化 
输入：<div>\n<span>\n</div>\n</span>
开放栈：[] → [div] → [span, div]
遇到 </div>：报告 span 缺结束标签 → 隐式闭合 span → 闭合 div → []
遇到 </span>：栈中找不到 → 报无效结束标签；已有 AST 保留
前提：onError 只收集错误而不抛出

三种 ParseMode

模式 用途 特殊行为
BASE 平台无关模板 所有标签内容按普通模板结构解析。
HTML compiler-dom Tokenizer 识别 RAWTEXT/RCDATA；HTML/SVG/MathML namespace 仍由 parser options 的 getNamespace 注入。
SFC compiler-sfc parse 根级非 template block 按原始文本读取，避免误解 script/style 内容。
默认错误处理可能留下 v-pre 状态：先解析 <div v-pre><span>，默认 onError 会在 EOF 清理开放元素前抛出；捕获异常后再解析 {{ msg }}，得到的是 Text，而非 Interpolation。原因是 inVPre/currentVPreBoundary 尚未退出，且不在 reset() 的清理清单中。诊断回调也不能重入 baseParse()：内层解析会覆盖外层正在使用的 tokenizer、输入、选项和节点状态。

实体解码

Node.js 构建由 tokenizer 内的 EntityDecoder 流式解码； browser 构建改用平台传入的 decodeEntities。compiler-core 只保持文本、属性两种解码上下文和源码范围。

空白整理

闭合元素时按 preserve/condense、pre 与相邻节点上下文整理其 children；扫描结束后再整理根级 children。

表达式预解析

Node.js 构建可用 Babel 解析表达式、参数或多语句并缓存失败状态；浏览器生产构建保持轻量。

03 / AST

同一条编译管线会先后使用两类 AST

模板 AST 表达用户写了什么；JS/codegen AST 表达应该生成怎样的 JavaScript。

Template AST

  • RootNode
    • ElementNode tag / props / children
    • IfNode branches[]
    • ForNode source / aliases
    • InterpolationNode
    • TextNode

JS / Codegen AST

  • VNodeCall
    • JSCallExpression
    • JSObjectExpression
    • JSFunctionExpression
    • JSConditionalExpression
    • CacheExpression
    • TemplateLiteral SSR

它不是运行时 VNode

VNodeCall 只是“将来要打印一次 VNode 调用”的编译期描述。此时没有 DOM、component instance 或响应式副作用。

从编译字段到运行时更新信息

patchFlag 与 dynamicProps 会传入运行时 VNode；isBlock 由 codegen 转成 openBlock 与 createBlock/createElementBlock 调用，使运行时建立动态后代列表。renderer 再使用这些信息选择更新路径，跳过稳定的 props 和 children。

helper 按需登记

createVNodeCall 不拼字符串，却会登记 openBlock/createElementBlock/withDirectives 等 helper。generate 最后只导入真正用到的函数。

为什么不直接保存代码字符串

transformElement 后面还可以增加 directive、提升 props，或把普通 VNode 升级为 block。结构化节点让这些后续优化不需重写字符串。

分类 关键节点 阅读重点
词法叶子 TEXT、COMMENT、SIMPLE_EXPRESSION、INTERPOLATION content、isStatic、constType、loc
模板容器 ROOT、ELEMENT、IF、IF_BRANCH、FOR children、结构替换、codegenNode
元素属性 ATTRIBUTE、DIRECTIVE arg、exp、modifiers、静态/动态参数
JS 表达式 CALL、OBJECT、FUNCTION、CONDITIONAL 由 transform 创建，供 generate 打印
SSR 节点 TEMPLATE_LITERAL、IF_STATEMENT、BLOCK_STATEMENT 线性字符串输出与控制流
连接两类 AST 的字段是 codegenNode：parser 不填它；transform 在退出阶段根据完整子树生成。于是模板结构和输出结构可以并存，codegen 无需反推模板语义。

Location

所有语义节点带 start/end/source，服务错误、source map、IDE 与精确测试。

Helper Symbol

AST 保存 symbol 而非硬编码导入名，平台可注册 helper 映射。

工厂函数

createVNodeCall 等工厂同时保证字段形状、helper 登记和 block 约束。

04 / Transform

进入、递归、退出

转换阶段原地修改 AST，并通过 TransformContext 共享作用域、资源与优化信息。

enter 适合建立环境

v-for/v-slot 在进入节点时把 item、index 或 slot props 登记为局部变量，子孙表达式遍历时就不会把它们误写为 _ctx.item。

exit 适合汇总子树

transformElement 返回 postTransformElement，等 children 的 codegenNode、插槽动态性和文本合并都完成后，才构造父 VNodeCall。

插件可以替换，也可以删除

v-if 会把 ElementNode 换成 IfNode；忽略副作用的 <script> 转换则可删节点。currentNode 让后续插件始终处理最新树。

为什么 exit 逆序

先注册的高层转换最后退出，因此退出时能读取后续转换补出的结果。这与递归 visitor 的 leave 阶段相同，也是插件顺序成为语义的原因。

TransformContext 只活在这一阶段。generate 拿到的是 RootNode 快照，不会继续碰遍历游标或作用域计数。SSR 跳过客户端的 createRootCodegen()，由 SSR 转换另建根输出。

Context 字段 转换时怎样变 离开 transform 后去哪
helpers: Map<symbol, number> 创建调用时加引用，VNode 普通调用/block 互换时可减引用。 只把仍有引用的 key 快照成 root.helpers: Set。
components / directives: Set 解析到资产时去重登记。 转成 RootNode 数组，供 generate 输出 resolve 声明。
hoists / cached 按数组长度分配稳定下标。 原数组挂到 RootNode，分别输出 _hoisted_n 与 _cache[n]。
identifiers / scopes 进入 v-for/v-slot 时增加，退出时成对减少。 不快照；它们只服务本次深度优先遍历。
currentNode / parent / childIndex 随遍历、替换和删除移动。 不快照；最终树已经反映修改结果。
相对顺序 转换 顺序原因
1 transformVBindShorthand 先把同名简写归一化。
2–5 v-once、v-if、v-memo、v-for 先处理缓存包装和会改树的结构指令，让后续插件看到正确节点形态。
可选 transformFilter 仅 Vue 2 compat 构建插入。
其后 trackVForSlotScopes → transformExpression Node 且开启前缀模式时出现；普通 v-for 作用域由 transformFor 自己登记，这个 tracker 处理带 v-for 的 slot template。
其后 slotOutlet、element 建立输出节点与 props/children。
最后 trackSlotScopes、transformText 维护 slot 深度，最后合并文本。
这张顺序表不是所有构建的固定编号：compat、browser 和 prefixIdentifiers 会增删插件，但相对约束不变。表达式转换若早于 v-for 作用域登记，会把 item 错改成 _ctx.item；元素转换若不等 children 完成，就无法正确判断 slots、动态文本和 block 身份。

先从 props 删掉 v-if/v-for，再移动并重遍历原元素。如果不先删，原元素再次进入同一个结构转换器，会不停套新的结构节点。<template v-slot>则交给 slot 转换统一管理，避免两套逻辑争抢同一层结构。

05 / Expressions

改表达式之前，先认清每个名字属于谁

给名字补前缀并不难；真正要判断的是 Identifier 在 Babel AST 的当前位置是否属于外部值引用。

需要前缀

{{ count + format(total) }}

_ctx.count + _ctx.format(_ctx.total)

自由值引用来自组件渲染上下文。

不能前缀

items.map(item => item.id)

_ctx.items.map(item => item.id)

函数参数、静态属性 key、声明与类型位置不是上下文变量。

表达式从模板源码到可打印节点

createExp保存 content / loc；可预解析 exp.ast
→
模板作用域v-for / v-slot 写入 identifiers
→
processExpression简单名快路径或 walkIdentifiers
→
绑定分流局部名 / _ctx / $setup / ref.value
→
ExpressionNode原节点或 CompoundExpression + 精确 loc
exp.ast 的三种状态：null 表示简单标识符，可直接改写；Babel AST 表示复合表达式，可复用预解析结果； false 表示 Parser 已报告语法错误，Transform 直接返回，避免重复诊断。

摘录保留绑定分流、简单标识符快路径和 Babel AST 标识符遍历； setup let 的完整写回协议与 source-map 位置拼接不影响这里的作用域判断，故省略。

两层作用域信息

context.identifiers 来自模板结构（v-for/v-slot）；Babel 的 isLocal 来自 JS 表达式内部（箭头函数参数/局部声明）。两层都不命中才是外部值。

SFC 元数据决定读法

inline 模式直接读取 setup 作用域：ref 用 .value，maybe-ref 用 unref()，prop 用 __props；非 inline 模式分别通过 $setup、$props 等渲染参数访问。未知绑定才回退到 _ctx。compileScript 提供绑定分类后，模板编译器才有这些访问路径。

单标识符有快路径

{{ count }} 不值得创建并遍历整棵 Babel AST；只有 count + list.map(x => x.id) 这类复合表达式才进入完整语法分析。

不能用正则完成

{ foo } 中 foo 既是 key 又是 value，obj.foo 只能改 obj，而 obj[foo] 两者都可能是引用。只有 AST 父子关系能区分这些语义。

语境 规则 典型陷阱
MemberExpression obj 是引用，非计算 prop 不是 foo.bar 只改 foo；foo[bar] 两者都可能改。
ObjectProperty 静态 key 不是，value 是 对象简写同时承担 key 与 value。
Assignment 右值读取，左值仍是写入目标 Babel 默认引用判断忽略左值，Vue 必须补充。
Function / Block 参数和局部声明加入 knownIds 嵌套同名遮蔽必须计数。
TypeScript 剥离 as、satisfies、non-null 等外壳 纯类型节点没有运行时引用。
Destructure 递归提取绑定 Identifier 对象、数组、rest、default 与赋值语义组合。
bindingMetadata 快速路径：SFC 已知变量是 props、ref、maybe ref、let 或 literal const。模板转换可直接生成相应访问/赋值代码，而非全部经过实例代理。

06 / Structural Transforms

先改结构，再构造 VNode

v-if 与 v-for 不是普通 props；它们替换原元素，建立专用结构节点并生成控制流。

v-if

把相邻 if / else-if / else 合并为 branches；为分支注入稳定 key，生成嵌套条件表达式或 block。

v-for

解析 source 与 value/key/index aliases，建立局部作用域，生成 renderList 与不同稳定性的 Fragment。

本节展开 v-if 与 v-for。v-slot 的动态插槽、forwarded 标志和 createSlots() 分支见插槽相关源码注释。

v-if 先占住原位置

第一条分支把 ElementNode 换成 IfNode。后续兄弟看到的已不是原 div，而是可以继续追加 branches 的结构容器。

v-else 会离开兄弟数组

它从原 children 删除后并入前一个 IfNode。因为父级循环以后不会再访问它，代码必须当场 traverseNode(branch)，再手动执行该分支的退出函数。

空白和注释不一定断链

向前找 IfNode 时会移除纯空白和注释；开发版通常把注释塞回新分支， Transition 的单有效子节点场景除外。

输出在退出阶段接起来

根分支先建 ConditionalExpression，后续分支挂到最深的 alternate。有条件却无匹配分支时，用 block comment 占位；每个真实分支注入不同 key。

对 v-for="(item, i) in list"，list 先按外部表达式处理；item/i 随后进入局部标识符计数。子树中的 item/i 保持局部名，退出后计数撤销，后方兄弟再写 item 时仍会得到 _ctx.item。缺少或无法拆分表达式时，转换会先报告错误并返回， 不会创建一个字段不完整的 ForNode。

主 Demo 的 source 是 _ctx.list，不是编译期常量，也没有 key， 所以外层列表得到 UNKEYED_FRAGMENT，并以 openBlock(true) 禁止外层收集每一项内部的动态节点。若提供 key， 同一位置改用 KEYED_FRAGMENT；只有编译期稳定 source 才用 STABLE_FRAGMENT。

v-for 条件 列表 Fragment 每项输出
source 为编译期常量 STABLE_FRAGMENT，不禁用 tracking。 单元素在允许时可保留普通 VNode；多根仍包稳定 Fragment。
动态 source + key KEYED_FRAGMENT，openBlock(true)。 key 注入单项 VNode、Fragment 或 slot props。
动态 source + 无 key UNKEYED_FRAGMENT，openBlock(true)。 单元素通常升级为 block，保证每轮动态后代正确收集。
<slot v-for> 外层仍是列表 Fragment。 复用 renderSlot()，避免再包一层无意义 Fragment。

transformElement 的退出阶段

resolve tag原生 / 组件 / 动态组件
→
buildProps属性、指令、mergeProps
→
分析 children文本、slots、动态性
→
createVNodeCallpatchFlag / dynamicProps / block

必须在退出阶段做

父元素是否只有一个动态文本、组件 slots 是否动态，只有在子树转换完后才知道。所以函数本体只返回 postTransformElement。

tag 不总是字符串

原生 div 的 tag 是字符串；普通组件通常在 render 顶部解析为组件变量，再用 createVNode() 创建。动态 <component :is> 会生成 resolveDynamicComponent，并独立成为 block。普通组件是否成为 block，还取决于它是否位于模板根、条件分支等位置。

SVG/MathML 边界为什么强制成为 block

SVG/MathML 内的 class、属性和子节点需使用对应命名空间的 patch 路径。如果边界没有成为 block，动态后代可能脱离正确的平台上下文被更新。

buildProps 产出的不只是 props

它同时给出 patchFlag、dynamicPropNames、运行时指令与 block 约束。因为“属性怎样变”比“属性值是什么”更直接影响 renderer。

从模板到 patch 协议 
<button class="save" :disabled="busy" @click="save">{{ label }}</button>

props           = { class: "save", disabled: _ctx.busy, onClick: _ctx.save }
patchFlag       = TEXT | PROPS  →  9
dynamicProps    = ["disabled", "onClick"]
运行时结果      = 只更新文本和这两个属性，不遍历全部 props

buildProps 的输入复杂度

  • 静态与动态属性。
  • 无参数 v-bind 与动态参数（如 :[name]）。
  • class/style/event 规范化。
  • 编译期指令与运行时自定义指令。

buildProps 的输出决策

  • 对象表达式或 mergeProps 调用。
  • FULL_PROPS / PROPS / CLASS / STYLE。
  • 精确 dynamicProps 名单。
  • NEED_PATCH / NEED_HYDRATION 与 block 要求。

07 / Optimization

静态性不是一个 boolean

ConstantTypes 分级描述节点能安全做到什么；cacheStatic、transformElement 与 DOM stringifyStatic 各自利用这份信息。

ConstantTypes 含义 可做的事
NOT_CONSTANT 依赖动态上下文 保留正常 render/patch。
CAN_SKIP_PATCH 值稳定到可跳过 patch，但未必适合跨 render 保存 编译器可据此减少该表达式对应的更新工作；这个编译期等级不会原样传给 runtime，也不足以直接生成缓存槽。
CAN_CACHE 可提升或缓存 按节点种类进入 _hoisted_n 或 _cache[n]。
CAN_STRINGIFY 可稳定序列化为 HTML 具备前述能力，DOM 平台还可合并为 StaticVNode。

等级是能力包含关系

CAN_STRINGIFY 的节点必然也能 cache/skip patch；CAN_SKIP_PATCH 却不一定能移到模块外。数值顺序让算法可用最小值传播整棵子树的安全级别。

根元素是特例

单元素根保持 VNodeCall，随后由 createRootCodegen 转为 block。即使后代全部静态，renderer 仍可通过这个更新边界跳过静态 children；cacheStatic 继续缓存它的静态后代。父组件传入的 attrs 在 renderComponentRoot 中另行合并到根 VNode。

数组缓存比逐个 VNode 更省

一整组静态 children 共用一个 _cache[n]，减少缓存槽和缓存判断。读取时仍会浅拷贝数组，让 runtime 修改本次 children 时不会写回缓存；缓存主要省去静态 VNode 的重复创建。

优化也要防引用泄漏

runtime 挂载 children 时会克隆 VNode 并写回数组。每次取缓存都展开一份新数组，才能避免列表项互相污染，也不让长寿命缓存持有 DOM el。

hoist（当前主要是 props）

Vue 3.5.41 仍把稳定 props 对象和 dynamicProps 键名数组提升到 render 外，生成 _hoisted_n；稳定 VNode/children 已不走这条路径。

cache

稳定 VNode、整组 children、事件、v-once、v-memo 等写入 _cache[n]，只在当前组件实例内复用。

PatchFlags

动态维度压成位标记，runtime 只处理 TEXT、CLASS、STYLE 或明确 props。

3.5.41 快照里的两种产物 
// 动态元素的稳定 props：模块级提升
const _hoisted_1 = { id: "foo" }
_createElementVNode("div", _hoisted_1, _toDisplayString(_ctx.msg), 1)

// 稳定 VNode/children：实例级缓存，不再生成 const _hoisted_n = VNode
_createElementBlock("div", null, [
  ...(_cache[0] || (_cache[0] = [
    _createElementVNode("span", { class: "inline" }, "hello", -1 /* CACHED */)
  ]))
])
优化限制：组件、结构分支、自定义指令、局部作用域引用、动态指令参数，以及产生 patchFlag 的动态 props、ref 或 hydration 事件会阻止整节点进入静态缓存。scopeId 不会降低 ConstantTypes；DOM 字符串化会把它写进静态 HTML。当前 3.5.41 的 hmr 选项也不参与这段常量分析。

08 / Codegen

Codegen 只打印已经定稿的 JS 结构

generate() 按 mode、ssr、inline、sourceMap 建立上下文，再根据 RootNode 保存的 helper、hoist、组件和指令集合生成 序言、资源声明和函数体。

generate(ast, options)

Preamblehelper imports / hoists
→
Signaturerender 或 ssrRender
→
Assetscomponents / directives
→
genNode递归打印 codegen AST

摘录只删掉了组件/指令解析、compat filter 与临时变量输出；它们位于序言之后、根 genNode() 之前。默认客户端签名是 (_ctx, _cache)；非 inline 且带 binding metadata 时还会追加 $props/$setup/$data/$options。

先生成序言

module 模式打印 ESM imports，function 模式从全局 Vue 解构 helper。helpers 来自 transform 写回 RootNode 的 Set，因此没用到的 helper 不会出现。

签名先看默认，再看附加分支

默认客户端 render 接收 _ctx/_cache 并返回 VNode；SSR ssrRender 改为 _ctx/_push/_parent/_attrs，通过 _push 输出 HTML。SFC 非 inline 模式还可能加四个 binding 参数。

with 属于“无前缀 function 模式”

条件是 !prefixIdentifiers && mode !== 'module'。浏览器运行时编译最常走这条路，但 Node 端直接使用默认 function 模式也会走；开启前缀或 module 模式才靠 _ctx.x 避开 with。

genNode 不做语义判断

它按 NodeTypes 分派到 genVNodeCall、genConditionalExpression、genCallExpression 等打印器。如果这里才开始判断 v-if 或 v-model，就说明 transform 责任泄漏了。

Element/If/For 在这里不会重新跑模板规则，只会转到 transform 已挂好的 codegenNode。开发版若缺少它会直接断言，能很快暴露“忘了安装某个转换”这类插件错误。

主链怎样提前结束：Parser 默认 onError 会抛出并终止编译；Transform 插件若删除当前节点，traverseNode() 立即返回，不再递归 children，也不执行该节点已收集的 exitFns；非法 v-for 在报告错误后不创建 ForNode。Generate 面对空 Root 会输出 null；Element/If/For 已存在却缺少 codegenNode 时，开发版断言提示转换器没有装齐。

普通 VNode 与 block 用不同 helper

isBlock 决定是否先打印 openBlock()，以及调用 createVNode 还是 createBlock；组件与原生元素又各有一套 helper。

openBlock(true) 不是随手多传一个参数

disableTracking 为真时打印 true，典型场景是动态 v-for Fragment：列表项自己管理动态节点，外层不应把它们全收进同一 block。

中间空参数必须补 null

有 patchFlag 却没有 props/children 时，调用仍需保留参数位置；只有末尾连续空值能删。测试直接锁定了 createElementVNode("div", null, null, 1)。

指令包在最外层

有运行时指令时最终形状是 withDirectives(vnode, dirs)；若 vnode 本身是 block，openBlock/createBlock 的配对仍完整留在内层。

生成分支 序言 函数形状
module 从 runtime module 生成 ESM imports，再输出 hoists。 export function render(...)；默认启用标识符前缀。
function + 无前缀 保存 const _Vue = Vue；helper 在 with 内解构。 return function render + with (_ctx)。
function + 前缀 helper 直接在顶层从 runtime global 解构。 没有 with，表达式已是 _ctx.x。
setup inline 独立 CodegenContext 生成并返回 preamble。 主体是可嵌入 setup 作用域的箭头函数。
SSR 客户端 helper 与 server-renderer helper 分开处理。 ssrRender 不加 return，由 codegenNode 里的 _push 产生副作用。

开启 source map 时，CodegenContext 的 push() 会同步维护 generated line/column/offset，并按 AST location 写映射。setup inline 模式还把 helper/hoist 序言单独放进 preamble，让 render 闭包能嵌回 setup 作用域。

09 / Reliability

哪些行为真的有测试兜底

不能只看测试名猜机制。下面把代表用例拆成输入、动作、断言和它能证明的范围。

同一测试同时锁住两条路径：默认处理器确实抛错；换成收集型处理器后，Parser 按开放栈恢复并返回 AST，而且两次诊断的位置不同、含义也不同。

测的是遍历不变量

断言不只检查 div 消失，还检查被删除节点的 text child 没有再进入插件，且后方 sibling 没因为数组索引左移而被跳过。

为什么要保留节点引用

toBe(c1) 检查对象身份，可以防止实现“看似结构相同”却意外克隆未变兄弟。这会影响后续插件保存在节点上的信息。

开启前缀模式后，两个 foo 保持函数局部名，bar 改为 _ctx.bar；对应 processExpression() → walkIdentifiers() 中的 needPrefix && !isLocal 分支。

这里的 source 在测试文件顶部定义，包含动态 class、插值、v-if/v-else 和 v-for。快照验证最终 JS；source map 断言又把生成的 _ctx.ok/_ctx.list 映回模板原标识符，因此 Parse 的 loc、Transform 的前缀改写和 Codegen 的 push/mapping 三段必须同时正确。

主线回看

  1. Parser 不是“先产 token 数组再建树”，而是 tokenizer 用 offset 回调驱动组装；标签栈负责闭合与恢复，默认错误处理仍会直接 throw。
  2. Transform 的关键是 enter 建环境、children 先完成、exit 再汇总； v-if/v-for 会改树，不能当成普通 props。
  3. TransformContext 保存本轮转换状态，结束时把 helper、资产、hoist、cache 和 codegenNode 固化到 RootNode；generate 只读取这份已经定稿的结果。
  4. Codegen 按节点类型打印，不重新理解模板。module/function/inline/SSR 改变序言和函数外壳，VNodeCall 自身已经带齐 block、flag、动态 props 与指令协议。
