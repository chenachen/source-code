模板编译的共享内核。它定义语言结构、AST 协议、转换插件模型和 JavaScript 生成器，却刻意把 DOM/SSR 平台知识留给上层。

01 / Entry

baseCompile：三段管线的总装线

它不亲自实现每个转换，只负责校验模式、合并 options、排列插件并把阶段串起来。

baseCompile(source, options)

校验构建模式browser / module / scopeId
→
baseParse字符串解析，RootNode 复用
→
transform基础转换 + 用户转换
→
generatecode / preamble / map

为聚焦主线，上方只省略了 browser/module、cacheHandlers 与 scopeId 的组合校验；三阶段调用保持原样。

入口允许两种输入

单独编译模板时传字符串；SFC 若已得到 template AST，可传 RootNode 避免第二次 parse。这是 compiler-core 与 compiler-sfc 的性能接口。

转换是唯一的语义中心

Parser 只记录“用户写了什么”；transform 把指令、作用域、 patchFlag 和 codegenNode 全部决定好，因此 generate 无需再理解模板。

数组追加，对象覆盖

nodeTransforms 依赖顺序，所以用数组追加；directiveTransforms 按名称查找，上层可用同名键替换默认语义。

返回值不只有 code

CodegenResult 还携带 AST、preamble 与 source map。测试可直接断言 AST 上的 patchFlag/hoist，构建工具则消费代码与映射。

用一个最小输入心算 
输入：<div :id="uid">{{ msg }}</div>
Parse：Element(div) + Directive(bind:id=uid) + Interpolation(msg)
Transform：uid/msg → _ctx.uid/_ctx.msg，元素获得 PROPS | TEXT
Generate：_createElementBlock("div", { id: _ctx.uid }, _toDisplayString(_ctx.msg), 9, ["id"])

为什么接收 RootNode

SFC parse 已经解析过完整文件。模板未预处理且编译器兼容时，可直接复用 template AST，避免重复解析。

为什么先处理 prefixIdentifiers

module 模式需要显式上下文访问；浏览器运行时编译依赖 with (_ctx)，两者支持的优化组合不同。

为什么用户转换放在后面

用户插件通常希望读取归一化结构；同名 directive transform 又允许覆盖基础语义，供平台层定制。

阶段 输入 主要副作用/输出 代表文件
Parse 模板字符串 创建带 location 的模板 AST tokenizer.ts、parser.ts
Transform RootNode 原地改树、挂 codegenNode、收集 helpers/hoists transform.ts、transforms/*
Generate 已转换 RootNode 输出 render 代码、preamble、source map codegen.ts

02 / Parse

Tokenizer 与 Parser 如何协作

Tokenizer 负责识别边界并发事件，Parser 维护上下文并组装节点；中间没有一份完整 token 数组。

Tokenizer：单遍有限状态机

逐字符扫描，状态描述当前位于文本、标签名、属性名、指令参数、注释、CDATA 或插值。发现边界时直接调用 parser callbacks。

StateCharCodesParseModeEntityDecoder

Parser：事件驱动组装器

维护当前打开标签、属性、标签栈和全局 options。开始/结束事件创建 Element、Attribute、Directive、Text、Interpolation，并精确计算 location。

stackcurrentOpenTagcurrentPropcurrentOptions

以 div + v-bind + interpolation 为例

Text遇到 <
→
InTagNameonopentagname(div)
→
Directivebind + arg:id + value:x
→
Interpolation创建表达式节点
→
Close Tag弹栈并封闭 loc

输入 x<div> 时，< 先触发 ontext(0, 1)，状态转到 BeforeTagName；扫描到 > 才用起止 offset 触发 onopentagname。 回调收到的是原字符串切片边界，不是另建的 token 对象。

先 reset，再解析

Parser 为了热路径性能复用了模块级 tokenizer、栈和当前属性。 reset 是编译任务的隔离墙，否则上一个模板的未闭合状态会污染下一个。

ParserOptions 是平台接口

core 不硬编码“img 是空标签”或“svg 需命名空间”。compiler-dom 通过 options 注入这些知识，SFC 则选择 sfc 解析模式。

没有完整 token 数组

tokenizer.parse() 边扫描边触发 ontext/onopentagname/onattribname 等回调，Parser 当场组装节点。这比“先分词、再遍历 token”少一份中间内存。

空白在最后统一收口

标签栈、<pre>、相邻元素和 whitespace 选项都会影响空白。先完整建树，再 condenseWhitespace，才能用上下文作出一致判断。

事件式解析的实际交接 
<button :disabled="busy">Save {{ count }}</button>

Tokenizer 事件：open(button) → directive(bind, disabled, busy)
                 → text("Save ") → interpolation(count) → close(button)
Parser 组装： ElementNode.props[DirectiveNode]
                 ElementNode.children[TextNode, InterpolationNode]

三种 ParseMode

模式 用途 特殊行为
BASE 平台无关模板 所有标签内容按普通模板结构解析。
HTML compiler-dom 支持 RAWTEXT、RCDATA 和 HTML/SVG/MathML namespace。
SFC compiler-sfc parse 根级非 template block 按原始文本读取，避免误解 script/style 内容。
模块级可变状态的取舍：编译是同步单次任务，复用 tokenizer 与临时对象可减少热路径分配。baseParse() 开始时 reset，结束后清理 currentRoot，测试则专门覆盖状态不能泄漏到下一次解析。

实体解码

Node 构建使用 entities；浏览器构建可借助原生 HTML 元素，构建标志保证不需要的实现被 tree-shake。

空白整理

节点先完整建立，最后按 preserve/condense、pre 与相邻元素上下文统一处理。

表达式预解析

Node 构建可用 Babel 解析表达式、参数或多语句并缓存失败状态；浏览器生产构建保持轻量。

03 / AST

一份文件里有两类 AST

模板 AST 表达用户写了什么；JS/codegen AST 表达应该生成怎样的 JavaScript。

Template AST

  • RootNode
    • ElementNode tag / props / children
    • IfNode branches[]
    • ForNode source / aliases
    • InterpolationNode
    • TextNode

JS / Codegen AST

  • VNodeCall
    • JSCallExpression
    • JSObjectExpression
    • JSFunctionExpression
    • JSConditionalExpression
    • CacheExpression
    • TemplateLiteral SSR

它不是运行时 VNode

VNodeCall 只是“将来要打印一次 VNode 调用”的编译期描述。此时没有 DOM、component instance 或响应式副作用。

字段就是编译期/运行时协议

patchFlag 告诉 renderer 哪些部分会变，dynamicProps 给出精确键名，isBlock 决定是否收集动态后代。运行时的快，来自编译期先做了分类。

helper 按需登记

createVNodeCall 不拼字符串，却会登记 openBlock/createElementBlock/ withDirectives 等 helper。generate 最后只导入真正用到的函数。

为什么不直接保存代码字符串

transformElement 后面还可以增加 directive、提升 props，或把普通 VNode 升级为 block。结构化节点让这些后续优化不需重写字符串。

分类 关键节点 阅读重点
词法叶子 TEXT、COMMENT、SIMPLE_EXPRESSION、INTERPOLATION content、isStatic、constType、loc
模板容器 ROOT、ELEMENT、IF、IF_BRANCH、FOR children、结构替换、codegenNode
元素属性 ATTRIBUTE、DIRECTIVE arg、exp、modifiers、静态/动态参数
JS 表达式 CALL、OBJECT、FUNCTION、CONDITIONAL 由 transform 创建，供 generate 打印
SSR 节点 TEMPLATE_LITERAL、IF_STATEMENT、BLOCK_STATEMENT 线性字符串输出与控制流
最关键字段是 codegenNode：parser 不填它；transform 在退出阶段根据完整子树生成。于是模板结构和输出结构可以并存，codegen 无需反推模板语义。

Location

所有语义节点带 start/end/source，服务错误、source map、IDE 与精确测试。

Helper Symbol

AST 保存 symbol 而非硬编码导入名，平台可注册 helper 映射。

工厂函数

createVNodeCall 等工厂同时保证字段形状、helper 登记和 block 约束。

04 / Transform

进入、递归、退出

转换阶段原地修改 AST，并通过 TransformContext 共享作用域、资源与优化信息。

单个节点的生命周期

按顺序 enterNodeTransform 1 → N
→
替换 / 删除修正 currentNode 与游标
→
递归 children子树先完成转换
→
逆序 exitN → NodeTransform 1

enter 适合建立环境

v-for/v-slot 在进入节点时把 item、index 或 slot props 登记为局部变量，子孙表达式遍历时就不会把它们误写为 _ctx.item。

exit 适合汇总子树

transformElement 返回 postTransformElement，等 children 的 codegenNode、插槽动态性和文本合并都完成后，才构造父 VNodeCall。

替换/删除是一等能力

v-if 会把 ElementNode 换成 IfNode；忽略副作用的 <script> 转换则可删节点。currentNode 让后续插件始终处理最新树。

为什么 exit 逆序

先注册的高层转换最后退出，可以看到后续转换已经增补的结果。 这与递归 visitor 的 leave 阶段相同，也是插件顺序成为语义的原因。

遍历位置

currentNode、parent、grandParent、childIndex 和节点删除回调。

作用域

identifiers 计数，v-for/v-slot 深度，v-once 状态。

资源账本

helpers、components、directives、imports、filters。

优化槽位

hoists、cached、temps、constantCache。

树操作

replaceNode、removeNode、hoist、cache。

扩展与诊断

onError、onWarn、node/directive transforms、transformHoist。

基础顺序 转换 顺序原因
1 transformVBindShorthand 先把同名简写归一化。
2–5 v-once、v-if、v-memo、v-for 结构指令会替换原节点，必须先改树。
6 trackVForSlotScopes 先登记局部变量。
7 transformExpression 有作用域信息后才能安全添加 _ctx.。
8–9 slotOutlet、element 建立输出节点与 props/children。
10–11 trackSlotScopes、transformText 维护 slot 深度，最后合并文本。
插件顺序就是语义：表达式转换若早于 v-for 作用域登记，会把 item 错改成 _ctx.item；元素转换若不等 children 完成，就无法正确判断 slots、动态文本和 block 身份。

05 / Expressions

表达式改写本质是作用域分析

难点不是字符串加前缀，而是判断 Identifier 在 Babel AST 的当前位置是否构成外部值引用。

需要前缀

{{ count + format(total) }}

_ctx.count + _ctx.format(_ctx.total)

自由值引用来自组件渲染上下文。

不能前缀

items.map(item => item.id)

_ctx.items.map(item => item.id)

函数参数、静态属性 key、声明与类型位置不是上下文变量。

每一条可执行语句均取自当前源码；“……”只标记被裁掉的完整分支。 摘录保留了绑定分流、简单标识符快路径，以及 Babel AST 标识符遍历，省略了 setup let 的完整写回协议和 source-map 位置拼接。

两层作用域信息

context.identifiers 来自模板结构（v-for/v-slot）；Babel 的 isLocal 来自 JS 表达式内部（箭头函数参数/局部声明）。两层都不命中才是外部值。

SFC 元数据决定读法

已知 ref 读 .value，maybe-ref 读 unref()，prop 读 __props，未知名字才回退到 _ctx。这是 compileScript 的绑定分类真正换来的代码优化。

单标识符有快路径

{{ count }} 不值得创建并遍历整棵 Babel AST；只有 count + list.map(x => x.id) 这类复合表达式才进入完整语法分析。

不能用正则完成

{ foo } 中 foo 既是 key 又是 value，obj.foo 只能改 obj，而 obj[foo] 两者都可能是引用。只有 AST 父子关系能区分这些语义。

语境 规则 典型陷阱
MemberExpression obj 是引用，非计算 prop 不是 foo.bar 只改 foo；foo[bar] 两者都可能改。
ObjectProperty 静态 key 不是，value 是 对象简写同时承担 key 与 value。
Assignment 右值读取，左值仍是写入目标 Babel 默认引用判断忽略左值，Vue 必须补充。
Function / Block 参数和局部声明加入 knownIds 嵌套同名遮蔽必须计数。
TypeScript 剥离 as、satisfies、non-null 等外壳 纯类型节点没有运行时引用。
Destructure 递归提取绑定 Identifier 对象、数组、rest、default 与赋值语义组合。
bindingMetadata 快速路径：SFC 已知变量是 props、ref、maybe ref、let 或 literal const。模板转换可直接生成相应访问/赋值代码，而非全部经过实例代理。

06 / Structural Transforms

先改结构，再构造 VNode

v-if 与 v-for 不是普通 props；它们替换原元素，建立专用结构节点并生成控制流。

v-if

把相邻 if / else-if / else 合并为 branches；为分支注入稳定 key，生成嵌套条件表达式或 block。

v-for

解析 source 与 value/key/index aliases，建立局部作用域，生成 renderList 与不同稳定性的 Fragment。

v-slot

收集静态/动态 slot、作用域参数和 forwarded 标志；条件/循环 slot 进入 createSlots 动态描述。

transformElement 的退出阶段

resolve tag原生 / 组件 / 动态组件
→
buildProps属性、指令、mergeProps
→
分析 children文本、slots、动态性
→
createVNodeCallpatchFlag / dynamicProps / block

必须在退出阶段做

父元素是否只有一个动态文本、组件 slots 是否动态，只有在子树转换完后才知道。所以函数本体只返回 postTransformElement。

tag 不总是字符串

原生 div 直接是 "div"；普通组件可能生成 resolveComponent()；<component :is> 则生成 resolveDynamicComponent。后两者需要更保守的 block 边界。

#639/#643 的具体场景

SVG/MathML 内的 class、属性和子节点需使用对应命名空间的 patch 路径。如果边界没有成为 block，动态后代可能脱离正确的平台上下文被更新。

buildProps 产出的不只是 props

它同时给出 patchFlag、dynamicPropNames、运行时指令与 block 约束。因为“属性怎样变”比“属性值是什么”更直接影响 renderer。

从模板到 patch 协议 
<button class="save" :disabled="busy" @click="save">{{ label }}</button>

props           = { class: "save", disabled: _ctx.busy, onClick: _ctx.save }
patchFlag       = TEXT | PROPS  →  9
dynamicProps    = ["disabled", "onClick"]
运行时结果      = 只更新文本和这两个属性，不遍历全部 props

buildProps 的输入复杂度

  • 静态与动态属性。
  • 无参数 v-bind 与动态参数（如 :[name]）。
  • class/style/event 规范化。
  • 编译期指令与运行时自定义指令。

buildProps 的输出决策

  • 对象表达式或 mergeProps 调用。
  • FULL_PROPS / PROPS / CLASS / STYLE。
  • 精确 dynamicProps 名单。
  • NEED_PATCH / NEED_HYDRATION 与 block 要求。

07 / Optimization

静态性不是一个 boolean

ConstantTypes 分级描述节点能安全做到什么；cacheStatic、transformElement 与 DOM stringifyStatic 各自利用这份信息。

ConstantTypes 含义 可做的事
NOT_CONSTANT 依赖动态上下文 保留正常 render/patch。
CAN_SKIP_PATCH 本次无需 patch，但不一定能提升 运行时跳过局部更新。
CAN_CACHE 可写入实例缓存槽 生成 _cache[n]。
CAN_STRINGIFY 可稳定序列化为 HTML DOM 平台合并为 StaticVNode。

等级是能力包含关系

CAN_STRINGIFY 的节点必然也能 cache/skip patch；CAN_SKIP_PATCH 却不一定能移到模块外。数值顺序让算法可用最小值传播整棵子树的安全级别。

根元素是特例

即使 <div class="box"> 全静态，它作为组件根时仍可能合并父组件 attrs。整体缓存会固定上一次的 class/id，所以只继续优化它的后代。

数组缓存比逐个 VNode 更省

一整组静态 children 共用一个 _cache[n]，可减少缓存槽、条件表达式和每次 render 的数组分配。

优化也要防引用泄漏

runtime 挂载 children 时会克隆 VNode 并写回数组。每次取缓存都展开一份新数组， 才能避免列表项互相污染，也不让长寿命缓存持有 DOM el。

hoist（当前主要是 props）

Vue 3.5.41 仍把稳定 props 对象和 dynamicProps 键名数组提升到 render 外，生成 _hoisted_n；稳定 VNode/children 已不走这条路径。

cache

稳定 VNode、整组 children、事件、v-once、v-memo 等写入 _cache[n]，只在当前组件实例内复用。

PatchFlags

动态维度压成位标记，runtime 只处理 TEXT、CLASS、STYLE 或明确 props。

3.5.41 快照里的两种产物 
// 动态元素的稳定 props：模块级提升
const _hoisted_1 = { id: "foo" }
_createElementVNode("div", _hoisted_1, _toDisplayString(_ctx.msg), 1)

// 稳定 VNode/children：实例级缓存，不再生成 const _hoisted_n = VNode
_createElementBlock("div", null, [
  ...(_cache[0] || (_cache[0] = [
    _createElementVNode("span", { class: "inline" }, "hello", -1 /* CACHED */)
  ]))
])
优化限制：组件、自定义指令、HMR、scopeId、局部作用域引用、动态指令参数、ref 与 hydration 事件都会降低静态级别。复杂分支是在证明优化不会改变引用身份或挂载行为。

08 / Codegen

代码生成器是一台可靠打印机

generate 按 mode、ssr、inline、sourceMap 建立上下文，再根据 RootNode 账本生成序言与函数体。

generate(ast, options)

Preamblehelper imports / hoists
→
Signaturerender 或 ssrRender
→
Assetscomponents / directives
→

先生成序言

module 模式打印 ESM imports，function 模式从全局 Vue 解构 helper。helpers 来自 transform 的 Set，因此没用到的 helper 不会出现。

签名揭示两种目标

客户端 render 接收 _ctx/_cache 并返回 VNode；SSR ssrRender 多了 _push/_parent/_attrs，通过副作用输出 HTML。

with 只服务浏览器运行时编译

构建时可把自由变量改为 _ctx.x；浏览器版不携带 Babel 分析成本，只能把模板表达式放进 with (_ctx) 中求值。

genNode 不做语义判断

它按 NodeTypes 分派到 genVNodeCall、genConditionalExpression、genCallExpression 等打印器。如果这里才开始判断 v-if 或 v-model，就说明 transform 责任泄漏了。

module 模式

import { openBlock as _openBlock,
  createElementBlock as _createElementBlock
} from "vue"

export function render(_ctx, _cache) { ... }

function / runtime 模式

const _Vue = Vue
return function render(_ctx, _cache) {
  with (_ctx) {
    const { ... } = _Vue
    return ...
  }
}

CodegenContext 的 push() 同时维护 generated line/column/offset，并按 AST location 写 source map。setup inline 模式还把 helper/hoist 序言单独放进 preamble，让 render 闭包能嵌回 setup 作用域。

09 / Reliability

错误码与测试构成行为边界

测试保护的不只是能否编译，还包括位置、helper 计数、block 身份与优化不变量。

Parser 错误

HTML 标准错误、结束标签、插值/属性/指令边界和 EOF 恢复，通常断言精确 location。

Transform 错误

结构指令、v-model、v-slot 的语义限制，以及重复 key、不可写表达式和作用域约束。

编译模式错误

浏览器构建不支持 module/prefixIdentifiers，scopeId 与 cacheHandlers 也有前置条件。

测的是遍历不变量

断言不只检查 div 消失，还检查被删除节点的 text child 没有再进入插件，且后方 sibling 没因为数组索引左移而被跳过。

为什么要保留节点引用

toBe(c1) 检查对象身份，可以防止实现“看似结构相同”却意外克隆未变兄弟。 这会影响后续插件保存在节点上的信息。

parse.spec.ts AST、location、EOF/HTML 容错、空白与实体。
