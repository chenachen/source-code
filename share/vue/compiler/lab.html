01 / Setup

先学会只跑相关测试

整个 compiler 测试很快，但单文件/单标题更适合反复观察。

运行前提：先进入 Vue 仓库根目录（能看到 pnpm-workspace.yaml），使用 Node.js 20 或更高版本、仓库锁定的 pnpm，并已执行 pnpm install。下面路径都从仓库根计算；若在 share/vue/compiler 目录直接运行，会找不到测试与配置。 
# 在 Vue 仓库根确认环境
node --version        # 期望 v20+
pnpm --version
test -d node_modules  # 失败则先 pnpm install

# 类型检查
pnpm check

# 四个 compiler 包
node node_modules/vitest/vitest.mjs run \
  packages/compiler-core/__tests__ \
  packages/compiler-dom/__tests__ \
  packages/compiler-sfc/__tests__ \
  packages/compiler-ssr/__tests__ \
  --project unit

# 单个测试文件
node node_modules/vitest/vitest.mjs run \
  packages/compiler-core/__tests__/transforms/vFor.spec.ts \
  --project unit

# 只跑匹配标题
node node_modules/vitest/vitest.mjs run \
  packages/compiler-sfc/__tests__/compileScript/defineProps.spec.ts \
  --project unit --reporter=verbose \
  -t "w/ type$"

标题过滤是正则并匹配包含文件/suite 前缀的完整测试名，因此只锚定末尾； 本命令在 3.5.41 应显示 defineProps > w/ type 且汇总为 1 passed。只看退出码不够： 拼错 -t 时，Vitest 可能报告 0 tests，却仍未替你验证目标断言。

优先复制现有测试

它已经准备好 compiler options、AST 断言与快照规范，减少环境噪音。

同时看三个结果

parse AST、transform/codegenNode、最终 code。不要只盯字符串快照。

一次改变一个变量

静态指令参数 :id → 动态参数 :[name]、顶层绑定 → 局部绑定、单根 → 多根，差异最清晰。

02 / Lab 1

Parse：手画 AST，再看 location

目标是区分 tokenizer 边界、parser 组装与平台 options，而不是记住所有状态。 

<svg>
  <foreignObject>
    <div :id="key">{{ value }}</div>
  </foreignObject>
</svg>

先预测节点类型

Root → Element(svg) → Element(foreignObject) → Element(div) → Interpolation。

预测 namespace

svg 与 foreignObject 属于 SVG；foreignObject 的 child div 回到 HTML。

拆 Directive

:id 归一化为 Directive(bind)，arg 是静态属性名 id，exp 是动态属性值 表达式 key。只有 :[key]="value" 的 arg 才是动态参数。

核对 location

检查 div、arg、exp、interpolation 的 source 与 offset 是否只覆盖对应片段。

制造残缺输入

删除最后两个结束标签，观察 errors 与恢复 AST；再比较 IDE 为什么仍可使用该结构。

观察点：namespace 是 parser options 的父上下文计算；Directive 的拆分由 tokenizer 状态完成；错误恢复后 root.loc 仍覆盖完整输入。
用半开区间核对坐标 
<div :id="key">{{ value }}</div>
01234567890123456789012345678901

Directive.loc  [5, 14)  → :id="key"
arg.loc        [6,  8)  → id
exp.loc        [10, 13) → key

start.offset 包含起点，end.offset 指向片段后一位；
行/列用于报错展示，offset 用于 MagicString 精确改写。

03 / Lab 2

Transform：证明顺序为什么不能交换

选择同时包含 v-for 局部变量、事件闭包与动态文本的模板。

<button
  v-for="(item, index) in items"
  :key="item.id"
  @click="select(item, index)"
>
  {{ item.label }}
</button>

进入 v-for 后

  • 原 Element 被 ForNode 包裹。
  • source=items。
  • item/index 加入 identifiers。
  • 子元素保留 key 指令等待元素转换。

离开子元素后

  • item/index 不加 _ctx。
  • items/select 加上下文访问。
  • handler 捕获循环 scope，不能全局 cache。
  • Fragment 根据 key 选择 KEYED_FRAGMENT。
尝试变化 预期变化 对应源码
删除 :key Fragment 从 KEYED 变 UNKEYED vFor.ts
handler 不引用 item/index 在允许条件下更可能 cache vOn.ts + hasScopeRef
把 item.label 换静态文本 子 VNode 不再需要 TEXT flag transformText / transformElement
外套 v-if 结构转换形成 IfNode 与 ForNode 嵌套 vIf.ts + vFor.ts 顺序

04 / Lab 3

SFC：跟踪一个绑定的身份变化

同一个名字在 script、template、style 三条分支里有不同表达，但依赖同一 binding metadata。 

<script setup lang="ts">
const { color = 'red' } = defineProps<{
  color?: string
}>()
</script>

<template><div class="box">{{ color }}</div></template>
<style scoped>.box { color: v-bind(color); }</style>

同一个 color 的三种落点

defineProps colorPROPS + String + default
↗
→
↘
Script

读取改成 __props.color；默认值进入 runtime props。

Template

插值直接访问 props/binding，不经普通实例代理。

Style

v-bind(color) → var(--id-color)，useCssVars 提供值。

实验变化：把 color 默认值改成函数、对象或 imported value，观察默认值是否需要工厂包装/skip marker，以及宏提升限制何时报告错误。

05 / Lab 4

SSR：比较产物，不比较实现

用同一模板对照 DOM render 与 SSR _push，找出两边共同维护的节点协议。 

<ul v-if="ok" class="list">
  <li v-for="item in items" :key="item.id">
    {{ item.name }}
  </li>
</ul>
语义 客户端 SSR
v-if 条件 VNode block 与分支 key if statement；无 else 时注释占位
v-for renderList + keyed Fragment ssrRenderList + Fragment 注释边界
静态 class 静态 props，可提升 直接进入开始标签字符串
插值 toDisplayString + TEXT flag ssrInterpolate + HTML 转义
key 参与客户端 diff 通常不输出 HTML 属性，但节点顺序仍要一致
核心问题：哪些差异只是目标不同，哪些差异会破坏 hydration？key 不出现在 HTML 中是正常差异；漏掉列表 Fragment 边界可能是拓扑错误。
从 SSR v-for 测试开始
06 / Lab 5

Issue：从最小回归倒推不变量

选择已有 issue 注释，不先看修复代码，按失败类型建立假设。

读测试标题与中文场景注释

提取输入、错误表现、涉及的两个以上特性。

归类失败模式

状态泄漏、作用域误判、结构邻接、平台修正、优化过度、同构错位。

找最早错误阶段

先比较 descriptor/parse AST，再比较 codegenNode，最后才看生成代码。

预测修复点

是补 reset/cache key，还是调整 transform enter/exit，或降低 ConstantTypes？

再看 git blame/log

确认修复为何位于该层，并检查后续是否有同类回归。

推荐一：表达式作用域

从 transformExpressions、vOn 或 props destructure 中选择函数参数/解构 issue。

推荐二：类型缓存

从 resolveType 中选择 global scope、tsconfig 或先后编译顺序 issue。

推荐三：Hydration

从 TransitionGroup、HTML nesting、fallthrough attrs 中选择边界 issue。

09 / Glossary

核心术语

这些词在不同文件中反复出现；理解协议含义比翻译名称更重要。

Template AST

parser 产出的模板语义树，包含 Element/Directive/If/For/Interpolation 与 location。

Codegen Node

transform 挂到模板节点上的输出意图；通常是 VNodeCall 或 JS AST 节点。

NodeTransform

在 AST 进入阶段执行、可返回退出回调的插件。顺序和退出逆序都具有语义。

DirectiveTransform

按指令名调用，返回 props 和可选 runtime directive；平台可覆盖同名实现。

TransformContext

遍历共享账本：位置、作用域、helpers、components、hoists、cache 与树操作。

Runtime Helper

以 symbol 登记的运行时能力，如 createElementBlock、renderList、toDisplayString。

PatchFlag

编译器给 runtime 的动态维度位标记，决定精确 patch 分支。

Block

收集动态后代的 VNode 边界；运行时可跳过中间静态树。

ConstantTypes

表达式/节点静态性等级，决定 skip patch、cache、hoist 或 stringify。

Binding Metadata

SFC 脚本给模板的变量身份表，区分 props、ref、maybe ref、let、const。

SFCDescriptor

完整 .vue 的结构描述，连接 parse、script/template/style 编译与 HMR。

TypeScope

compiler-sfc 类型解析作用域，保存声明、imports、owner、文件、依赖与缓存。

ScopeId

scoped CSS 的 data-v-* 标识，需要在 CSS、客户端 VNode、SSR 与 slot 中一致传播。

Hydration Boundary

SSR 用注释/元素表示的节点范围，使客户端能把 VNode 树对齐到现有 DOM。

Hoist

把值提升出 render。Vue 3.5.41 主要用于稳定 props 与 dynamicProps 键名数组；稳定 VNode/children 改用实例 _cache，不要把两者混为一谈。

Preamble

render 主体之前的 helper imports、hoists 与 setup inline 序言。

10 / FAQ

常见理解误区

把这些边界分清，源码阅读会少绕很多路。

为什么 codegen 看起来没有太多“智能”？
因为动态性、结构、helper 和 codegenNode 已由 transform 决定。codegen 的责任是稳定打印与映射，而不是重新分析模板。
compiler-dom 为什么还要依赖 compiler-core 的 v-model？
core 先处理可赋值表达式、modelValue 与 update handler；DOM 再按元素类型选择表单 helper。两层分别表达通用组件协议与原生控件语义。
script setup 宏为什么只能在顶层使用？
宏参与组件 options 与 setup 签名生成，需要静态、唯一且可提升地分析。嵌套在条件/函数中会让编译期无法建立稳定组件契约。
为什么 SSR 还需要 VNode fallback？
组件 slot 在某些无 _push 的调用路径仍要提供普通 VNode 形式。SSR 直接输出和 VNode fallback 共享 slot 语义，但目标不同。
为什么测试里有大量看似非法的模板？
IDE 编辑时模板经常处于临时非法状态；parser 必须尽量恢复稳定 AST 和 location。另一些输入用于锁定 HTML 标准容错或安全边界。
阅读时要不要把所有枚举值背下来？
不用。先掌握分类与消费者：NodeTypes 连接 AST 分派，ErrorCodes 连接诊断，PatchFlags 连接 runtime，State 连接 tokenizer。遇到分支再查具体成员。
