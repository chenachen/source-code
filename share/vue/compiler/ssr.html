Module 04 · Server Rendering Target

compiler-ssr

服务端不需要创建可持续 patch 的 VNode 树，而要高效、安全地输出 HTML 字符串。但它仍必须与客户端保持组件、slot、scopeId 和 hydration 节点边界一致。

入口：compile()目标：ssrRender + _push关键结构：两遍转换
从“创建 VNode”切换到“生成 HTML 程序”

本页嵌入 SSR 入口、两遍转换、字符串缓冲、安全属性、组件插槽与 v-if/v-for 的真实源码。每个 hydration 注释都会说明它在客户端对齐了什么，不将它们当成普通输出细节；范围只到 “编译器生成何种边界”，客户端如何接管与处理 mismatch 属于 runtime-core。

01 / Entry

SSR 先重设编译目标

compile() 复用 DOM parserOptions，但强制设置 ssr/inSSR、prefixIdentifiers，并关闭客户端专属优化。

选项 SSR 设置 原因
ssr / inSSR true 让共享转换知道当前目标，选择 SSR helper 与语义。
prefixIdentifiers true 服务端函数不使用 with，所有上下文访问必须明确。
cacheHandlers false 每次 SSR 只生成一次字符串，客户端实例缓存没有收益。
hoistStatic false 客户端 VNode 提升不适用于服务端字符串流。
scopeId 显式指定 mode: 'function' 时置空 清空条件检查传入的 mode；省略 mode 不触发清空，不能仅凭最终产物是 function 形式判断 scopeId 已被移除。

parserOptions 仍来自 DOM 平台

服务端也必须按浏览器的 HTML/SVG/MathML 规则建树，否则生成 HTML 被浏览器重新解析后的 DOM 形状会与客户端 AST 不同，hydration 必然失配。

共享表达式和作用域，替换输出转换

v-for/v-slot 局部变量追踪与 _ctx. 前缀仍复用 core； element/component/model/show 则改为 SSR 专用实现，因为目标是 HTML 片段而非可 patch VNode。

v-on 仍要经过通用 props 构造

原生 DOM 事件在服务端不会注册，但组件的 onXxx 可能是 emits listener，必须作为 props 传给子组件。后续元素/组件转换再分别取舍。

rawOptionsMap 服务插槽 fallback

SSR slot 有时被普通 render function 消费，没有 _push，必须返回 VNode。WeakMap 保存原编译选项，方便对该 slot 子树重建一条 core+DOM 客户端转换管线。

复用的边界：HTML/SVG/MathML parser、v-bind/v-on props 构造、表达式前缀和作用域追踪可以共享；VNode patch 优化、DOM 事件和客户端 block tree 不能照搬。

02 / Architecture

为什么 SSR 需要两遍转换

第一遍收集完整模板语义和 SSR 元数据；第二遍才把树变成线性 JS 控制流与字符串输出。

compiler-ssr compile()

baseParseDOM parserOptions
→
第一遍 transformif/for/scope/element/component
→
ssrCodegenTransform模板 AST → SSR JS AST
→
generate打印 ssrRender

第一遍不会设置最终根 codegenNode

core transform 完成结构归一、作用域和 SSR 元数据；第二遍新建 BlockStatement 并一次替换 root.codegenNode。因此 core generate 只需新增打印这些 JS 语句节点的能力。

CSS vars 每次 SSR 只求值一次

先建立 const _cssVars = { style: ... }，各个可注入根和条件分支都复用。 这既减少重复响应式读取，也防止同次 render 中不同分支读到不一致值。

多根只在真正需要时加 Fragment

多个纯文本 child 可以直接合并成字符串，没有节点范围歧义。 只有多根且含非文本节点时，才需要 <!--[-->/<!--]--> 边界。

SSR helper 与 Vue helper 分开导入

ssrInterpolate/ssrRenderAttrs 来自 @vue/server-renderer， resolveComponent/mergeProps 等仍来自 Vue。转换后按 helper symbol 分流，代码生成器才能打印两个正确序言。

第一遍：分析与登记

  • 结构指令建立 IfNode/ForNode。
  • 表达式添加显式上下文前缀。
  • 元素转换准备开标签与 props 元数据。
  • 组件转换准备 props、slots 与 fallback。
  • attrs/CSS vars 找到目标根；scopeId 登记到元素与 slot 输出。

第二遍：形成输出程序

  • 连续文本合并成 TemplateLiteral。
  • 元素调用 ssrProcessElement。
  • If/For 变成 JS IfStatement / renderList。
  • 内置组件生成专用 SSR helper。
  • 最终替换 RootNode.codegenNode。
分成两遍的价值：如果第一遍边遍历边输出，父元素还不知道后代 slot/fragment 情况，attrs 注入和 hydration 边界也难统一；若完全另写 parser/作用域，又会复制 core 的复杂语义。

03 / Output Buffer

连续字符串尽量一次 _push

SSRTransformContext 维护 body 和当前 string buffer。静态文本、标签片段与动态表达式可共同组成 TemplateLiteral。

可合并片段

<div class="box">hello {{ name }}</div>

_push(`<div class="box">hello ${
  ssrInterpolate(_ctx.name)
}</div>`)

示意：静态片段与已安全处理的动态表达式进入同一模板字面量。

必须断开缓冲

  • if/for 等 JS statement。
  • 组件 render 调用。
  • Teleport/Suspense 的独立内容函数。
  • slot fallback 函数。
  • 需要单独控制 _push 的分支。

第一个字符串片段才创建 _push

普通空分支无需建立字符串缓冲；只含组件调用的子树使用独立 _push(_ssrRenderComponent(...))。#5352 的 slot 根路径会刻意推入空字符串，供运行时判定插槽内容，HTML 本身不增加节点。

相邻静态字符串原地合并

开标签、静态文本、关标签可来自三个 transform 调用，但最终只占一个 TemplateLiteral 字符串元素。动态表达式只作为中间的 expression 插槽。

控制流不能嵌入字符串

IfStatement 直接追加控制流；组件则追加独立的 _push(_ssrRenderComponent(...))。ssrRenderComponent 返回子组件的 SSRBuffer，异步组件还可能返回 Promise，不能将结果放入字符串插值。_push 保留子缓冲和输出顺序，最终展开阶段再得到 HTML。pushStatement 清空 currentString，下一个字符串片段重新建立 _push。

子上下文共享 helper，不共享 body

v-if 分支和 slot 函数需自己的 BlockStatement，但里面用到的 SSR helpers 必须在根统一导入。createChildContext 因此重建 buffer/body，却传入同一个 helpers Set。

pushStringPart() 向当前 buffer 追加字符串或表达式；pushStatement() 在写控制流前先结算 buffer。各 transform 因而不必自行处理字符串拼接边界。

为什么无参 v-bind 必须整体合并

<div id="a" v-bind="obj"> 中 obj.id 按源码顺序应覆盖静态 id。如果开标签已提前写出 id="a"，后面再追加会产生重复属性。回退 mergeProps 才能保留覆盖规则。

自定义指令也可以贡献 props

指令的 getSSRProps 可返回 class/style/textContent 等任意属性。这些值与用户显式 props 的优先级只能在合并对象后统一确定。

属性名与属性值是两道安全门

SSR_RENDER_ATTR 负责转义值；在调用它之前，isSSRSafeAttrName 先防止名称携带空格、引号或 > 突破开标签结构。只做值转义不能防动态键注入。

Boolean 属性不能输出 false

disabled="false" 在 HTML 中仍表示 disabled 存在。因此它们使用 ssrIncludeBooleanAttr：值为 truthy 或空字符串 '' 时输出空格加属性名，其余值不输出。空字符串用于表达 <input disabled> 这类只声明属性存在的写法。

属性类型 输出策略 安全/正确性原因
静态普通属性 编译期转义后直接拼入字符串 零运行时 helper，且固定输出。
动态普通属性 ssrRenderAttr / ssrRenderDynamicAttr 值转义，动态名称还要校验安全。
Boolean 属性 includeBooleanAttr 决定是否输出名称 不能简单输出 true/false 字符串。
class / style ssrRenderClass / ssrRenderStyle 支持数组、对象和规范化语义。
无参数 v-bind mergeProps + ssrRenderAttrs 可能覆盖静态属性，必须保留合并顺序。
自定义指令 ssrGetDirectiveProps 后合并 指令可能贡献任意 SSR props。
动态属性名是安全边界：SSR 直接生成 HTML，恶意名称可能突破标签结构。编译器/运行时必须拒绝不安全名称；这与客户端 setAttribute 的风险模型不同。

v-html

表达式被视为已准备的 HTML 并覆盖 children；调用者承担内容可信责任。

v-text

用 ssrInterpolate 输出转义文本，避免字符被解释成标签。

textarea / pre

初始换行与文本解析特殊，输出必须匹配 hydration 后的 DOM。

对 input/textarea 之外的原生元素，若运行时自定义指令的 getSSRProps 返回 textContent/innerHTML，编译器仅在元素没有模板 children 且未声明 v-text/v-html 时采用它们；textContent 优先并经过转义，否则输出 innerHTML。元素已有模板 children 时仍输出这些 children。普通 :innerHTML/:textContent 绑定不会在这条 SSR 模板编译路径中自动变成内容覆盖，应使用 v-html/v-text 表达该意图。

05 / Components

组件与 slot 有两条输出路径

SSR slot 直接向 _push 写 HTML；某些调用场景没有 _push，需要回退为普通 VNode slot。

上方将原函数的两个相隔阶段并列展示：第一遍保存 WIPSlotEntry，第二遍在 ssrProcessComponent() 中补 body。

为什么 slot 第一遍不能完成

buildSlots 必须在 core context 还持有 v-for/v-slot 作用域时识别插槽； 但 SSR body 需要第二遍的字符串缓冲与控制流上下文。WIP 结构是两遍之间的桥。

_push 是调用协议的判别位

server-renderer 调 slot 时传入 _push，函数直接输出 HTML； 普通 render function 调 slot 时不传该参数，就走 alternate 并返回 VNode 数组。

VNode fallback 不能复用 SSR 已改写子树

第一遍会 clone slot children，再用 core+DOM transforms 建立 fallback。否则 SSR 元素转换已在原树上挂载专用元数据，同一节点再经客户端转换会互相污染。

WeakMap 不延长 AST 生命周期

中间信息以 ComponentNode 为 key。一次编译完成后若 AST 不再被引用，wip 条目也可被回收，不会因模块级表而累积每个 SFC 的插槽树。

<slot> 出口调用提供方的函数

ssrTransformSlotOutlet 第一遍准备 slots、名称、props、fallback、_push 和 _parent 参数。fallback 先放 null，第二遍有 children 时再填入独立的 SSR 函数。运行时 ssrRenderSlot 在外围输出 Fragment 锚点，内部按名称取出 slot 函数并传入 _push；这里的 fallback 是出口自身的默认内容，与提供方函数中无 _push 时返回 VNode 的分支不同。

_scopeId 从消费方传回提供方

假设父组件 A 提供 <span>Hello</span> 给子组件 B，A 的普通 scopeId 是 data-v-a，最终元素输出会带上这个属性。B 的 <slot> 若启用 slotted 样式，还会向 helper 传入 data-v-b-s。helper 调用 A 的 slot 函数时给它补前导空格，作为 _scopeId 参数；A 的元素输出再追加这项属性，最终 span 同时带 data-v-a 和 data-v-b-s。前者匹配 A 的 scoped 样式，后者匹配 B 的 :slotted() 样式。

转发 <slot> 时，出口把当前 scopeId-s 与外层 _scopeId 合并传下去；slot 内的组件则把 _scopeId 传给组件 helper，由 server-renderer 合入其根 attrs。指定 slotted: false 时，出口不生成自身的 scopeId-s。

Transition 中的出口省去外围 Fragment

Transition/TransitionGroup 只含一个元素类型的 slot 子节点时，编译器改用 ssrRenderSlotInner，并传入 transition: true。slot 带 v-if 时还会检查 IfBranch 的祖父组件。Inner 自身不添加普通出口的外围 Fragment；运行时还会去除 slot 内容已有的一对最外层 Fragment 锚点，空内容保留一个空注释，以匹配客户端展平后的节点。

#5352 的具体场景：当 slot 根是透明 Transition，且内部 v-if 当前为 false 时，slot 的有效输出可能只剩 hydration 注释。ssrRenderSlot 曾将这判为“空 slot”而误走 fallback。当前实现先 _push(``)，helper 的 bufferedPush 将每次调用原样收进 slotBuffer，因此内容成为 ['', '<!---->']。isComment('') 返回 false，整份 slot 就不会被判为全注释而改走 fallback。空字符串不产生 DOM；外围 Fragment 锚点仍由 ssrRenderSlot 输出。

06 / Control Flow

v-if 与 v-for 生成真实 JS 控制流

客户端生成条件 VNode/Fragment；SSR 直接生成 if statement 与 ssrRenderList 回调。

v-if

if (_ctx.ok) {
  _push(`<div>yes</div>`)
} else {
  _push(`<!---->`)
}

无 else 的空注释是 hydration 占位；特殊父上下文可禁用。

v-for

_push(`<!--[-->`)
_ssrRenderList(_ctx.items, (item, key, index) => {
  _push(`<li>...</li>`)
})
_push(`<!--]-->`)

整个列表默认都有 Fragment 边界，即使每项只有一个元素；单项含多个节点或唯一节点不是元素时，单项自身也有边界。

else-if 是 alternate 中的 IfStatement

AST 中 branches 是扁平数组，生成 JS 时重建为 if ... else if ... else 链。currentIf 始终指向链尾，后续分支才能接到正确 alternate。

没有 else 也要占一个节点

客户端条件 block 在 false 时使用注释 VNode 保留位置。SSR 输出空注释，hydration 游标才会与客户端对“该分支位置存在一个占位节点”的预期一致。

v-for 边界标记的是整个列表

项数只在运行时知道，父 children 不能靠数量推断列表结束位置。 成对 fragment comments 让 hydration 和后续节点移动都能精确定位列表范围。

嵌套边界可被关闭

Transition/TransitionGroup 的客户端运行时会展平直接 children 中的 Fragment，SSR 因而在对应输出路径传入 disableNestedFragments，抑制这些列表或分支的额外边界。普通嵌套列表仍各自保留 Fragment，不能只因祖先已有边界就关闭。另外，v-if 分支唯一 child 为 ForNode 时，processIfBranch 直接复用 v-for 的边界，不再额外包一层。

注释不是装饰：Fragment 锚点与空注释承担节点边界协议。删错、重复或在 TransitionGroup 中错误保留，都会让 hydration 游标错位。
07 / Injection

找出可透传的根

fallthrough attrs、CSS vars 和 scopeId 都会增加属性，但目标规则不同：_attrs 只透传到单根，_cssVars 可覆盖多个合格根，scopeId 则标记组件拥有的元素。

注入内容 目标 不能注入的场景
_attrs 单根原生元素或组件；模板有效根为一条 v-if 链时，分别注入其中的单根分支 条件链之外另有有效根、当前分支多根、文本根、无可透传根；根 v-for 也不注入。
_cssVars 每个合格根元素/组件；多根与各个 v-if 分支也会分别注入 文本/注释与根 v-for；循环单项不会补注入。Suspense 改为注入 slot children。
scopeId 当前组件拥有的元素；组件/slot 通过各自 scope 通道传播 不能当作 fallthrough attrs 只找单根，也不能泄漏到他人后代。
slotted scopeId 消费组件的 scopeId-s，通过 _scopeId 写入父组件提供的 slot 元素 slotted: false 时不生成自身的 scopeId-s；转发出口仍传递外层 _scopeId。
为什么在第一遍注入：_attrs/_cssVars 需要观察根结构和分支，并修改元素/组件 props 元数据；scopeId 则由元素、组件和 slot 转换分别携带。变成线性 _push 后再判断归属会困难很多。
08 / Built-ins

内置组件改变输出拓扑

它们不是普通组件调用：服务端有专用 transform/输出路径，hydration 与缓冲边界也各不相同。

Teleport

children 进入独立内容函数和目标缓冲；to 必填，disabled 决定当前位置/目标输出。

Suspense

default/fallback slots 各自编译为函数；当前 ssrRenderSuspense 只调用 default，没有 default 时输出空注释，不执行 fallback。default 中异步组件的结果进入 SSR buffer，由最终展开阶段等待。

Transition

通常直接输出过滤注释后的 children。声明 appear 或 :appear 时额外输出 template 包装；客户端取出其内容，根据运行时 appear 值执行相应过渡，再替换外层 template。编译器只检查属性是否存在，:appear="false" 也会生成包装。

TransitionGroup

无 tag 时以自身的一对 Fragment 锚点包围展平的 children，有 tag 时输出外层元素。运行时会过滤注释，SSR 同步禁用对应子列表/分支的边界、普通注释和缺省 v-if 空注释。

“专用”不代表四者都调用同一种 helper：Teleport/Suspense 形成专用调用，Transition 根据 appear 属性决定直接输出或 template 包装， TransitionGroup 根据 tag 选择元素或 Fragment 拓扑。共同点是都不能落入普通 ssrRenderComponent 路径。

Transition 的单 child 和 HTML 嵌套校验由客户端 compiler-dom 的开发期转换执行。compiler-ssr 默认管线没有安装这两项校验；只有普通组件 slot 的 VNode fallback 子转换会复用 DOMNodeTransforms。单独完成 SSR 编译，不能据此认为这些结构已经通过 DOM 校验。

09 / Hydration

HTML 必须匹配客户端节点模型

SSR 正确不仅是字符串合法，还意味着客户端 renderer 能按同样的节点边界接管。

  1. 1
    DOM 树形一致。非法 nesting 会被浏览器重排，造成与客户端 VNode 树不同的结构。客户端 compiler-dom 的开发期校验可提示这类问题，SSR 默认编译管线不执行该校验。
  2. 2
    Fragment 边界一致。多根、列表、条件分支和 slot 使用约定注释标记。
  3. 3
    文本转义一致。插值、属性、textarea 与注释遵循各自 HTML 上下文。
  4. 4
    scope/attrs 归属一致。服务端注入位置与客户端 VNode 相同。
  5. 5
    内置组件拓扑一致。Teleport、Suspense、TransitionGroup 不能多出或少掉边界。

成对注释标记一个可含多个 DOM 节点的 Fragment 范围；空注释让条件分支 即使未命中也占据一个可对齐位置。这里证明的是 SSR 输出协议；浏览器修正 HTML 后的实际 DOM 遍历、节点复用和 mismatch 警告仍由 runtime-core hydration 实现。

排查 hydration issue：比较浏览器实际解析后的 DOM 与客户端 VNode 预期，而非只比较服务器 HTML。浏览器纠正 HTML、注释过滤和 Fragment 错位都是高频根因。
