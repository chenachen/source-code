Module 03 · Single File Component Orchestrator

compiler-sfc

SFC 编译器把一个 .vue 文件变成可由构建工具组装的脚本、渲染函数和样式。它既是协调器，也是 TypeScript 静态分析器、编译宏实现和多层 source map 管理者。

输入：完整 .vue工具：Babel AST + MagicString + PostCSS输出：script/template/style 三分支
这是完整的 SFC 编译故事

从 .vue 切 block，到宏消除、props 解构、TS 类型推导、模板目标选择与 PostCSS 管线，每一段都给出当前版本源码和实际产物。不需要先理解 Babel 或 MagicString 内部实现。

01 / Parse

SFCDescriptor 是第一层协议

parse() 不编译 JavaScript 或 CSS；它只切分顶层 block，记录属性、位置、映射与构建元数据。

parse(source, options)

缓存键source + 影响解析的 options
→
compiler.parseparseMode: sfc
→
遍历根级 blockstemplate/script/style/custom
→
descriptor + errors尽量恢复，不首错中断

缓存键包含 compiler.parse

相同源码使用不同自定义 parser 时可产生不同 AST。若只用 source 作 key，第二次编译就会错用第一个工具链的 descriptor。

SFC mode 保护 script/style 原文

根级非 template block 的内容按原始文本读取，所以 JS 中的 < 和 CSS 中的大括号不会被模板 parser 误解成标签语法。

模板 AST 可以复用

无 src 且使用默认模板语法时，parse 把 template children 包成独立 RootNode。compileTemplate 后面可直接传 AST，省掉一次 tokenizer 扫描。

errors 是数组，不是异常终点

IDE 编辑中的 SFC 常处于暂时未闭合状态。可恢复的结构错误被收集， descriptor 仍尽量构造，这样语法高亮和其他 block 的诊断不会全部失效。

一份 SFC 的第一次降维 
App.vue
├─ descriptor.template      content + attrs + loc + cached AST
├─ descriptor.scriptSetup   content + lang + loc
├─ descriptor.styles[0]     scoped/module + content + loc
├─ descriptor.cssVars       ["theme.color"]
└─ descriptor.customBlocks  交给 Vite/vue-loader 插件处理

SFCDescriptor 保存什么

  • filename 与完整 source。
  • template、script、scriptSetup。
  • styles[]、customBlocks[]。
  • cssVars、slotted。
  • HMR shouldForceReload 回调。

每个 SFCBlock 保存什么

  • block content、lang、src、attrs。
  • 在完整文件中的 location。
  • block → SFC source map。
  • template 可缓存 AST。
  • style 的 scoped/module 等标志。
为什么 parse 返回 errors 而不直接 throw：重复 block、非法 src/setup 组合与暂时语法错误可能同时存在。IDE 需要尽量得到 descriptor，并一次显示多个诊断。
block 解析阶段规则 后续处理者
template 最多一个；无 src 时缓存 children AST compileTemplate
script 区分普通与 setup；语言必须兼容 compileScript / normalScript
style 允许多个；记录 scoped/module/lang compileStyle
custom block 保留 tag、attrs、content 上层构建插件

02 / Script

compileScript：完整文件上的受控改写

它需要整个 descriptor，因为脚本生成会读取 template import 使用情况、CSS vars、scoped 状态与宏类型。

ScriptCompileContext

集中保存 Babel AST、MagicString、宏状态、imports、bindings、parser plugins、错误定位与类型解析上下文。

Babel AST

负责“理解”JS/TS 语法：导入、声明、类型、函数作用域、宏调用和顶层 await。

MagicString

负责“修改”完整 SFC：move、remove、overwrite、prepend，并保留源位置以生成 map。

主流程九个阅读步骤

这里把职责拆成九步，方便逐项理解；它们不是源码中的九个独立循环。 下方真实源码再归并为五个可下断点的观察点，两套编号会明确对应。

01 · 收集 imports

普通 script 与 setup 分开登记；去重、冲突检查，并标记 type import 与模板使用情况。

02 · 处理两个脚本

提取普通 script 默认导出；遍历 setup 顶层声明并记录 Vue API 的用户别名。

03 · 识别与改写宏

defineProps、defineEmits、defineExpose、defineOptions、defineSlots、defineModel、withDefaults。

04 · 转换 props 解构

读取改为 __props，默认值进入运行时 props，rest 创建 proxy，同时维护所有嵌套作用域。

05 · 检查提升边界

宏 options 位于 setup 外，不能捕获尚未初始化的 setup 局部值；字面量常量除外。

06 · 裁剪非脚本 block

MagicString 一直使用完整 SFC 坐标，完成分析后才删除 template/style/custom blocks。

07 · 汇总 binding metadata

合并普通 script、setup、imports、props/model，并按读写语义细分绑定类型。

08 · 注入桥接代码

CSS vars、顶层 await async context、setup 参数、__props/__emit/rest proxy。

09 · 组装返回与默认导出

非 inline 返回模板绑定；inline 直接嵌入 render；最后合并 props/emits/name 等组件选项。

九步 → 五个源码观察点：A=01 imports；B=02/03/05 两份 AST 的顶层遍历、宏处理与提升检查；C=04 props 解构重写；D=06/07 删除非脚本区间并汇总 bindings；E=08/09 注入 setup 桥接并生成返回/默认导出。

宏名列表只用于编译期

从 vue 导入 defineProps 会被警告并删除 import，因为产物中不需要这个函数。 宏返回的只是一个编译期位置，会被 __props/__emit/useModel 等真实运行时协议替换。

理解用 AST，改代码用 MagicString

Babel 告诉编译器这是 import、TS assertion 还是被局部变量遮蔽的名字； MagicString 只在已知 start/end 处 move/remove/overwrite，从而保留原始坐标用于 source map。

分析一直使用完整 SFC 坐标

template/style 不会一开始就被截掉。所有 Babel block 坐标加上 startOffset 对齐完整文件，完成交叉分析后才统一删除非脚本 block。

bindingMetadata 是主要产物之一

它不是 IDE 附加信息，而是会直接传入 compiler-core 的模板表达式转换。一个名字是 ref、prop、let 还是 literal const，决定最终打印 .value、unref()、__props.x 还是直接常量。

最小 script setup 编译前后 
<script setup lang="ts">
import { ref } from 'vue'
const props = defineProps<{ title: string }>()
const count = ref(0)
</script>

↓ 核心产物

import { defineComponent as _defineComponent, ref } from 'vue'
export default _defineComponent({
  props: { title: { type: String, required: true } },
  setup(__props) {
    const props = __props
    const count = ref(0)
    return { props, count }
  }
})
为什么不能把 compileScript 看成文本替换：宏可以被 TS assertion 包裹，变量可能在嵌套函数中遮蔽，var 会提升，import 有类型/值双重身份。所有这些都要求真实 AST 与作用域模型。

03 / Macros

编译宏不是运行时函数

这些名字无需从 Vue 导入；compiler-sfc 在顶层识别并擦除/替换调用，把声明转换为组件 options 与 setup 上下文协议。

宏 编译期输入 输出/改写 关键限制
defineProps 运行时对象/数组或 TS 类型 __props 参数、runtime props、binding metadata 类型式与运行时式不能混用；只能调用一次。
withDefaults 类型式 defineProps + defaults mergeDefaults / 解构默认值信息 仅能包裹类型式 props。
defineEmits 事件数组/对象或类型签名 runtime emits 与 __emit 提取调用签名/具名 tuple；禁止重复或混用。
defineModel 名称、类型与 options prop + update event + useModel() 模型名冲突、默认值、修饰符与 getter/setter 类型。
defineExpose 暴露对象 替换为 setup context 的 expose 只能一次；未调用时生成 expose() 保持默认封闭。
defineOptions 静态组件 options 提升并合并默认导出 不能引用 setup 局部，也不能重复声明 props/emits 等专用项。
defineSlots 仅类型参数 useSlots() 或类型信息 不接受运行时参数。

识别失败时继续尝试 withDefaults

AST 顶层可能是 withDefaults(...) 而不是 defineProps CallExpression。包装宏再递归要求第一个参数必须是 defineProps，避免把普通函数误当宏。

运行时声明和类型声明互斥

defineProps<T>({ foo: String }) 同时给出两份完整事实，它们可能对 required/default/type 产生冲突，所以编译器不尝试“智能合并”。

运行时 key 立即成为 PROPS 绑定

数组或对象里可静态读取的键当场写入 bindingMetadata， 模板编译就知道这些名字应读取 props，而不是未知的公开实例属性。

解构只先记录，后统一改写

此处不立即遍历后续代码，只保存 public key、local alias 和 default。等全部顶层声明被了解后，transformDestructuredProps 才能用完整作用域信息安全重写。

类型式 defineProps

const props = defineProps<{
  title: string
  count?: number
}>()

// 生成概念：
// props: { title: { type: String, required: true },
//          count: { type: Number, required: false } }

defineModel

const title = defineModel<string>('title')

// 生成概念：
// prop: title
// emit: update:title
// const title = useModel(__props, 'title')
宏参数为什么不能捕获 setup 局部变量：runtime props/emits/options 会被提升到模块或组件 options 初始化阶段，而 setup 局部值此时尚不存在。编译器遍历宏参数中的 Identifier，提前报告这类时间顺序错误。

04 / Props Destructure

响应式解构是一场标识符重写

普通 JavaScript 解构会把 prop 复制成局部值。Vue 通过编译期把后续读取改回 __props，使简洁语法保持响应性。

用户源码

const { foo: localFoo = 1, bar, ...rest }
  = defineProps<Props>()

watchEffect(() => {
  console.log(localFoo, bar, rest.baz)
})

概念改写

const __props = ...
const rest = createPropsRestProxy(__props, ['foo', 'bar'])

watchEffect(() => {
  console.log(__props.foo, __props.bar, rest.baz)
})

为什么读取改成 __props

JavaScript const { foo } = obj 只在声明时取一次值；组件更新 props 时局部 foo 不会变。所有读取回到 __props.foo，才会每次取当前值。

对象简写要保留 key

把 { foo } 整个替换成 { __props.foo } 是非法 JS， 也丢失了对象键名。正确结果是 { foo: __props.foo }，因此需要根据父节点语义展开 shorthand。

赋值在编译期失败

如果把 foo++ 默默改成 __props.foo++，就绕过了 props 单向数据流。编译器用原始 id 位置直接报只读错误，比运行时警告更精确。

watch 需要 getter，不是当前值

表达式重写只能把 watch(foo) 变成 watch(__props.foo)， 但这仍是一次取值。因此编译器单独识别 watch/toRef 并要求 watch(() => foo)，让响应式系统能在 getter 内跟踪依赖。

真正困难的是作用域边界

语法 期望 原因
函数参数同名 函数内使用局部参数 参数遮蔽顶层解构 prop。
catch (foo) catch body 使用局部错误变量 catch 建立独立作用域。
for (const foo of list) 循环内局部，循环后恢复 prop 进入/离开循环要成对登记。
对象 shorthand key 保留 foo，value 改 __props.foo 同一 Identifier 同时承担两个语义。
对解构 prop 赋值 编译错误 prop 只读，不能把重写变成隐式 mutation。
默认值是函数 按 runtime type 决定是否工厂调用 函数值 prop 与对象默认值工厂语义冲突。
var 提升也必须考虑：即使 var 声明写在后面，它在函数作用域内仍遮蔽 prop。相关 issue 修复说明这里执行的是接近 JavaScript 绑定语义的静态分析，而非简单按源码顺序替换。

05 / Type Resolution

从 TypeScript 类型推导运行时声明

defineProps/defineEmits 的类型在运行时不存在。compiler-sfc 必须展开足够多的 TypeScript 语义，生成可用但保守的 runtime props/emits。

resolveTypeElements / inferRuntimeType

宏类型节点interface / alias / literal
→
TypeScope本地声明 + imports + owner scope
→
展开类型元素泛型 / union / intersection / mapped
→
runtime typeString / Number / Boolean / Object...

这里保留缓存、作用域选择、主要节点分派和泛型实参映射；省略位置均以 “……”标明。它们是从同一函数中整段裁掉的分支，不是把源码改写成伪代码。

这不是 TypeScript checker

算法只实现生成 props/emits 所需的 AST 可见类型展开，不执行完整类型检查、 控制流程缩窄或任意条件类型求值。这使 compiler-sfc 不必携带整个 TS 编译器。

ownerScope 决定名字从哪里查

展开外部 BaseProps 后，其成员类型里的别名与 import 应在 BaseProps 所在文件解析，而不是在当前 .vue 文件。每个属性因此保留 _ownerScope。

带泛型实参时不可直接缓存

Box<string> 和 Box<number> 共用同一个 Box 声明 AST，结果却不同。只有不依赖 typeParameters 的展开才能挂到 node 上复用。

读取缓存仍要重放 deps

第二次编译可以复用类型结果，但当前 SFC 仍必须记录它依赖了哪些外部 .ts 文件，否则这些文件变化时构建工具不会重编译该 SFC。

类型信息如何变成运行时选项 
interface Props extends Base {
  title: string
  count?: number
}

↓ resolveTypeElements + inferRuntimeType

props: {
  ...Base 中可解析的字段,
  title: { type: String, required: true },
  count: { type: Number, required: false }
}

文件与作用域

TypeScope 记录 filename、source、AST、types、declares、imports、deps、resolvedImportSources 与全局标志。

跨文件解析

通过 fs 接口读取相对导入、tsconfig paths、三斜线 references、namespace 与 global types。

缓存与失效

文件 scope、模块解析和 tsconfig 结果会缓存；依赖路径返回给构建工具，用于 HMR/监听。

支持维度 示例 处理策略
接口/别名 interface Props extends Base 递归合并 type elements。
泛型 Box<string> 建立临时 child scope，把类型参数映射到实参。
联合/交叉 A | B、A & B 合并属性与更宽 runtime 类型，保守处理未知分支。
映射/索引访问 Pick、Omit、T[K] 解析静态 key 集合并回到源属性。
工具类型 Partial、Required、Readonly、Record 内建识别并改变 required/key 语义。
跨文件类型 import type { Props } 模块解析 + scope 缓存 + deps 记录。
推导是保守近似：编译器不等同于完整 TypeScript checker。无法可靠求值的类型会退化为 null/unknown 运行时类型，而不是猜测；生产模式还会在不影响 Boolean/Function 语义时压缩声明。

06 / Binding Metadata

script 与 template 的桥梁

binding metadata 让模板编译器知道每个名字来自哪里、是否可能是 ref、读取与赋值该采用哪条路径。

绑定类型 典型来源 模板读取策略
PROPS defineProps 字段 __props / $props 访问，不允许直接赋值。
SETUP_REF ref()、computed() 读取/写入 .value。
SETUP_MAYBE_REF 普通 const 调用结果 读取 unref；赋值先 isRef 判断。
SETUP_LET let 绑定 兼容 ref 与普通值两种情况。
LITERAL_CONST 字面量 const 直接使用，可安全提升。
SETUP_CONST 函数、稳定对象、import 直接使用，不走实例代理。

自动接线只发生在 inlineTemplate 分支。构建工具分别调用 compileScript 与 compileTemplate 时，必须把前者返回的 bindings 放进后者的 compilerOptions.bindingMetadata；compiler-sfc 不会跨两次独立 API 调用隐式保存这份状态。

Import Usage Check

扫描模板标签、指令、表达式、动态参数、ref 与 v-model，判断 TS 值导入是否真的需要返回给模板。

Top-level Await

用 withAsyncContext 包裹 await，在挂起/恢复之间恢复 current instance，并保留赋值表达式值。

Inline Template

render 闭包直接捕获 setup 局部变量，不需要把所有绑定放进 setup 返回对象，可减少代理和暴露面。

模板扫描不是普通文本搜索：组件 PascalCase/kebab-case、动态参数、对象 key、局部 slot 参数、纯类型位置都可能造成误判。importUsageCheck 的测试集中覆盖这些边界。
07 / Template

compileTemplate：选择目标并串联映射

它处理预处理器、资产 URL、scoped/slotted 与 SSR 选项，然后调用 compiler-dom 或 compiler-ssr。

compileTemplate(options)

预处理pug 等；失败返回结构化错误
→
选择 AST复用或重新 parse
→
DOM / SSR compilemodule + prefix + hoist
→
合并 mapcode → block → SFC

DOM/SSR 只在一行分叉

SFC 自身不重写模板语义；ssr 只决定选 compiler-dom 还是 compiler-ssr。资产 URL、scope id、错误与 map 的组装在两个目标之间共享。

资产 URL 是模板转换，不是字符串替换

<img src="./logo.png"> 会转成 import 绑定，而外链、data URL、hash 和 :src 要保留。srcset 还含多个 URL/密度描述，必须基于已解析的属性节点处理。

选项展开顺序允许高层调整

SFC 先给出 module/prefix/hoist 等建议，再展开 compilerOptions。 但 nodeTransforms 最后被显式重建，确保资产转换不会被整个覆盖，用户插件仍可追加。

source map 是两段函数的复合

模板编译器给出“生成 code → template block”，parse 时给出“template block → 完整 .vue”。mapLines 把两层串起来，开发工具才能把 render 中的位置指回用户的模板行。

AST 复用条件

默认 compiler、无改变源码的预处理、parser options 兼容。自定义 compiler 或预处理后必须重新解析。

资产 URL

相对 src/href/srcset 变为去重 import；外链、data URL、hash 与动态绑定原样保留或按 base 处理。

编译选项

module、prefixIdentifiers、hoistStatic、cacheHandlers、scopeId、hmr 与用户 transforms 在此集中合并。

错误位置回补：如果传入的是 template block 字符串而非完整 SFC AST，编译错误 location 先相对 block；compileTemplate 会根据 inMap 把它平移回 .vue 文件。

08 / Style

compileStyle：一条 PostCSS 插件管线

预处理语言先把源码变成 CSS；随后内置插件与用户插件依次处理 CSS vars、trim、scoped 和 CSS Modules。

doCompileStyle(options)

PreprocessorSass / Less / Stylus
→
CSS v-bind表达式 → var(--id-name)
→
Scopedselector + data-v-id
→
CSS Modulesasync + class JSON
→
code / map / deps返回构建工具

预处理在 PostCSS 之前

Sass/Less/Stylus 先把自己的语法降成 CSS，后续 cssVars/scoped/modules 插件只需处理统一 CSS AST。预处理器 map 会作为 PostCSS map 的 prev 继续串联。

cssVars 插件必须最先安装

v-bind(theme.color) 先变成稳定的 CSS custom property，后续 scoped 选择器改写只处理选择器，CSS Modules 也不会误解其中的 JS 表达式。

CSS Modules 为什么强制异步

postcss-modules 可能加载外部文件并通过异步钩子返回类名映射。 同步 API 读取 LazyResult.css 时无法等待它，所以提前报错而不是产生不完整 modules。

dependencies 是 HMR 的输出

Sass @use 和 PostCSS dependency message 都被汇总。当其中一个外部文件变化时，Vite/vue-loader 依此重编译该 style block。输入文件自身被删除，避免一次修改触发两条监听路径。

scoped + CSS vars 产物 
输入：.card { color: v-bind(theme.color) }
scope：data-v-a1b2

CSS：.card[data-v-a1b2] { color: var(--a1b2-theme_color) }
Script：_useCssVars(_ctx => ({
  "a1b2-theme_color": _ctx.theme.color
}))

缓存键必须包含语义选项

parse cache、type scope、module resolution、tsconfig 与模板 AST 都有缓存。若忽略 compiler/parser/fs/tsconfig 等选项，就会出现跨编译污染。

shouldForceReload 的窄职责

它只处理一个特殊比较：script 已相同、仅 template 变化时，TS/TSX script setup 中原先未被模板使用的 import 是否变成已使用。其他 HMR 失效策略由构建工具判断。

依赖收集

style imports、type imports、global types、tsconfig references 都会反馈给构建器，决定哪些外部文件变化应重编译 SFC。

为什么 reactive const 仍可能需要重新赋值

reactive() 返回的对象本身可修改属性，但组件 v-model 的 update 事件语义是 name = $event，即替换整个绑定。const 不允许这种赋值。

修复跨越 script 和 template

单看 script 只能得到 SETUP_REACTIVE_CONST；compileScript 还会扫描已缓存的 template AST，发现 name 是 v-model 目标后，把声明从 const 改为 let，并把 bindingMetadata 同步降级为 SETUP_LET。

断言同时保护三层结果

content 保护生成 JS 可赋值，bindings 保护模板稍后采用可写路径，warning 则让用户知道源声明被编译器调整。只比较代码 snapshot 会漏掉后两个协议。

建议追踪一个宏的完整链条：processDefineProps → resolveTypeElements → genRuntimeProps → bindingMetadata → compileTemplate transformExpression → runtime props 校验。只看宏文件会漏掉一半语义。
