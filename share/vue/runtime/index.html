先抓住最常走的一条更新主线

状态变化后，Vue 要用尽可能少的工作，让浏览器页面与最新状态一致。

✎ 先算“应该长什么样” 组件读取最新数据，产生一份新的页面描述。 component + render
⇄ 再找“哪里不一样” 比较前后描述，保留能复用的部分，找出新增、删除和移动。 renderer + diff
✓ 最后修改真实页面 把必要操作翻译成浏览器 DOM、属性、事件和样式更新。 runtime-dom

调度系统决定这些工作什么时候做；Teleport、Suspense、KeepAlive 和 Transition 改变某些特殊时机；Hydration 则让 Vue 接管服务端已经生成的页面。组件生命周期、错误处理和卸载还要解决创建、 恢复与资源回收，它们会在各自章节单独展开。

Counter 贯穿主线；列表 Diff 单独换一个输入

Counter 足以讲清组件、调度、元素 patch 和 DOM 提交，却不会进入 keyed children 的最长递增子序列分支。到了 Diff 章，我们会明确改用带 key 的列表，不拿一个没走到该分支的例子硬讲算法。
