Chapter 03 · Renderer

Vue 怎样决定页面该改哪里

组件会交出新的页面描述，但它不修改浏览器。Renderer 接过新旧两份描述，判断哪些节点继续使用、哪些要创建、更新、移动或离开。

按执行顺序再走一遍

  1. Renderer 的输入不是 ref，而是同一组件两次 render 产生的新旧 VNode。
  2. patch 先做身份判断：对象相同可返回；type/key 不同必须卸载重挂；本例可复用。
  3. processElement 只决定 mount 还是 patch；更新时 patchElement 把旧 el 转给新 VNode。
  4. 本例是手写 h，走安全的完整 children/props 比较；文本变化直接调用 hostSetElementText。
  5. host 层执行真正写操作，因而同一 core 流程既能更新 TestElement，也能更新 DOM。
  6. 清理仍以 VNode 为入口，卸载逻辑资源后调用 hostRemove。

renderer.ts · patch（完整连续函数） 
  const patch: PatchFn = (
    n1,
    n2,
    container,
    anchor = null,
    parentComponent = null,
    parentSuspense = null,
    namespace = undefined,
    slotScopeIds = null,
    optimized = __DEV__ && isHmrUpdating ? false : !!n2.dynamicChildren,
  ) => {
    if (n1 === n2) {
      return
    }

    // type 或 key 不同不能就地复用；先记录旧范围后的锚点，再完整卸载旧树并按挂载处理。
    if (n1 && !isSameVNodeType(n1, n2)) {
      anchor = getNextHostNode(n1)
      unmount(n1, parentComponent, parentSuspense, true)
      n1 = null
    }

    if (n2.patchFlag === PatchFlags.BAIL) {
      // BAIL 表示编译优化元数据不可信（常见于手写/异常插槽），清空 block 快路径。
      optimized = false
      n2.dynamicChildren = null
    }

    const { type, ref, shapeFlag } = n2
    switch (type) {
      case Text:
        processText(n1, n2, container, anchor)
        break
      case Comment:
        processCommentNode(n1, n2, container, anchor)
        break
      case Static:
        if (n1 == null) {
          mountStaticNode(n2, container, anchor, namespace)
        } else if (__DEV__) {
          patchStaticNode(n1, n2, container, namespace)
        }
        break
      case Fragment:
        processFragment(
          n1,
          n2,
          container,
          anchor,
          parentComponent,
          parentSuspense,
          namespace,
          slotScopeIds,
          optimized,
        )
        break
      default:
        if (shapeFlag & ShapeFlags.ELEMENT) {
          processElement(
            n1,
            n2,
            container,
            anchor,
            parentComponent,
            parentSuspense,
            namespace,
            slotScopeIds,
            optimized,
          )
        } else if (shapeFlag & ShapeFlags.COMPONENT) {
          processComponent(
            n1,
            n2,
            container,
            anchor,
            parentComponent,
            parentSuspense,
            namespace,
            slotScopeIds,
            optimized,
          )
        } else if (shapeFlag & ShapeFlags.TELEPORT) {
          ;(type as typeof TeleportImpl).process(
            n1 as TeleportVNode,
            n2 as TeleportVNode,
            container,
            anchor,
            parentComponent,
            parentSuspense,
            namespace,
            slotScopeIds,
            optimized,
            internals,
          )
        } else if (__FEATURE_SUSPENSE__ && shapeFlag & ShapeFlags.SUSPENSE) {
          ;(type as typeof SuspenseImpl).process(
            n1,
            n2,
            container,
            anchor,
            parentComponent,
            parentSuspense,
            namespace,
            slotScopeIds,
            optimized,
            internals,
          )
        } else if (__DEV__) {
          warn('Invalid VNode type:', type, `(${typeof type})`)
        }
    }

    // 宿主/组件处理完成后再更新 ref，此时 n2.el/component 已经可用。
    if (ref != null && parentComponent) {
      setRef(ref, n1 && n1.ref, parentSuspense, n2 || n1, !n2)
    } else if (ref == null && n1 && n1.ref != null) {
      setRef(n1.ref, null, parentSuspense, n1, true)
    }
  }

Renderer 就像拿着新旧图纸验收现场

它始终面对三个东西：上一次的页面描述、这一次的页面描述、当前真实页面。

＋创建新描述有、旧描述没有：创建节点并插入。mount
≈更新新旧是同一身份：复用节点，只修补变动部分。patch
−离开旧描述有、新描述没有：执行清理并移除。unmount

例如按钮文字从“保存”变成“已保存”：按钮类型和 key 没变，所以不重建按钮，只改文字。若 button 变成 a，节点类型不同，旧按钮就不能原位复用。

相同身份button → button

沿用原 DOM，更新文字、class 或事件。

不同身份button → a

卸载旧按钮，在正确位置创建链接。

为什么统一叫 patch

patch 的意思是“让旧状态变成新状态”。它先看节点是什么：文本就改文字，元素就改属性和 children，组件就更新组件，Teleport/Suspense 则交给各自协议。它不是只指 Diff，也不是浏览器 API。

Renderer 的输出不是新 VNode。新 VNode 是它的输入；它的输出是一组真实平台操作，以及与新 VNode 建好的节点或组件关联。
进入 Renderer 内部与源码层

baseCreateRenderer 为什么是巨型闭包

createRenderer 把 RendererOptions 交给 baseCreateRenderer。后者解构为 hostInsert、hostRemove、hostPatchProp 等局部变量，并在同一闭包中定义 patch、mountElement、processComponent、unmount、move 等函数。

这种组织方式带来三个收益：

  • 所有递归处理器共享同一套宿主实现，无需层层对象查找。
  • patch 与内置组件可以通过 RendererInternals 相互调用，但不暴露为公共 API。
  • 普通 renderer 与 hydration renderer 复用大部分逻辑，只额外注入 hydrateNode 等能力。

patch：先判断身份，再讨论差异

patch 先检查 n1 === n2，同一对象直接返回。否则核对 type / key：身份不同，先找到旧树之后的 anchor，卸载 n1，再把 n2 当首次挂载。随后独立检查 BAIL，再进入类型分派。

patch 参数看似很多，是因为递归调用不能依赖隐式全局状态：container 决定物理宿主，anchor 决定插入位置，parentComponent 决定上下文，parentSuspense 决定异步 effect 去向，namespace 决定 DOM 节点类型，optimized 决定能否信任编译器提示。

为什么倒序遍历

insertBefore 需要一个已经存在的 anchor。倒序处理时，当前节点右侧的新节点已经在正确位置，因此可以把它作为稳定 anchor；从左到右则无法保证“下一个新节点”已经提交。

为什么 LIS 能减少 DOM move

newIndexToOldIndexMap 记录新序列中的节点来自哪个旧索引。递增子序列代表这些节点在旧树中的相对顺序本来就正确；最长递增子序列就是可保持原位的最大集合。其余节点才需要移动。

优化模式：编译器替 Runtime 排除不可能

PATCH FLAGS

缩小单节点比较范围

TEXT、CLASS、STYLE、PROPS 等让 patchElement 跳过未变化类别。

DYNAMIC CHILDREN

缩小子树遍历范围

patchBlockChildren 只对齐编译器收集的动态节点，静态后代无需访问。

HOISTED

跳过稳定对象创建

静态 VNode 可提升到 render 外；复用前根据挂载状态克隆，避免共享 el。

BAIL

优化提示不可信时回退

复用已有 VNode、非稳定 slot、多 keyed Fragment 展平等情况使 block 元数据不再可信时，清空 dynamicChildren 并完整 Diff。

优化设计的重要特征是不改变语义。任何快路径都必须存在等价慢路径，这也是测试中会大量比较 optimized 与 non-optimized 行为的原因。

move 与 unmount：不是简单 removeChild

move 必须按 VNode 类型处理：组件移动其 subTree，Fragment 移动锚点范围，Static 移动连续节点，Teleport 决定只移动主视图占位还是远端 children，Suspense 移动 activeBranch。Transition 还会把 ENTER/LEAVE 变成异步流程。

unmount 同样先维护逻辑状态：清 ref、执行 VNode/指令钩子、停止组件 scope、处理 KeepAlive 缓存标志，再删除宿主节点。若只看最终 hostRemove，会错过绝大多数 Runtime 语义。

VNODE RANGE → CONTAINER / ANCHOR → RECURSIVE CLEANUP
Componentmove/unmount 递归到 instance.subTree；组件 VNode 自身没有另一份 DOM。
Fragment移动起点、各 child 与终点；卸载时先递归清理逻辑资源，再沿 nextSibling 删除宿主范围。
Teleport / Suspense委托协议自身处理多容器或 activeBranch，普通 renderer 不猜目标。
Element / StaticREORDER 用 hostInsert 复用节点；unmount 完成逻辑清理后才由 remove 处理宿主范围。
renderer.ts · move 按 VNode 范围分派（连续源码） 
  const move: MoveFn = (
    vnode,
    container,
    anchor,
    moveType,
    parentSuspense = null,
  ) => {
    const { el, type, transition, children, shapeFlag } = vnode
    if (shapeFlag & ShapeFlags.COMPONENT) {
      move(vnode.component!.subTree, container, anchor, moveType)
      return
    }

    if (__FEATURE_SUSPENSE__ && shapeFlag & ShapeFlags.SUSPENSE) {
      vnode.suspense!.move(container, anchor, moveType)
      return
    }

    if (shapeFlag & ShapeFlags.TELEPORT) {
      ;(type as typeof TeleportImpl).move(vnode, container, anchor, internals)
      return
    }

    if (type === Fragment) {
      hostInsert(el!, container, anchor)
      for (let i = 0; i < (children as VNode[]).length; i++) {
        move((children as VNode[])[i], container, anchor, moveType)

renderer.ts · remove 处理 Fragment/Static/Transition 的物理删除 
  const remove: RemoveFn = vnode => {
    const { type, el, anchor, transition } = vnode
    if (type === Fragment) {
      if (
        __DEV__ &&
        vnode.patchFlag > 0 &&
        vnode.patchFlag & PatchFlags.DEV_ROOT_FRAGMENT &&
        transition &&
        !transition.persisted
      ) {
        ;(vnode.children as VNode[]).forEach(child => {
          if (child.type === Comment) {
            hostRemove(child.el!)
          } else {
            remove(child)
          }
        })
      } else {
        removeFragment(el!, anchor!)
      }
      return
    }

    if (type === Static) {
      removeStaticNode(vnode)
      return
    }

    /** 物理删除完成后通知 afterLeave；persisted 过渡不由渲染器触发该阶段。 */
    const performRemove = () => {
      hostRemove(el!)
      if (transition && !transition.persisted && transition.afterLeave) {
        transition.afterLeave()
      }
    }

    if (
      vnode.shapeFlag & ShapeFlags.ELEMENT &&
      transition &&
      !transition.persisted
    ) {
      const { leave, delayLeave } = transition
      /** 把删除动作交给 leave；delayLeave 可持有此闭包以协调 in-out 的先后顺序。 */
      const performLeave = () => leave(el!, performRemove)
      if (delayLeave) {
        delayLeave(vnode.el!, performRemove, performLeave)
      } else {
        performLeave()
      }
    } else {
      performRemove()
    }
  }
