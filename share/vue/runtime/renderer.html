Chapter 03 · Renderer

Vue 怎样决定页面该改哪里

组件会交出新的页面描述，但它不修改浏览器。Renderer 接过新旧两份描述，判断哪些节点继续使用、哪些要创建、更新、移动或离开。

建议阅读 40 分钟核心文件 renderer.ts重点：patch / move / unmount

Renderer 就像拿着新旧图纸验收现场

它始终面对三个东西：上一次的页面描述、这一次的页面描述、当前真实页面。

＋创建新描述有、旧描述没有：创建节点并插入。mount
≈更新新旧是同一身份：复用节点，只修补变动部分。patch
−离开旧描述有、新描述没有：执行清理并移除。unmount

例如按钮文字从“保存”变成“已保存”：按钮类型和 key 没变，所以不重建按钮，只改文字。若 button 变成 a，节点类型不同，旧按钮就不能原位复用。

相同身份button → button

沿用原 DOM，更新文字、class 或事件。

不同身份button → a

卸载旧按钮，在正确位置创建链接。

为什么统一叫 patch

patch 的意思是“让旧状态变成新状态”。它先看节点是什么：文本就改文字，元素就改属性和 children，组件就更新组件，Teleport/Suspense 则交给各自协议。它不是只指 Diff，也不是浏览器 API。

Renderer 的输出不是新 VNode。新 VNode 是它的输入；它的输出是一组真实平台操作，以及与新 VNode 建好的节点或组件关联。
进入 Renderer 内部与源码层

baseCreateRenderer 为什么是巨型闭包

createRenderer 把 RendererOptions 交给 baseCreateRenderer。后者解构为 hostInsert、hostRemove、hostPatchProp 等局部变量，并在同一闭包中定义 patch、mountElement、processComponent、unmount、move 等函数。

这种组织方式带来三个收益：

  • 所有递归处理器共享同一套宿主实现，无需层层对象查找。
  • patch 与内置组件可以通过 RendererInternals 相互调用，但不暴露为公共 API。
  • 普通 renderer 与 hydration renderer 复用大部分逻辑，只额外注入 hydrateNode 等能力。

patch：先判断身份，再讨论差异

patch 的第一步是 isSameVNodeType(n1, n2)。type 或 key 不同，旧节点无法原位更新：先找到旧树之后的 anchor，卸载 n1，再把 n2 当首次挂载。类型相同才进入分派。

编译器生成的 KEYED_FRAGMENT 和 UNKEYED_FRAGMENT 能直接选算法；手写 render 缺少保证时，patchChildren 使用保守 keyed diff，它同时兼容有 key 和无 key 节点。

Keyed Diff 概览：Renderer 如何取得列表提交计划

同步头部
从左向右 patch 连续同类型同 key 节点，缩小未知区间。
同步尾部
从右向左跳过稳定尾部，同时天然获得尾端 anchor。
处理纯新增
旧区间先耗尽，按新节点下一个位置为 anchor 批量 mount。
处理纯删除
新区间先耗尽，剩余旧节点全部 unmount。
构造 keyToNewIndexMap
为未知新区间建立 key 到索引映射，并在开发期诊断重复 key。
扫描旧区间
定位每个旧节点的新位置；找不到就卸载，找到就 patch，并生成 newIndexToOldIndexMap。
判断是否移动
若匹配到的新索引不再单调递增，说明相对顺序变化，需要计算 LIS。
倒序提交
从右向左 mount 新节点；不在最长递增子序列中的复用节点才执行 move。

为什么倒序遍历

insertBefore 需要一个已经存在的 anchor。倒序处理时，当前节点右侧的新节点已经在正确位置，因此可以把它作为稳定 anchor；从左到右则无法保证“下一个新节点”已经提交。

为什么 LIS 能减少 DOM move

newIndexToOldIndexMap 记录新序列中的节点来自哪个旧索引。递增子序列代表这些节点在旧树中的相对顺序本来就正确；最长递增子序列就是可保持原位的最大集合。其余节点才需要移动。 

旧：a b c d e
新：a c b e d

同步头部后未知区间：
旧索引序列映射到新位置 ≈ [c→2, b→1, e→4, d→3]

Renderer 已知道最终顺序；LIS 只用于决定哪些节点可以不 move。

优化模式：编译器替 Runtime 排除不可能

PATCH FLAGS

缩小单节点比较范围

TEXT、CLASS、STYLE、PROPS 等让 patchElement 跳过未变化类别。

DYNAMIC CHILDREN

缩小子树遍历范围

patchBlockChildren 只对齐编译器收集的动态节点，静态后代无需访问。

HOISTED

跳过稳定对象创建

静态 VNode 可提升到 render 外；复用前根据挂载状态克隆，避免共享 el。

BAIL

证明失效时回退

手写 slot、错误边界或非同构 block 使优化前提不成立时，清空 dynamicChildren 并完整 Diff。

优化设计的重要特征是不改变语义。任何快路径都必须存在等价慢路径，这也是测试中会大量比较 optimized 与 non-optimized 行为的原因。

move 与 unmount：不是简单 removeChild

move 必须按 VNode 类型处理：组件移动其 subTree，Fragment 移动锚点范围，Static 移动连续节点，Teleport 决定只移动主视图占位还是远端 children，Suspense 移动 activeBranch。Transition 还会把 ENTER/LEAVE 变成异步流程。

unmount 同样先维护逻辑状态：清 ref、执行 VNode/指令钩子、停止组件 scope、处理 KeepAlive 缓存标志，再删除宿主节点。若只看最终 hostRemove，会错过绝大多数 Runtime 语义。

Renderer 的完整语义已经建立。下一章把最重要也最容易被一句“用了 LIS”带过的列表 Diff 单独拆开：从 key 身份、区间收缩、中段映射一直推演到倒序提交。
