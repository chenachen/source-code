Chapter 08 · Runtime DOM

Vue 的更新怎样真正落到浏览器

Renderer 已经决定“按钮的文字和 props 需要检查”。真正有变化时，runtime-dom 再处理浏览器的具体规则：该写 property 还是 attribute，事件怎样换回调，输入框怎样不丢光标；本页事件用例会专门把回调 A 更新为 B。

建议阅读 40 分钟先修：架构 / Renderer浏览器边界

为什么不能所有属性都用 setAttribute

HTML 看起来统一，浏览器对象的行为却不同。下面四种更新需要四套规则：

业务想做什么 浏览器层真正要考虑 负责模块
修改 class 普通 class 还要与 Transition 临时动画 class 合并 patchClass
修改 style 对象中消失的旧样式要清除，CSS 变量与 important 有特殊写法 patchStyle
更换点击回调 尽量复用已注册监听器，只替换它内部调用的新函数 patchEvent
更新输入框 不能打断拼音输入、移动光标或覆盖水合前用户已输入的内容 v-model / DOM prop
runtime-core 的语言

“把这个元素的 value 从 A 更新成 B。”它不假设目标一定是浏览器。

runtime-dom 的判断

元素是什么？用户是否正在输入？value 应写 property 还是 attribute？写入会不会触发副作用？

事件更新为什么不反复解绑

Vue 第一次添加 click 时注册一个稳定的“转接器”；回调从 A 变成 B，只更新转接器指向的函数。这样少做浏览器注册工作，也能统一处理错误、数组回调和事件传播中的时间问题。

runtime-dom 的价值：Renderer 保持通用和干净，所有浏览器兼容、交互连续性与安全写入规则集中在平台边界。

静态内容为什么单独有接口

编译器可把连续静态节点提升成 HTML 字符串。逐个 VNode 创建会浪费解析与对象成本，insertStaticContent 让浏览器一次解析整段；同时返回起止节点，保证这段没有单一根元素时仍能整体复制、移动和删除。

  insertStaticContent(content, parent, anchor, namespace, start, end) {
    // 插入前结构：<parent> before | first ... last | anchor </parent>。
    const before = anchor ? anchor.previousSibling : parent.lastChild
    // #5308：缓存 clone 仅在单根，或起点仍能沿 nextSibling 走到终点时安全。若缓存节点
    // 已脱离原父级且是多根，兄弟链信息丢失，只能重新解析静态字符串。
    if (start && (start === end || start.nextSibling)) {
      // 沿缓存范围逐个深克隆并插入，原缓存节点保持不动供下一次复用。
      while (true) {
        parent.insertBefore(start!.cloneNode(true), anchor)
        if (start === end || !(start = start!.nextSibling)) break
      }
    } else {
      // 首次/缓存失效：通过 template.innerHTML 解析。
      templateContainer.innerHTML = unsafeToTrustedHTML(
        namespace === 'svg'
          ? `<svg>${content}</svg>`
          : namespace === 'mathml'
            ? `<math>${content}</math>`
            : content,
      ) as string

      const template = templateContainer.content
      if (namespace === 'svg' || namespace === 'mathml') {
        // wrapper 只用于命名空间解析，把其 children 提升回 template Fragment。
        const wrapper = template.firstChild!
        while (wrapper.firstChild) {
          template.appendChild(wrapper.firstChild)
        }
        template.removeChild(wrapper)
      }
      parent.insertBefore(template, anchor)
    }
    return [
      // 插入后首节点。
      before ? before.nextSibling! : parent.firstChild!,
      // 插入后末节点。
      anchor ? anchor.previousSibling! : parent.lastChild!,
    ]
  },

patchProp 决策树：同一个 key，不一定是同一种操作

patchProp 收到的 key 还只是 VNode prop 名。它先识别专用模块，再决定普通 key 应写 property 还是 attribute。顺序很重要：例如 onUpdate:modelValue 看起来也是 onXxx，却必须留给 v-model，而不能注册成浏览器事件。

02isOn(key)model listener 跳过；其余 onXxx 进入 patchEvent。

05Vue Custom Element声明 prop 或异步定义的非字符串/大写 key，camelize 后写元素 property。

连续源码：patchProp 的完整分派函数 
export const patchProp: DOMRendererOptions['patchProp'] = (
  el,
  key,
  prevValue,
  nextValue,
  namespace,
  parentComponent,
) => {
  const isSVG = namespace === 'svg'
  if (key === 'class') {
    patchClass(el, nextValue, isSVG)
  } else if (key === 'style') {
    patchStyle(el, prevValue, nextValue)
  } else if (isOn(key)) {
    // `onUpdate:modelValue` 等由组件 v-model 消费，不注册成原生 DOM 事件。
    if (!isModelListener(key)) {
      patchEvent(el, key, prevValue, nextValue, parentComponent)
    }
  } else if (
    key[0] === '.'
      ? ((key = key.slice(1)), true)
      : key[0] === '^'
        ? ((key = key.slice(1)), false)
        : shouldSetAsProp(el, key, nextValue, isSVG)
  ) {
    patchDOMProp(el, key, nextValue, parentComponent)
    // #6007：value/checked/selected 写 property 后也同步 attribute，使表单 reset 能恢复
    // 初始状态，且依赖 attribute 的库/扩展可读取。#11163：自定义元素 value 可能是对象
    // prop，不能再写 attribute 造成字符串化，所以仅普通原生标签执行。
    if (
      !el.tagName.includes('-') &&
      (key === 'value' || key === 'checked' || key === 'selected')
    ) {
      patchAttr(el, key, nextValue, isSVG, parentComponent, key !== 'value')
    }
  } else if (
    // #11081：Vue 自定义元素即使组件定义异步未解析，也要把可能 prop 先写入元素对象。
    (el as VueElement)._isVueCE &&
    // #12408：已解析元素只对声明 prop 走 property；异步元素还接受大写键/非字符串值，
    // 等定义解析后再完成类型转换。
    (shouldSetAsPropForVueCE(el as VueElement, key) ||
      // `_def` 是 runtime-dom 内部字段，公开 VueElement 类型不暴露。
      // @ts-expect-error
      ((el as VueElement)._def.__asyncLoader &&
        (/[A-Z]/.test(key) || !isString(nextValue))))
  ) {
    patchDOMProp(el, camelize(key), nextValue, parentComponent, key)
  } else {
    // checkbox 的 true-value/false-value 允许对象等非字符串。attribute 会强制字符串化，
    // 额外存 `_trueValue/_falseValue` 供 vModelCheckbox 读取原始值。
    if (key === 'true-value') {
      ;(el as any)._trueValue = nextValue
    } else if (key === 'false-value') {
      ;(el as any)._falseValue = nextValue
    }
    patchAttr(el, key, nextValue, isSVG, parentComponent)
  }
}

为什么不能简单写成 el[key] = value

例子 为什么例外 策略
form input/button 等表单控件的 .form 是只读关联对象，不是可写的 form id 字符串 把传入的 form id 写为 attribute
input list property 只读或语义与 attribute 不一致 使用 attribute
textarea type DOM 上不存在有意义的可写 property 使用 attribute
小写 native onxxx 字符串 如 onclick="..." 的 attribute 表示内联源码；函数值才可写同名 property 按值类型分派
自定义元素 升级后的实例可能定义任意 property setter 存在 property 时优先 prop，显式修饰符可覆盖
spellcheck / draggable / translate / autocorrect 部分浏览器同名 property 会把字符串 "false" 错当真值 保留枚举 attribute 语义
iframe sandbox property 的 null/空串转换无法表达“移除限制” 始终增删 attribute
img/video/canvas/source width、height property 会数值转换，无法正确表达 attribute 增删 使用 attribute；自定义元素不套这条原生标签规则

property 分支：真正写值前还要做类型和表单修正

value 是最特殊的一条：DOM 只保留字符串，Vue 另存 _value 保存对象或数字原值；checkbox 没有 value 时，null 要恢复浏览器默认 "on"。普通原生元素的 value / checked / selected 写完 property 后还同步 attribute，以便表单 reset 找回初始状态。

其余 property 遇到 null/空串，会参考浏览器当前 property 类型转换：boolean 用布尔属性规则， string 先写空串，number 先写 0，必要时再移除 attribute。setter 只读或拒绝该值时，Vue 捕获异常并在开发态警告，避免一次非法 prop 让整棵组件树的 patch 中断。

attribute 分支：存在、字符串值与命名空间

普通 attribute 的 null 表示删除；特殊布尔 attribute 只看“是否存在”，真值写空串。 SVG 的 xlink:* 必须用命名空间 API，Symbol 则先显式转成字符串。

连续源码：patchAttr 的完整非 compat 主路径 
export function patchAttr(
  el: Element,
  key: string,
  value: any,
  isSVG: boolean,
  instance?: ComponentInternalInstance | null,
  isBoolean: boolean = isSpecialBooleanAttr(key),
): void {
  if (isSVG && key.startsWith('xlink:')) {
    if (value == null) {
      el.removeAttributeNS(xlinkNS, key.slice(6, key.length))
    } else {
      el.setAttributeNS(xlinkNS, key, value)
    }
  } else {
    if (__COMPAT__ && compatCoerceAttr(el, key, value, instance)) {
      return
    }

    // 此处的 special Boolean 仅指没有同名 DOM property、因此不会走 patchDOMProp 的键。
    if (value == null || (isBoolean && !includeBooleanAttr(value))) {
      el.removeAttribute(key)
    } else {
      // HTML attribute 值最终为字符串；布尔 attribute 用空串表达“存在”。
      el.setAttribute(
        key,
        isBoolean ? '' : isSymbol(value) ? String(value) : value,
      )
    }
  }
}

class 要与 Transition 共存

Transition 在动画期间临时添加 enter/leave class。如果组件更新直接覆盖 className，动画 class 会丢失。因此元素上保存 transition class 集合，patchClass 把声明式 class 与临时 class 合并后提交。只有合并后的值仍为空，才移除 class attribute；否则再按 HTML/SVG 选择写入方式。

精确规则：先把元素上由 Transition 维护的临时 class 合入 value；合并后的值仍为 null，才调用 removeAttribute('class')。否则再分流——SVG 使用 setAttribute，HTML 使用 className。因此传入 null 但仍有 Transition class 时，不会移除 attribute。
连续源码：patchClass 合并 Transition class 
export function patchClass(
  el: Element,
  value: string | null,
  isSVG: boolean,
): void {
  // HTML 直接写 className 更快；SVG 的 className 是 SVGAnimatedString，需 setAttribute。
  const transitionClasses = (el as ElementWithTransition)[vtcKey]
  if (transitionClasses) {
    value = (
      value ? [value, ...transitionClasses] : [...transitionClasses]
    ).join(' ')
  }
  if (value == null) {
    el.removeAttribute('class')
  } else if (isSVG) {
    el.setAttribute('class', value)
  } else {
    el.className = value
  }
}

style 是对象级 Diff

  • 新值是字符串：写入 cssText，但保留由 useCssVars() 注入的 CSS 变量文本，并继续服从 v-show 的 display 状态。
  • 新值是对象：先删除旧值中已经消失的属性，再设置新属性。旧值即使是 cssText 字符串，也会拆出属性名并清理。
  • 数组是同一属性的有序 fallback 值，例如依次尝试旧语法和标准值；它与下面的 property 名自动前缀是两套机制。
  • 属性名以 -- 开头：用 setProperty 处理 CSS 自定义属性。
  • 值包含 !important：拆分后使用第三参数设置 priority。
  • 普通属性：缓存自动前缀结果，兼容浏览器实现名。
  • textarea 被用户拖拽调整宽高后，如果新旧 VNode 的 width/height 完全相同，不覆盖浏览器刚写入的实际尺寸。

这里的“删除旧属性”说明为什么不能只遍历 nextValue：DOM style 是有状态目标，未显式清理的旧字段会永久残留。

连续源码：patchStyle 与 v-show 的 display 所有权 
export function patchStyle(el: Element, prev: Style, next: Style): void {
  const style = (el as HTMLElement).style
  const isCssString = isString(next)
  let hasControlledDisplay = false
  if (next && !isCssString) {
    if (prev) {
      if (!isString(prev)) {
        for (const key in prev) {
          if (next[key] == null) {
            setStyle(style, key, '')
          }
        }
      } else {
        for (const prevStyle of prev.split(';')) {
          const key = prevStyle.slice(0, prevStyle.indexOf(':')).trim()
          if (next[key] == null) {
            setStyle(style, key, '')
          }
        }
      }
    }
    for (const key in next) {
      if (key === 'display') {
        hasControlledDisplay = true
      }
      const value = next[key]
      if (value != null) {
        if (
          !shouldPreserveTextareaResizeStyle(
            el,
            key,
            !isString(prev) && prev ? prev[key] : undefined,
            value,
          )
        ) {
          setStyle(style, key, value)
        }
      } else {
        setStyle(style, key, '')
      }
    }
  } else {
    if (isCssString) {
      if (prev !== next) {
        // #9821：cssText 整体覆盖会删除 useCssVars() 直接写入的 CSS 变量，需把保存的
        // CSS_VAR_TEXT 追加回来。
        const cssVarText = (style as any)[CSS_VAR_TEXT]
        if (cssVarText) {
          ;(next as string) += ';' + cssVarText
        }
        style.cssText = next as string
        hasControlledDisplay = displayRE.test(next)
      }
    } else if (prev) {
      el.removeAttribute('style')
    }
  }
  // vShowOriginalDisplay 字段存在表示同一元素还受 v-show 控制。
  if (vShowOriginalDisplay in el) {
    // 显示时应恢复本次 v-bind:style 的 display，而不是指令挂载时的旧值。
    el[vShowOriginalDisplay] = hasControlledDisplay ? style.display : ''
    // 隐藏状态下 v-show 优先于绑定 style，最终仍为 none。
    if ((el as VShowElement)[vShowHidden]) {
      style.display = 'none'
    }
  }
}

时间戳保护解决什么场景

一个事件冒泡过程中，父组件更新可能在父节点上新注册同类监听器。如果新监听器立即收到正在传播的“旧事件”，就违反了浏览器直觉。invoker 记录安装时刻，事件也带时间戳；比安装更早的事件不会触发新监听器。

更多边界

  • 事件名解析：onClickOnceCapture 拆出 once/capture/passive options，并把剩余名称 hyphenate。
  • 处理器数组：逐个调用；stopImmediatePropagation 会包装事件，阻止数组中后续回调。
  • 错误通道：事件处理器先进入组件错误处理链；若 errorCaptured 或 app.errorHandler 未处理，开发态会继续抛出，生产态也可由 throwUnhandledErrorInProduction 配置为重抛。

DOM 指令：v-model 与 v-show 都在协调两份状态

编译器不会把原生 v-model 简化成一次 value 赋值。它保留 onUpdate:modelValue 写回函数，同时选择一个 runtime-dom 指令； withDirectives 把指令绑定放进 vnode.dirs，runtime-core 再在 created、mounted、beforeUpdate、updated 等阶段调用它。这样 core 只负责生命周期顺序， 表单和 display 的浏览器细节留在 runtime-dom。

  2. vModelText.created 缓存当前 assigner，注册 input/change 与 composition 监听；用户输入经过 trim/number 转换后调用 assigner。
  3. model 更新触发组件调度。core 在 patch props 前调用指令 beforeUpdate，此时指令先换成最新 assigner，再判断是否需要触碰 DOM。
  4. 正在 composition 时直接返回；获得焦点的输入框若只是 trim 后等价，或 lazy model 没变，也不重写 value，避免光标/selection 跳动。
连续源码：vModelText 的输入监听、水合保护与更新 guard 
export const vModelText: ModelDirective<
  HTMLInputElement | HTMLTextAreaElement,
  'trim' | 'number' | 'lazy'
> = {
  created(el, { modifiers: { lazy, trim, number } }, vnode) {
    // 水合 created 面对已在 DOM 的元素。保存 SSR/defaultValue 规范化结果，mounted 时可
    // 判断用户是否在 JS 加载前已经输入；若已输入，应写回 model 而非覆盖用户内容。
    if (el.parentNode) {
      if (el.type === 'text') {
        // text input.value 会去掉 CR/LF，但 defaultValue 保留，先按浏览器 value 规则规范化。
        el[initialValueKey] = el.defaultValue.replace(/[\r\n]/g, '')
      } else if (el.type === 'textarea') {
        // textarea.value 把 CRLF/CR 统一成 LF。
        el[initialValueKey] = el.defaultValue.replace(/\r\n?/g, '\n')
      }
    }
    el[assignKey] = getModelAssigner(vnode)
    const castToNumber =
      number || (vnode.props && vnode.props.type === 'number')
    addEventListener(el, lazy ? 'change' : 'input', e => {
      if ((e.target as any).composing) return
      el[assignKey](castValue(el.value, trim, castToNumber))
    })
    if (trim || castToNumber) {
      addEventListener(el, 'change', () => {
        el.value = castValue(el.value, trim, castToNumber)
      })
    }
    if (!lazy) {
      addEventListener(el, 'compositionstart', onCompositionStart)
      addEventListener(el, 'compositionend', onCompositionEnd)
      // Safari <10.2/UIWebView 在输入法确认前切焦点可能不发 compositionend；部分浏览器
      //（如 iOS Chrome）自动填充只发 change。change 兜底统一结束 composing 并补 input。
      addEventListener(el, 'change', onCompositionEnd)
    }
  },
  // mounted 才设 value，保证 range 的 min/max 等 props 已先写入。
  mounted(el, { value, modifiers: { trim, number } }) {
    const newValue = value == null ? '' : value
    const initialValue = el[initialValueKey]
    delete el[initialValueKey]
    if (
      initialValue !== undefined &&
      (el.type === 'text' || el.type === 'textarea') &&
      el.value !== initialValue
    ) {
      el[assignKey](castValue(el.value, trim, number))
    } else {
      el.value = newValue
    }
  },
  beforeUpdate(
    el,
    { value, oldValue, modifiers: { lazy, trim, number } },
    vnode,
  ) {
    el[assignKey] = getModelAssigner(vnode)
    // #2302：输入法组合尚未确认时不能用响应式旧值覆盖 DOM 中间文本。
    if ((el as any).composing) return
    const elValue =
      (number || el.type === 'number') && !/^0\d/.test(el.value)
        ? looseToNumber(el.value)
        : el.value
    const newValue = value == null ? '' : value

    if (elValue === newValue) {
      return
    }

    const rootNode = el.getRootNode()
    if (
      (rootNode instanceof Document || rootNode instanceof ShadowRoot) &&
      rootNode.activeElement === el &&
      el.type !== 'range'
    ) {
      // #8546：正在编辑的输入框尽量不写等价值，避免光标跳动/selection 重置。
      if (lazy && value === oldValue) {
        return
      }
      if (trim && el.value.trim() === newValue) {
        return
      }
    }

    el.value = newValue
  },
}

水合保护发生在 created / mounted，不是 beforeUpdate

SSR HTML 到达后，用户可能在 JS 下载完成前已经输入。created 先保存服务器 defaultValue 的规范化结果；mounted 发现当前 el.value 已不同，就把用户值写回 model，而不是用旧 model 覆盖它。 beforeUpdate 负责的是后续更新中的 composition、焦点和 trim/lazy guard， 两种保护不要混为一谈。

v-show：style 绑定和指令共同维护 display

vShowOriginalDisplay 记住“显示时该恢复什么”， vShowHidden 记住“现在是否被指令强制隐藏”。 patchStyle 每次看到新的声明式 display 都更新前者；只要后者仍为真，最终 DOM display 就必须保持 none。

V-SHOW · DISPLAY OWNERSHIP
S0 显示original = block；hidden = false；DOM = block
→ v-show=false
S1 隐藏original = block；hidden = true；DOM = none
→ style:grid
S2 隐藏中更新original = grid；hidden = true；DOM 仍是 none
→ v-show=true
S3 恢复hidden = false；DOM = grid

有 Transition 时，显示顺序是 beforeEnter → 恢复 display → enter；隐藏则先 leave，结束回调里才写 display:none。没有 Transition 时直接切换。 卸载前会按当前 binding 恢复一次 display，让离场/清理看到一致状态。

连续源码：vShow 四个生命周期与 setDisplay 
export const vShow: ObjectDirective<VShowElement> & { name: 'show' } = {
  // 水合 style mismatch 检查用内部 name 识别 v-show 应产生 display:none。
  name: 'show',
  beforeMount(el, { value }, { transition }) {
    el[vShowOriginalDisplay] =
      el.style.display === 'none' ? '' : el.style.display
    if (transition && value) {
      transition.beforeEnter(el)
    } else {
      setDisplay(el, value)
    }
  },
  mounted(el, { value }, { transition }) {
    if (transition && value) {
      transition.enter(el)
    }
  },
  updated(el, { value, oldValue }, { transition }) {
    if (!value === !oldValue) return
    if (transition) {
      if (value) {
        transition.beforeEnter(el)
        setDisplay(el, true)
        transition.enter(el)
      } else {
        transition.leave(el, () => {
          setDisplay(el, false)
        })
      }
    } else {
      setDisplay(el, value)
    }
  },
  beforeUnmount(el, { value }) {
    setDisplay(el, value)
  },
}

/** 按布尔值恢复原 display 或强制 none，并同步给 patchStyle 的隐藏标记。 */
function setDisplay(el: VShowElement, value: unknown): void {
  el.style.display = value ? el[vShowOriginalDisplay] : 'none'
  el[vShowHidden] = !value
}

Custom Element：让 Vue 组件进入浏览器组件协议

defineCustomElement 生成 HTMLElement 子类。内部组件仍由 Vue app 和 renderer 挂载，但对外必须像普通 Web Component： attribute 能驱动 prop，property 可以反射，移动节点不能误卸载，组件 emit 要变成 DOM CustomEvent。

这里没有实现 attributeChangedCallback，也不靠 observedAttributes 枚举属性。VueElement 用 MutationObserver 观察所有 attribute，再把变化交给 _setAttr → _setProp。
阶段 VueElement 动作 关键竞态
constructor 建立根节点，保存定义与初始 props，接住升级前已经写在实例上的 property 元素可能在定义前已拥有自有 property
connectedCallback 解析同步/异步定义、读取已有 attributes、启动 observer、创建组件实例 连接后定义仍可能是异步组件
MutationObserver _processMutations → _setAttr → _setProp，Number prop 先转数字 property 反射 attribute 时要避免 observer 把自己的写入再送回来
disconnectedCallback 微任务后确认仍断开再 unmount DOM move 会先断开再连接，不应误销毁
emit 转换为 CustomEvent，通过 DOM dispatchEvent 组件事件名大小写与 DOM 监听习惯

节点从一个父容器移动到另一个父容器时，浏览器会先触发 disconnected，再触发 connected。Vue 把真正卸载推迟到 nextTick；如果期间又连接，状态和 MutationObserver 都继续使用。只有复查仍断开，才停止 observer、卸载 app、清空组件与 Teleport target 引用。

反射如何避免自己触发自己

attribute 进来时，_setAttr 统一 camelCase，并按组件声明把 Number 转成数字。 property 进来时，setter 直接调 _setProp。若要反射回 attribute，Vue 先用 takeRecords() 消费已排队变化，再暂时断开 observer；写完 set/removeAttribute 后重新观察。对象和函数不适合字符串化，只保留在 property。

   * 更新内部 prop，可选反射回 attribute 与触发 VNode patch。
   *
   * 反射期间先消费 observer 已排队记录并暂时断开，防止自己的 setAttribute 再次回流。
   * 只有 boolean/string/number 适合 attribute；对象/函数只保留 property。
   * @internal
   */
  _setProp(
    key: string,
    val: any,
    shouldReflect = true,
    shouldUpdate = false,
  ): void {
    if (val !== this._props[key]) {
      this._dirty = true
      if (val === REMOVAL) {
        delete this._props[key]
      } else {
        this._props[key] = val
        // key 是 VNode 身份字段，不属于普通 props；App 已存在时还需同步根 ceVNode.key。
        if (key === 'key' && this._app) {
          this._app._ceVNode!.key = val
        }
      }
      if (shouldUpdate && this._instance) {
        this._update()
      }
      // property → attribute 反射。
      if (shouldReflect) {
        const ob = this._ob
        if (ob) {
          this._processMutations(ob.takeRecords())
          ob.disconnect()
        }
        if (val === true) {
          this.setAttribute(hyphenate(key), '')
        } else if (typeof val === 'string' || typeof val === 'number') {
          this.setAttribute(hyphenate(key), val + '')
        } else if (!val) {
          this.removeAttribute(hyphenate(key))
        }
        ob && ob.observe(this, { attributes: true })
      }
    }
  }

Trusted Types：给 sink 正确类型，不替你判断内容是否可信

runtime-dom 有两个直接的 HTML sink：patchDOMProp 给 innerHTML 赋值，insertStaticContent 给共享 <template>.innerHTML 赋值。两处都经过 unsafeToTrustedHTML。这个名字里的 unsafe 不是客套：Vue 创建的 policy 只是原样返回输入，让 CSP Trusted Types 接受该类型，不检查标签、属性或脚本协议。

2. patchEvent 的完整源码

export function patchEvent(
  el: Element & { [veiKey]?: Record<string, Invoker | undefined> },
  rawName: string,
  prevValue: EventValue | null,
  nextValue: EventValue | unknown,
  instance: ComponentInternalInstance | null = null,
): void {
  // vei = Vue Event Invokers；按原 prop 名缓存，options 变化会表现为不同 key。
  const invokers = el[veiKey] || (el[veiKey] = {})
  const existingInvoker = invokers[rawName]
  if (nextValue && existingInvoker) {
    // 监听器已存在：只替换内部函数值。
    existingInvoker.value = __DEV__
      ? sanitizeEventValue(nextValue, rawName)
      : (nextValue as EventValue)
  } else {
    const [name, options] = parseName(rawName)
    if (nextValue) {
      // 首次绑定：解析事件名/options，创建稳定代理。
      const invoker = (invokers[rawName] = createInvoker(
        __DEV__
          ? sanitizeEventValue(nextValue, rawName)
          : (nextValue as EventValue),
        instance,
      ))
      addEventListener(el, name, invoker, options)
    } else if (existingInvoker) {
      // 新值为空：用同一代理和 options 解除监听。
      removeEventListener(el, name, existingInvoker, options)
      invokers[rawName] = undefined
    }
  }
}

  1. 首次绑定：解析 onClick 与 options，创建 invoker，记录注册时间，再交给浏览器。
  2. 首次派发：invoker 读取当时的 value，所以调用 prevFn。
  3. 更新：缓存已命中，不触碰浏览器监听器表；下一次派发才读取 nextFn。
  4. 清理：null 分支用注册时同一 listener/options 解绑，并删除 Vue 私有缓存引用。
异常与边界：handler 抛错或返回 rejected Promise 时，invoker 通过 callWithAsyncErrorHandling 先进入组件错误链；错误是否继续抛出， 取决于 errorCaptured、app.errorHandler、开发/生产模式和 throwUnhandledErrorInProduction。数组 handler 会先复制快照， 并模拟 stopImmediatePropagation；冒泡途中刚注册的 listener 由 attached / event._vts 防止误收同一次事件；更新与解绑仍以稳定 invoker 身份为边界。
