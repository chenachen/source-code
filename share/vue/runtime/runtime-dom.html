Chapter 08 · Runtime DOM

Vue 的更新怎样真正落到浏览器

Renderer 已经决定“按钮的文字和 props 需要检查”。真正有变化时，runtime-dom 再处理浏览器的具体规则：该写 property 还是 attribute，事件怎样换回调，输入框怎样不丢光标；本页事件用例会专门把回调 A 更新为 B。

建议阅读 40 分钟先修：架构 / Renderer浏览器边界

为什么不能所有属性都用 setAttribute

HTML 看起来统一，浏览器对象的行为却不同。下面四种更新需要四套规则：

业务想做什么 浏览器层真正要考虑 负责模块
修改 class 普通 class 还要与 Transition 临时动画 class 合并 patchClass
修改 style 对象中消失的旧样式要清除，CSS 变量与 important 有特殊写法 patchStyle
更换点击回调 尽量复用已注册监听器，只替换它内部调用的新函数 patchEvent
更新输入框 不能打断拼音输入、移动光标或覆盖水合前用户已输入的内容 v-model / DOM prop
runtime-core 的语言

“把这个元素的 value 从 A 更新成 B。”它不假设目标一定是浏览器。

runtime-dom 的判断

元素是什么？用户是否正在输入？value 应写 property 还是 attribute？写入会不会触发副作用？

事件更新为什么不反复解绑

Vue 第一次添加 click 时注册一个稳定的“转接器”；回调从 A 变成 B，只更新转接器指向的函数。这样少做浏览器注册工作，也能统一处理错误、数组回调和事件传播中的时间问题。

runtime-dom 的价值：Renderer 保持通用和干净，所有浏览器兼容、交互连续性与安全写入规则集中在平台边界。
进入 DOM 接口、属性分派与源码层

包入口：组装 Renderer，而不是另写一套 Renderer

runtime-dom 把 nodeOps 与 patchProp 合并成 rendererOptions，传给 core 的 createRenderer / createHydrationRenderer。创建结果会缓存，因为同一页面不需要多份相同 DOM renderer。 

// 概念模型
const rendererOptions = extend({ patchProp }, nodeOps)

function ensureRenderer() {
  return renderer ||= createRenderer(rendererOptions)
}

export const render = (...args) => ensureRenderer().render(...args)
export const createApp = (...args) => {
  const app = ensureRenderer().createApp(...args)
  // DOM 专属：规范化容器、处理模板、清空容器、标记 data-v-app
  return app
}

createApp 的包装很重要：如果根组件没有 render/template，它可读取挂载容器的 innerHTML 作为模板；挂载前清空旧内容；挂载后移除 v-cloak、增加 data-v-app。这些都属于浏览器入口体验，不应进入 core。

静态内容为什么单独有接口

编译器可把连续静态节点提升成 HTML 字符串。逐个 VNode 创建会浪费解析与对象成本，insertStaticContent 让浏览器一次解析整段；同时返回起止节点，保证这段无单一根节点的内容仍能整体复制、移动和删除。

为什么不能简单写成 el[key] = value

例子 为什么例外 策略
form input/button 等表单控件的 .form 是只读关联对象，不是可写的 form id 字符串 把传入的 form id 写为 attribute
input list property 只读或语义与 attribute 不一致 使用 attribute
textarea type DOM 上不存在有意义的可写 property 使用 attribute
native onXxx 字符串 attribute 可表示内联监听器，但函数应走 addEventListener 按值类型分派
自定义元素 升级后的实例可能定义任意 property setter 存在 property 时优先 prop，显式修饰符可覆盖

class 与 style：看似简单，实则要保护其他子系统

class 要与 Transition 共存

Transition 在动画期间临时添加 enter/leave class。如果组件更新直接覆盖 className，动画 class 会丢失。因此元素上保存 transition class 集合，patchClass 把声明式 class 与临时 class 合并后提交。只有合并后的值仍为空，才移除 class attribute；否则再按 HTML/SVG 选择写入方式。

精确规则：先把元素上由 Transition 维护的临时 class 合入 value；合并后的值仍为 null，才调用 removeAttribute('class')。否则再分流——SVG 使用 setAttribute，HTML 使用 className。因此传入 null 但仍有 Transition class 时，不会移除 attribute。

style 是对象级 Diff

  • 新值是字符串：写入 cssText，但保留由 v-show 管理的 display。
  • 新值是对象：删除旧对象中已消失的属性，再设置新属性；数组值用于多候选前缀。
  • 属性名以 -- 开头：用 setProperty 处理 CSS 自定义属性。
  • 值包含 !important：拆分后使用第三参数设置 priority。
  • 普通属性：缓存自动前缀结果，兼容浏览器实现名。

这里的“删除旧属性”说明为什么不能只遍历 nextValue：DOM style 是有状态目标，未显式清理的旧字段会永久残留。

事件系统：Invoker 让监听器更新变成 O(1) 赋值

元素用内部 map 缓存 invoker。首次出现 onClick 时才 addEventListener；回调从 A 更新为 B 时只替换 invoker.value；彻底移除时才 removeEventListener。这避免频繁解绑，也保持 options 解析统一。 

// 概念模型
function invoker(event) {
  if (!event._vts) {
    event._vts = Date.now()
  } else if (event._vts <= invoker.attached) {
    return
  }
  callWithAsyncErrorHandling(
    invoker.value,
    instance,
    ErrorCodes.NATIVE_EVENT_HANDLER,
    [event],
  )
}

// 更新只改 value
existingInvoker.value = nextHandler

时间戳保护解决什么场景

一个事件冒泡过程中，父组件更新可能在父节点上新注册同类监听器。如果新监听器立即收到正在传播的“旧事件”，就违反了浏览器直觉。invoker 记录安装时刻，事件也带时间戳；比安装更早的事件不会触发新监听器。

更多边界

  • 事件名解析：onClickOnceCapture 拆出 once/capture/passive options，并把剩余名称 hyphenate。
  • 处理器数组：逐个调用；stopImmediatePropagation 会包装事件，阻止数组中后续回调。
  • 错误通道：事件处理器先进入组件错误处理链；若 errorCaptured 或 app.errorHandler 未处理，开发态会继续抛出，生产态也可由 throwUnhandledErrorInProduction 配置为重抛。

DOM 指令：把表单与显示语义封装在平台层

指令 核心状态 为什么不能只编译成普通属性
vModelText assigner、composing、事件监听 IME composition、lazy/trim/number 修饰符与光标状态
vModelCheckbox checked、数组/Set/value 单布尔值和多选集合有不同写回规则
vModelRadio checked 与 looseEqual DOM value 字符串化不能代表所有 JS 值
vModelSelect selected options、_assigning multiple、Set/Array、更新时避免 change 回流
vShow 原始 display、hidden 标记 要与 style patch、Transition hooks 共同维护 display
vOn withModifiers / withKeys wrapper stop/prevent/self 和键盘别名是运行时事件语义

表单更新为何要避免无条件赋值

用户正在输入时，无条件执行 el.value = newValue 可能移动光标、打断拼音输入或覆盖尚未同步到状态的文本。v-model 在 beforeUpdate 比较真实 DOM、修饰后的值和 activeElement，再决定是否赋值。运行时在这里保护的是交互连续性，不只是数据一致性。

DOM Transition：从抽象 hook 到 CSS 帧

beforeEnter
添加 *-enter-from 和 *-enter-active。
nextFrame
双 requestAnimationFrame 后移除 from，添加 to，让浏览器先提交初态再产生过渡。
whenTransitionEnds
读取 computed style，计算 transition/animation 的最大 delay + duration，并监听结束事件。
finish
清除 class，调用 core 传入的 done，使插入/删除状态机继续。

显式 duration 是兜底与控制手段；若 CSS 中多个属性时长不同，实现取最大 timeout，并校验 end 事件数量。用户过早取消、节点被卸载或 enter/leave 相互打断时，回调必须保证只结束一次。

Custom Element：让 Vue 组件进入浏览器组件协议

defineCustomElement 生成 HTMLElement 子类。它要处理浏览器升级、attribute/property 同步、connected/disconnected、ShadowRoot、slot、事件派发和样式注入；内部仍使用 Vue app 与 renderer 挂载组件。

阶段 VueElement 动作 关键竞态
constructor 保存初始 props，决定 shadowRoot，处理声明式 Shadow DOM 元素可能在定义前已拥有自有 property
connectedCallback 解析定义、观察 attribute、创建组件实例并 render 连接后定义仍可能是异步组件
attributeChanged 类型转换后写入 props 并触发更新 反射 property 时避免循环写回
disconnectedCallback 微任务后确认仍断开再 unmount DOM move 会先断开再连接，不应误销毁
emit 转换为 CustomEvent，通过 DOM dispatchEvent 组件事件名大小写与 DOM 监听习惯

“微任务后再判断 isConnected”是典型平台修复：节点从一个父容器移动到另一个父容器时，浏览器同步触发 disconnected/connected。若断开时立刻卸载，普通移动就会丢失组件状态。

安全与可信类型：平台层必须知道写入的危险性

  • innerHTML / textContent：用户通过 v-html 或 render prop 显式传入时走 DOM prop 路径；只有 innerHTML 经 unsafeToTrustedHTML 转成 TrustedHTML 类型，textContent 直接赋值。
  • 静态内容：insertStaticContent 写 template.innerHTML 前使用同一转换函数。策略的 createHTML 是恒等转换，只满足 Trusted Types sink 的类型要求，不做清洗。
  • 事件属性：函数走 addEventListener；字符串形式的 on* 赋值具有脚本语义，必须严格分派。
  • URL 属性：runtime 提交不等同于 URL 安全过滤，应用仍应避免把不可信输入直接传给危险协议。
Vue 的转义默认保护模板插值，但 v-html、直接 DOM prop、第三方指令与自定义 renderer 会扩大信任边界。阅读 runtime-dom 时应把“这个值最终进了哪个浏览器 sink”作为固定问题。TrustedHTML 代表调用方声明信任，不等于内容经过安全过滤。

手把手证据链：点击回调 A 怎样换成 B，又怎样彻底解绑

这里用两个仓库用例还原一台完整状态机：更新用例在同一个元素上完成“没有监听器 → 绑定 prevFn → 换成 nextFn”，解绑用例另建隔离元素证明 “已绑定 → 传入 null”。浏览器真正注册的函数是 invoker；更新阶段只改变它的 value。

1. 完整仓库测试：准备、动作、断言与清理

性质：Vue 3.5.41 仓库真实测试。第一段给出真实 import 和等待 helper； 第二段证明替换；第三段证明删除监听器。三段均是各自在文件中的连续原文。 vi / describe / it / expect 来自仓库 Vitest globals。

/** 等待一个宏任务，使事件时间戳和监听器附加时机跨过同一事件循环边界。 */
const timeout = () => new Promise(r => setTimeout(r))
  // 测试场景：应该更新事件处理程序。
  it('should update event handler', async () => {
    const el = document.createElement('div')
    const prevFn = vi.fn()
    const nextFn = vi.fn()
    patchProp(el, 'onClick', null, prevFn)
    el.dispatchEvent(new Event('click'))
    patchProp(el, 'onClick', prevFn, nextFn)
    await timeout()
    el.dispatchEvent(new Event('click'))
    await timeout()
    el.dispatchEvent(new Event('click'))
    await timeout()
    expect(prevFn).toHaveBeenCalledTimes(1)
    expect(nextFn).toHaveBeenCalledTimes(2)
  })
  // 测试场景：应该取消分配事件处理程序。
  it('should unassign event handler', async () => {
    const el = document.createElement('div')
    const fn = vi.fn()
    patchProp(el, 'onClick', null, fn)
    patchProp(el, 'onClick', fn, null)
    el.dispatchEvent(new Event('click'))
    await timeout()
    expect(fn).not.toHaveBeenCalled()
  })

Given：新建一个尚无 Vue 监听器的 div，并准备旧、新两个 spy。

When：先用 patchProp 绑定旧函数并点击一次，再把同一个 onClick 更新为新函数并点击两次；清理用例最后把值更新为 null。

Then：旧函数只收到首次点击，新函数收到后两次；解绑后继续派发 click 不再调用 handler。

Mechanism：patchProp 识别事件键后进入 patchEvent。缓存命中时只写 existingInvoker.value；null 分支以同一 invoker 调用 removeEventListener 并清空缓存槽。

Source：runtime-dom/src/modules/events.ts；局部元素不挂入 document，用例结束后可由 jsdom 回收，显式解绑路径由第二个测试证明。

2. 决定性连续源码：不是概念化骨架

export function patchEvent(
  el: Element & { [veiKey]?: Record<string, Invoker | undefined> },
  rawName: string,
  prevValue: EventValue | null,
  nextValue: EventValue | unknown,
  instance: ComponentInternalInstance | null = null,
): void {
  // vei = Vue Event Invokers；按原 prop 名缓存，options 变化会表现为不同 key。
  const invokers = el[veiKey] || (el[veiKey] = {})
  const existingInvoker = invokers[rawName]
  if (nextValue && existingInvoker) {
    // 监听器已存在：只替换内部函数值。
    existingInvoker.value = __DEV__
      ? sanitizeEventValue(nextValue, rawName)
      : (nextValue as EventValue)
  } else {
    const [name, options] = parseName(rawName)
    if (nextValue) {
      // 首次绑定：解析事件名/options，创建稳定代理。
      const invoker = (invokers[rawName] = createInvoker(
        __DEV__
          ? sanitizeEventValue(nextValue, rawName)
          : (nextValue as EventValue),
        instance,
      ))
      addEventListener(el, name, invoker, options)
    } else if (existingInvoker) {
      // 新值为空：用同一代理和 options 解除监听。
      removeEventListener(el, name, existingInvoker, options)
      invokers[rawName] = undefined
    }
  }
}

3. 同一用例的状态图

ONE ELEMENT · ONE onClick SLOT
S0 空el._vei[onClick] 不存在
→ add
S1 旧值DOM listener = invoker；value = prevFn
→ patch
S2 新值listener 身份不变；value = nextFn
→ null
S3 清理removeEventListener；缓存 = undefined
  1. 首次绑定：解析 onClick 与 options，创建 invoker，记录注册时间，再交给浏览器。
  2. 首次派发：invoker 读取当时的 value，所以调用 prevFn。
  3. 更新：缓存已命中，不触碰浏览器监听器表；下一次派发才读取 nextFn。
  4. 清理：null 分支用注册时同一 listener/options 解绑，并删除 Vue 私有缓存引用。
异常与边界：handler 抛错或返回 rejected Promise 时，invoker 通过 callWithAsyncErrorHandling 先进入组件错误链；错误是否继续抛出， 取决于 errorCaptured、app.errorHandler、开发/生产模式和 throwUnhandledErrorInProduction。数组 handler 会先复制快照， 并模拟 stopImmediatePropagation；冒泡途中刚注册的 listener 由 attached / event._vts 防止误收同一次事件；更新与解绑仍以稳定 invoker 身份为边界。
