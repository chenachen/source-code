Vue Runtime，就是负责把“数据变了”可靠地翻译成“页面也跟着变”的那套系统。

先区分三个世界

① 数据世界 任务数组、当前用户、是否展开。它描述应用现在是什么状态。 state / reactive / ref
② 描述世界 根据当前数据，Vue 算出“页面应该有四个列表项”。这还不是真实页面。 render / VNode
③ 浏览器世界 用户真正看到和点击的 HTML 节点。修改它才会改变页面。 DOM
Vue 不会让业务数据直接操作浏览器。它先生成一份新的页面描述，再拿新旧描述比较，最后只把必要变化交给浏览器。

后面最常见的八个词

术语 先这样理解 待办列表示例
DOM 浏览器中的真实页面节点 真正显示出来的 <li>
组件 拥有输入、状态和界面的一块独立功能 整个 TodoList 或其中一个 TodoItem
render 根据当前数据，重新计算页面应该长什么样 数组有四项，于是描述四个 li
VNode Vue 内部的一张“页面节点说明卡” 类型是 li、文字是跑步、key 是任务 id
patch 让旧页面逐步变成新页面的更新过程 保留前三项，只插入第四项
Diff 比较新旧列表，找出复用、新增、删除和移动 判断“学习 Vue”是移动，不是重建
Scheduler 把短时间内很多变化合并，并安排正确执行顺序 连续 push 三次，页面通常只统一更新一次
Hydration 接管服务端已经生成的 HTML，让它可以交互 页面先可见，JS 到达后绑定点击与组件状态
读到这里应该能回答：VNode 不是真实 DOM；render 负责描述结果；Diff 负责找变化；patch 负责执行更新计划。

为什么不把整个页面删掉重建

因为“看起来一样”不等于“还是原来的节点”。重建会丢掉许多用户正在使用的状态：

  • 输入框里的光标和正在输入的拼音；
  • 视频播放位置、元素滚动位置；
  • 组件内部状态和第三方 DOM 插件状态；
  • 正在执行的进入/离开动画；
  • 用户代码保存的 DOM 或组件引用。

所以 Vue 的核心目标不是“重新生成 HTML”，而是认出哪些东西还是原来的，只改变真正变动的部分。这正是 key、Diff 和 patch 存在的原因。
