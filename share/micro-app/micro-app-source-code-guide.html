1. 结论、范围与证据等级

核心结论：micro-app 把“应用”落成一个 Custom Element，把“运行实例”落成 CreateApp，先把 HTML 转成惰性模板并等待 CSS/JS 两条准备通道，再在挂载时 克隆 DOM、启动沙箱、执行脚本。隔离不是另起浏览器进程，而是 Proxy、节点归属标记、 全局原型补丁和副作用账本的组合。

3. 公开入口与启动

3.1 默认单例，不是无法绕过的进程级单例

src/index.ts 重导出 micro_app.ts 的 default；模块末尾只创建一次 new MicroApp()。但 MicroApp 类也公开导出，因此严格说默认导入是单例， API 并未禁止调用方手工 new MicroApp()。重复启动约束由每个实例自己的 hasInit 承担。

仓库源码摘录 · src/micro_app.ts · MicroApp.start / default export
export class MicroApp extends EventCenterForBaseApp {
  tagName = 'micro-app'
  hasInit = false

  start (options) {
    if (this.hasInit) return logError('microApp.start executed repeatedly')
    this.hasInit = true
    initGlobalEnv()
    if (window.customElements.get(this.tagName)) return logWarn(...)
    defineElement(this.tagName)
  }
}

const microApp = new MicroApp()
export default microApp
src/index.ts · default/MicroApp 重导出；src/micro_app.ts · MicroApp、microApp

3.2 start 的真实顺序

  1. 能力检查。必须是浏览器且有 window.customElements，否则只报错并返回。
  2. 重复检查。hasInit 为真直接报错；随后立即把它设为真。
  3. tagName 校验。只接受 micro-app 或 micro-app-* 形态。
  4. initGlobalEnv。保存原生 window/document、DOM 原型方法、timer、event、history 等快照，并注入全局微应用样式。
  5. 已有元素检查。若 tag 已注册，只告警返回。
  6. 规范化 options。兼容 disable 配置名，安排 prefetch/globalAssets，格式化插件模块名。
  7. defineElement。闭包内定义 MicroAppElement，调用 customElements.define。
边界：hasInit = true 早于 tagName 合法性判断。一次非法 tagName 会消耗该实例的启动机会； 再调用将命中“executed repeatedly”。已有自定义元素检查也发生在 initGlobalEnv 之后。

4.2 连接、属性与断开的异步边界

入口同步动作微任务动作目的
connectedCallback 递增 connectedCount，把本次连接记为 true 若本次仍有效，发 base created；连接瞬间已有 name/url 才调用 handleConnected 抑制框架瞬时插入/删除造成的重复渲染
attributeChangedCallback 初始 name/url 立即格式化保存；运行中变化只设 isWaiting 同一轮多次变化合并到一次 handleAttributeUpdate 让 name 与 url 成对校验、避免中间态重建
disconnectedCallback 把当前连接记为 false，立即分派隐藏或 unmount 无额外 defer 取消尚未执行的旧连接任务，同时及时启动清理

defer 是 Promise.resolve().then(...)，这里的“异步”是微任务，不是 timer。

4.3 name/url 校验与冲突决策

  • formatAppName 删除开头数字及非字母数字、下划线、连字符字符；空结果非法。
  • formatAppURL 以基座地址补全，只接受 http/https/file，去掉 hash，保留 pathname/search。
  • 同名运行中实例不能被替换；即使 keep-alive 已隐藏，它仍被视为 active。
  • 目标 URL/SSR URL 相同且旧实例已 unmount 时直接复用；此分支不检查 scopecss/sandbox/iframe 是否变化。
  • 目标 URL 相同的 prefetch 只有 scopecss/sandbox/iframe 三项核心配置一致才复用；否则替换。
  • URL 不同的 unmount/prefetch 实例会被销毁后新建。核心配置变化本身不会迫使同 URL 的 unmount 实例重建，源码在属性迁移处仍留有对应 TODO。
复用边界：“核心配置一致才复用”只适用于 prefetch，不能泛化到已卸载实例。若要切换同 URL 应用的沙箱类型或 CSS 隔离，需显式 destroy，不能依赖普通 unmount 后重新插入。

5.3 loadSourceLevel 是两方屏障，不是百分比

仓库源码摘录 · src/create_app.ts · CreateApp.onLoad
private loadSourceLevel: -1 | 0 | 1 | 2 = 0

public onLoad ({ html, ...prerenderOptions }): void {
  if (++this.loadSourceLevel === 2) {
    this.source.html = html
    if (this.isUnmounted()) return
    if (!this.isPrefetch) {
      getRootContainer(this.container).mount(this)
    }
  }
}
值含义触发者
0HTML 尚未成功分出两条资源通道构造初值
1CSS lane 或 JS lane 任一完成；先后不固定第一次 app.onLoad
2两条通道都完成；保存模板并允许 mount第二次 app.onLoad
-1HTML fetch Promise rejectonLoadError

CSS 无外链时立即完成；JS 无登记脚本时立即完成。CSS 有外链时所有请求 settle 后完成， 即便某个失败；JS lane 在首次阶段只等待普通非 defer/non-async 脚本的预取， defer、async、module 的实际下载/执行留到 mount。故“level 2”不等于所有脚本已执行。

5.4 sourceCenter 的共享边界

sourceCenter 内部是 link Map 与 script Map，key 是补全后的绝对地址。 外链代码全局共享；每项的 appSpace[appName] 再保存该 app 的属性、CSS 解析结果或 JS 解析函数。当前实现没有基于 global 属性才共享的分支：外链默认都共享。

HTML 本身不进入 sourceCenter；动态 inline script 也不进入。静态 inline script 用随机 inline-* key 登记，destroy 时只删除这些 inline 项。外链 CSS/JS 没有 destroy 删除调用。

  • 不缓存请求中 Promise：并发应用看到同 URL 项的 code === '' 时会各自 fetch；缓存只复用已经完成的文本。
  • Set 会折叠重复静态地址：同一应用重复远程 src/href 只调度一次；远程 script 不按重复标签多次执行。静态 inline nonce 与动态 script 不受此折叠。
  • destroy 留下 appSpace：同名同 URL 新实例会沿用第一次登记的 attrs、async/defer/module/inline/pure 及 parsed metadata；当前实现用 appSpace[name] ||= newData，没有应用级失效。

5.5 加载失败的实际语义

  • HTML fetch reject：loadSourceLevel = -1，发 error，状态设 LOAD_FAILED。
  • HTML 空字符串：发 error 并返回，但不调用 onLoadError；内部状态仍为 LOADING、level 仍为 0，子应用却先收到 detail=LOAD_FAILED 的 statechange。
  • 缺 head/body：同样出现“对外 LOAD_FAILED、内部 LOADING/0”的分裂。
  • 静态 CSS 或由框架 fetchSource 管理的 JS reject：记录错误，但对应 lane/批次仍完成，应用可缺资源继续 mount；原生外链 module 例外见 6.3。
  • fetchSource 直接调用 res.text()，没有显式检查 res.ok；HTTP 错误是否变成失败取决于自定义 fetch 或返回正文的后续解析。
关键区别：只有 HTML Promise reject 进入 LOAD_FAILED/-1。空 HTML 与结构缺失是 “已报告但内部停在 LOADING”的路径；不能笼统称为统一加载失败状态。

7. CSSParser / scopedCSS：算法与手工推演

7.1 目标与算法

输入是一段 CSS、应用前缀、app URL 与可选 CSS 文件地址；输出是保留声明和 at-rule 结构、 改写普通选择器与相对 URL 的 CSS 字符串。解析器重复识别三类 token：style rule、at-rule、comment。 它不是浏览器 CSSOM，而是顺序消费字符串的专用 parser。

  1. matchRules。跳过空白和注释，循环尝试 at-rule，否则尝试 style rule。
  2. formatSelector。保护属性选择器中的逗号/值，再拆顶层逗号，为每个选择器决定前缀。
  3. body 特例。body 或 html body 被换为“应用前缀 + micro-app-body”。

9. mount 与执行完成

源码顺序校正：真实顺序是 sandboxReady → nextAction → cloneContainer → sandbox.start， 不是先 start 再 clone。随后才是 actionsBeforeExecScripts → execScripts。
  1. MicroAppElement.mount。把当前 container、inline、routerMode、base/default route、request patch 与 fiber 传给实例。
  2. 未加载完提前 mount。只保存 container、取消 prerender、发 child LOADING statechange，状态保持 LOADING；level 2 时由 onLoad 再触发。
  3. 等待 sandboxReady。With 构造时同步完成初始化但 Promise 回调仍在微任务；iframe 通过 0ms 轮询等待独立 document。
  4. BEFORE_MOUNT。进入 nextAction 后先设状态；非 prerender 路径发 base beforemount。
  5. MOUNTING 与模板。设 MOUNTING、发 child statechange；从 source.html 深克隆到宿主（UMD remount 则转移活 DOM）。
  6. sandbox.start。初始化路由状态、请求代理与全局 DOM/history 补丁，active 变 true。
  7. 执行前。patchElementTree 标记静态 DOM；劫持 window.mount/unmount 和 window['micro-app-'+name] 识别 UMD hooks。
  8. execScripts/runScript。按上一节的同步/defer/module/fiber边界执行，脚本先设置 active proxyWindow，再经插件与 bindScope。
  9. UMD 判定。同时取得函数型 mount 与 unmount 时，umdMode = true，调用 mount(data)；之后 remount 不再重跑初始化脚本。
  10. handleMounted。UMD mount Promise resolve/reject 后都进入 actionsAfterMounted；普通路径在脚本完成回调进入。
  11. MOUNTED。先设状态，再调用 child window.onmount，发 child statechange/mounted，最后发 base mounted。

  3. 子应用收：EventCenterForMicroApp.addDataListener 的 callbacks 被调用；autoTrigger 可读已有缓存。
  4. 子应用回：window.microApp.dispatch → __catalog_from_micro_app__ → base addDataListener。
  5. 宿主事件：同次有效 dispatch 后向 <micro-app> 发 datachange，detail 为合并数据。
  6. 卸载：listener 清理与 data 清理由不同 API 控制；默认保留缓存。只有真实 unmount 到达 active sandbox 时，clear-data/destroy 才清 per-app 双向数据；直接结算/no-op 分支可忽略它。

链 4：普通卸载、keep-alive、destroy

  1. 公共入口：remove element → disconnectedCallback → handleDisconnected。
  2. 普通：unmount → child hooks → sandbox.stop(default) → 清 event/timer → base unmount → clearOptions。
  3. keep-alive：hiddenKeepAliveApp → HIDDEN → afterhidden；level 2 时 DOM 移到 div 并 snapshot/release，未完成时退化普通 unmount；show 只适用于前者。
  4. destroy：unmount(destroy) → sandbox.stop(destroy) → clearData → clearOptions → actionsForCompletelyDestroy。
  5. 结果：普通与 UMD 可由同一 Map 实例复用；完成加载的 keep-alive 不真正 unmount；destroy 迫使下一次新建实例，但外链缓存及旧 appSpace 仍可复用。

15. 设计权衡、失败路径与未展开边界

15.1 从当前实现推断的设计权衡

从当前实现推断

Custom Element 降低接入成本

DOM 插拔天然映射生命周期；代价是框架渲染器的瞬时连接/断开需要微任务去抖和冲突仲裁。

从当前实现推断

共享资源换取复用

绝对地址全局缓存减少请求/解析；代价是 destroy 不清外链缓存，长期元数据和同 URL 内容新鲜度需由外部策略承担。

从当前实现推断

Proxy 兼容优先于强安全

缺失值回落 rawWindow 支持旧库；代价是隔离为工程命名空间，不是恶意代码安全容器。

从当前实现推断

确定性脚本顺序优先

async 与 defer 聚合后按 DOM 顺序执行，减少框架内竞态；代价是与浏览器原生 async 语义不同。

从当前实现推断

UMD/keep-alive 以常驻换速度

保留 DOM、timer 和副作用快照提升二次展示；代价是隐藏或卸载后仍可能有 timer/EventSource 等持续工作。

从当前实现推断

通信批处理降低噪声

同微任务合并与浅去重减少重复 render；代价是嵌套对象按引用判断，且 nextStep 在相同数据时也不执行。
