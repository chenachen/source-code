16. 公共 API、诊断与兼容类型边界

Node 公共出口汇集运行入口、配置和工具；日志、协议常量与类型声明把这些能力接到调用方。

证据基线：v8.2.1commit 421615865dad约 10 分钟查看 Markdown 原稿

公共出口按普通、兼容和 experimental API 区分；DTS 用编译期断言检查类型关系。

#从出口、诊断与类型看协议边界

前面的章节沿配置、请求与构建推进；这一章把那些主链共享的出口、常量和工具接起来。 沿 src/node/index.ts 找到公开能力，再看调用方怎样使用 logger、路径工具和兼容代理， 最后核对类型用例实际证明了哪些契约。

#共享常量连接解析与协议

constants.ts 集中维护跨模块必须一致的协议值：

  • ROLLUP_HOOKS 是构建侧 injectEnvironment 的钩子名称表：命中后包装 Environment 上下文， 执行交给 Rolldown。dev pluginContainer 按自身实现调度钩子。
  • client/server mainFields 与 conditions 分开，防止 SSR 误选 browser 入口。
  • DEV_PROD_CONDITION 延迟到解析期替换成 development/production。
  • /@fs/、/@vite/client、/@vite/env 是浏览器 URL 与内部文件/运行时之间的协议。
  • KNOWN_ASSET_TYPES 必须同步 client.d.ts 和 MIME 注册，否则运行时、TS 与响应头会分裂。
  • defaultAllowedOrigins 匹配 localhost 及其子域、127.0.0.1、[::1] 的 HTTP/HTTPS 来源。
  • optimizer 错误码让请求层区分构建失败与缓存文件缺失，选择不同恢复路径。

ESBUILD_BASELINE_WIDELY_AVAILABLE_TARGET 沿用 esbuild 的目标字符串记法，实际供当前的 Oxc/Rolldown 及相关转换步骤使用。scripts/generateTarget.ts 取 2026-01-01 为基线日期，生成 chrome111/edge111/firefox114/safari16.4/ios16.4；iOS 与 Safari 按独立目标维护。

#日志输出、状态与去重

createLogger() 先按 LogLevel 过滤，再按终端能力选择输出模式：

最近一次 type/msg 与计数器是模块级状态，由默认 logger 实例共享。warnOnce 的文本集合和 loggedErrors 的 WeakSet 则属于各自实例。

warnOnce 只在首次见到完整文本时调用输出，再登记文本；日志级别过滤了这次输出，文本仍会登记。 warn/warnOnce/error 也会先把 hasWarned 设为 true，所以它表示调用过警告或错误方法。

WeakSet 只登记携带 options.error 且通过级别过滤的错误对象。error() 每次仍调用输出，调用方需先查 hasErrorLogged(error) 再决定是否调用 logger.error(..., { error })。当前 baseEnvironment 将这项查询 转发给顶层 logger，保持错误身份表共享。WeakSet 不延长错误对象生命周期。

#preview、快捷键与 Source Map 诊断

preview() 以 command: 'serve'、默认 mode/NODE_ENV: 'production' 解析配置，插件的 apply 判断因此走 serve 条件。它从 build.outDir 提供产物，不运行开发模块或 HTML 转换。configurePreviewServer 先执行， 返回的安装回调在静态服务与 HTML fallback 之后、最终 HTML/404 中间件之前执行，随后才开始监听。

sirv 的 shouldServe 回调调用 shouldServeFile。这个 helper 只在大小写不敏感文件系统上逐级核对 文件名大小写，在其他系统上直接返回 true；候选路径没有在这一回调内取 realpath。

CLI 快捷键复用 _shortcutsState.rl，每次绑定替换 line listener。已有键在原位置更新 action，新键插入 列表前面；同键的新注册会替换旧 action。输入在 action 执行期间被忽略，await 正常完成才解锁，action 拒绝会保留占用状态直到重新绑定。q 的 finally 会退出进程，即使关闭服务器失败。

extractSourcemapFromFile 只用 mapFileCommentRegex 把外部文件引用换成等长空白，内联 data URL 注释仍保留。 node_modules 中的 map/source 引用会按所属包根检查规范化的文本路径；各个读取候选未逐一取 realpath。 缺少 source 的 readFile 会写入 null 并产生警告，但畸形 URI 的 decodeURI、用户 ignoreList 回调等异常 仍可向上传播，不能从“缺文件只告警”推导所有 map 处理都不会影响转换。

#类型目录的三类文件

#1. Vite 自有协议类型

  • types/importMeta.d.ts：通过全局声明合并加入 hot/env/glob，所以不能有顶层 import。
  • types/importGlob.d.ts：重载按 eager/lazy 与 raw/url/worker query 声明返回类型。
  • types/customEvent.d.ts：内置 HMR、forward-console 与 bundled-dev 事件名/payload 映射。
  • types/metadata.d.ts：模块增强 Rolldown 输出，为 chunk/asset 附加 Vite 资源依赖元数据。

ViteTypeOptions.strictImportMetaEnv 采用“键是否存在”判断，而不是读取布尔值。用户声明合并该键后， ImportMetaEnv 的任意 string 索引消失，只保留内置字段和用户显式声明。

MODE 是用户选择的模式名，DEV/PROD 则来自 config.isProduction；例如 staging 模式仍可生成生产产物。 SSR 跟随 Environment consumer 是否为 server。glob 在开发与构建转换时都会展开。

glob 类型重载还保留了历史推导：query: '?raw' 即使未选 import: 'default'，也声明为 string；实际生成 namespace 还是默认值取决于 import 选项。旧 as: 'raw'/'url' 会补 default，而 query 不会自动补。 worker 的类型映射声明为 Worker，实际 ?worker 模块默认导出的是构造包装器，须调用后才创建实例。 这两处要分别读 importGlob.d.ts 的声明和 importMetaGlob.ts/worker.ts 的变换。

#2. 工具配置的隔离类型

Sass、Less、Stylus、esbuild 与 Terser 是可选依赖；当前 Lightning CSS 随 Vite dependencies 安装。 internal 声明通过 type-only import 和部分 @ts-ignore 隔离类型解析，再 Omit 掉由 Vite 掌控的 filename、sourcemap、entry/output 等字段。Sass 类型额外检查可选导入是否退化为 any，优先选择仍有 信息的声明。这里的 Omit 表达配置所有权：用户提供算法参数，Vite 设置流水线参数。

rollupTypeCompat.d.ts 的 Rollup* 名称全部指向当前 Rolldown 类型，保留旧命名便于现有配置迁移。

#3. 内联的上游快照

chokidar.d.ts、connect.d.ts、ws.d.ts、commonjs.d.ts、alias.d.ts 主要来自上游项目。 其中 alias、chokidar、connect、ws 的声明描述集成的解析、监听、中间件与 WebSocket 接口，内联后用户 无需再安装相应类型包；文件保留上游来源与许可证。

commonjs.d.ts 有另一层历史边界：Vite 仍暴露 build.commonjsOptions，但当前构建不再注册 @rollup/plugin-commonjs，也未把这组选项传入 Rolldown；转换走 Rolldown 内置 CJS 支持。 文件里的 strictRequires 等注释描述旧插件协议，不能据此断言当前构建会执行相应选项。

#类型用例怎样读

src/node/__tests_dts__ 不执行运行时代码，靠 TypeScript 编译成败表达契约：

  • config.ts：defineConfig 重载是否保持对象、Promise 和函数返回形态；未知嵌套项是否报错。
  • plugin.ts：Vite 插件与 Rolldown/Rollup 类型是否兼容，钩子 this 是否带 Environment 扩展。
  • importGlob.ts：eager/query/as 组合的声明是否推导为值表、Promise 工厂、string 或 Worker。
  • postcss.ts：Vite 对外类型是否与 postcss-load-config 一致。
  • utils.ts：mergeWithDefaults 的结果类型是否匹配嵌套覆盖、数组、函数、undefined/null。

plugin.ts 中 HooksMissingInConstants 比较 RollupPluginHooks 与 (typeof ROLLUP_HOOKS)[number]。 常量显式标成 RollupPluginHooks[]，元素类型已拓宽为完整联合，所以这条断言不能检出数组实际漏了某个名称。

运行时单测的证据也各有范围：logger.spec.ts 用六组快照检查服务器地址及网卡标签，并未测试 createLogger 去重；constants.spec.ts 给默认 CORS 正则输入允许/拒绝表；shortcuts.spec.ts 检查同键覆盖与重启后 readline/action 的复用；utils.spec.ts 检查路径、srcset、配置合并与 Source Map 组合； server/__tests__/sourcemap.spec.ts 只检验最近 node_modules 包根的提取，不读取 map/source 文件。

@ts-expect-error 要求下一行产生诊断：若下一行不再报错，指令本身会成为诊断。这类反向断言与 Equal 断言一起约束发布类型；运行行为仍由源码和运行时用例说明。
