13A. CSS 编译、HMR 与构建产物

三段 CSS 插件把预处理、用户变换、开发注入与构建抽取分层，并管理 worker 和构建轮次缓存。

证据基线：v8.2.1commit 421615865dad约 14 分钟查看 Markdown 原稿

本页重点

三段 CSS 插件把预处理、用户变换、开发注入与构建抽取分层，并管理 worker 和构建轮次缓存。

推导边界

普通 CSS、CSS Modules、HTML proxy 有不同身份；不能概括为全部 CSS 都 self-accept。

证据口径

正文保留目标版本中的真实源码、状态说明与代表性测试映射。测试源码用于锁定设计契约；本轮没有执行测试命令。

#阅读边界

本章研究一个 CSS 请求怎样从源码变成开发态可 HMR 的 JS 模块，或生产构建中的 CSS asset：

  3. 普通 CSS 能自接受，CSS Modules 为什么通常不能？
  4. @import、url() 与 PostCSS 插件注入的 URL 怎样统一解析和登记依赖？
  5. Sass/Less 内联文件后，内部相对 URL 为什么要 rebase？
  6. 预处理器 worker 哪些情况会回退主线程，关闭 server 时为何必须 await？
  7. renderChunk 怎样判断纯 CSS chunk，并为何还要保留一个空 JS 代理到这个阶段？
  8. cssCodeSplit=false 时，CSS 顺序怎样由同步 import、当前 chunk、动态 import 决定？
  9. 删除纯 CSS 空 JS chunk 后，谁继承它的 importedCss/importedAssets metadata？
  10. @import/@charset 为什么在压缩前提升，hash marker 又解决了什么缓存问题？

  1. css.ts 顶部 query 正则和 CSSOptions。
  2. cssPlugin() 的 load/transform：只看输入怎样变成统一 CSS、deps、modules、map。
  3. compileCSS()：理解预处理器与 PostCSS/Lightning CSS 二阶段。
  4. cssPostPlugin.transform() 的 serve 分支：普通、direct、inline、CSS Modules。
  5. cssAnalysisPlugin()：看 CSS @import 怎样进入模块图。
  6. cssPostPlugin.renderChunk()：先读 styles 聚合和 URL 占位符替换。
  7. 同函数的 cssCodeSplit/legacy 分支，再读 generateBundle 的单 bundle 与纯 CSS chunk 删除。
  8. URL 重写 helper：skipUrlReplacer()、doUrlReplace()、rewriteCssImageSet()。
  9. Sass/Less/Stylus 的公共 worker/rebase 协议；不必先深读每个第三方选项。
  10. 单元测试按算法组、playground 按开发/构建对照阅读。

#CSS 请求身份

URL query 是 Vite 插件间协议，不是任意 cache 参数：

请求身份 结果
foo.css 开发态 JS 注入模块；构建态空 JS 代理 + 抽取 CSS
foo.css?direct 直接返回 CSS 内容，供 link/浏览器获取
foo.css?inline 导出编译后的 CSS 字符串，不插入页面
foo.css?url 导出独立 CSS 资源 URL
foo.module.css 导出 class name 映射，同时处理样式
?html-proxy&inline-css 缓存 HTML style/style attribute 编译结果，稍后回填 HTML
?transform-only ?url 构建内部身份，不混入普通 CSS chunk

?direct 仍经过预处理和 URL 重写，只是 css-post 不把它包装成 JS。?inline 与普通 CSS Modules 的导出 语义也不同：前者导出 CSS 文本，后者导出 class 映射。

#为什么有三个 CSS 插件

#vite:css：规范化输入

它在用户插件前运行，把 Sass/Less/Stylus/SugarSS 转成 CSS，应用 PostCSS 或 Lightning CSS，解析 @import/url/CSS Modules，返回 CSS code + sourcemap，并用 addWatchFile() 登记依赖。

它不把 CSS 包成最终 JS，因为用户插件可能还想修改统一 CSS 内容。

#vite:css-post：消费编译结果

它在用户插件后运行：

  • serve：生成 updateStyle() JS、HMR accept/prune 或 CSS Modules exports；
  • build：保存 CSS，给 Rolldown 一个带 side effects 的 JS 代理，renderChunk 时按实际 chunk 图抽取；
  • HTML inline proxy：把最终 CSS 写回 HTML transform 缓存。

#vite:css-analysis：开发模块图

普通 Import Analysis 维护 JS import/HMR 边；CSS @import 和第三方插件 addWatchFile() 不一定以 JS import 出现在代码里。该插件把这些文件建成 file-only ModuleNode，并更新根 CSS proxy 的 importedModules， 使依赖文件编辑能反向触发根样式 HMR。

PostCSS messages 中的 dir-dependency 会按 glob 枚举当前文件，同时把目录模式交给 watcher 语义；文件 新增/删除也应触发更新，而不只是已有文件内容变化。

#Lightning CSS 分支

Lightning CSS 同时承担 bundle、CSS Modules、URL dependency 分析与可选压缩。resolver 根据 importer 语言只选择对应 CSS/Sass/Less resolver；这与 PostCSS Modules composes 会遍历多个 resolver 的行为不 完全相同。

返回的 dependency placeholder 分类型处理：

  • file/glob：登记 watcher deps；
  • url：经 Vite asset resolver 后替换 url("placeholder")；
  • import：函数 replacer 原样插入 URL，防止 $& 被 String.replace 当匹配模式。

外部 @import 中 $ 保留的修复见 PR #22718。压缩阶段关闭 cssModules/visitor/customAtRules， 避免把编译阶段转换再跑一次；近期修复见 PR #23147。

CSS Modules exports 先按 key 排序，再拼 composes class，保证输出对象和 hash 不受底层遍历顺序影响。

#CSS URL 重写

cssUrlRE 只定位真正的 url() 函数，不能把 Sass 的 svg-url() 后缀误判。它支持：

  • 冒号后无空格；
  • image()/image-set() 中嵌套位置；
  • 文件名转义括号；
  • 单/双引号与裸 URL。

本地 URL 先去 CSS 转义，再经 Vite resolver。替换后若包含空格、) 或引号冲突，会重新选择 wrapper 并 转义。不能简单保留原引号：资源内联可能改变 URL 字符集合，例如 SVG 编码后的单双引号分布。

#预处理器 worker 生命周期

preprocessorMaxWorkers：

以下值无法结构化克隆，会回退主线程：

  • Less plugins（函数）；
  • Stylus define 中函数或 Evaluator；
  • additionalData 函数已在主线程执行，传给 worker 的副本固定 undefined。

Sass 使用自身 AsyncCompiler 长期实例，不另建通用 pool；优先 sass-embedded，若平台二进制加载失败则 回退 sass，见 PR #21002。

buildEnd()/server close 必须 await Less/Sass/Stylus controller 全部 close。只调用 stop 而不等待会在 进程中残留 sass-embedded 子进程；修复见 PR #22275。

插件生命周期外的 preprocessCSS() 不拥有可关闭时机，因此复用 max=0 的 fake controller，避免创建 调用方无法释放的真实 worker。

CSS Modules 还导出 class map：

#构建态：为什么先保留空 JS 代理

cssPostPlugin.transform() 把普通 CSS 记录到 styles，却返回空 JS，并设置 moduleSideEffects:'no-treeshake'。原因是最终 CSS 分组取决于 Rolldown 真实 chunk 图；transform 阶段还不 知道该 CSS 属于哪个同步/动态/手工 chunk。

renderChunk 遍历 chunk.modules：

  • id 在 styles：追加 CSS；
  • CSS Module 含 JS exports，因此 chunk 不是 pure CSS；
  • id 不在 styles 且 JS code 非空：不是 pure CSS；
  • cssScopeTo 对应 importer export 未渲染：跳过该 CSS，实现样式 tree-shaking。

cssScopeTo 查找优化用跨所有 meta.chunks 的 Proxy，只有真正访问 importer 时才搜索，避免提前构造完整 renderedModules 映射；相关性能改进见本地提交 59d0b35b3。

#CSS code split

开启时，每个 JS chunk 最多发射一个 CSS sidecar：

CSS 发射使用串行 Promise queue。Rolldown 的并行 renderChunk 完成顺序不稳定；若直接 emit，CSS asset 顺序/命名与最终 cascade 可能漂移。即使当前 chunk 没有 ?url 任务，也必须穿过同一队列，才能让后续 阶段的相对顺序一致。

JS entry 间接导入 CSS 时，CSS sidecar 名按 JS chunk basename；CSS 自身作为 entry 时保留 CSS 路径。 standalone CSS entry 的 manifest/assets 元数据演进见 PR #21015。

legacy IIFE/UMD 不能使用普通 ESM CSS sidecar 加载协议，样式以内联 document.createElement('style') 代码插进 wrapper 内部。ES 输出若有 shebang，注入点必须在 shebang 换行之后；修复见 PR #22717 与特殊行终止符补充 PR #23038。

cssCodeSplit:false 时 generateBundle 按 cascade 优先级聚合：

#纯 CSS chunk 清理

一个动态入口可能只 import CSS，Rolldown 仍生成空 JS chunk。Vite 发射真实 CSS 后必须删除它，但需同步 修补：

  1. 用 preliminaryFileName 把 rendered chunk 对应到 bundle 最终文件名；
  2. 从所有 importer 的 chunk.imports 删除空 JS；
  3. 把空 chunk 的 importedCss/importedAssets 转移给 importer；
  4. 在生成代码中删除 ESM import/CJS require；
  5. 删除 JS 和 map；standalone CSS entry 的 metadata 转到真实 CSS asset。

生成代码替换保持等长注释，降低 sourcemap 位移。CJS minifier 可能生成：

替换器必须正确保留前/后逗号或分号，不能只删字符串。特殊文件名与 import map 修复见 PR #19814、 PR #22841。空 CSS entry 应留下 .css 而非 .js，见 PR #20518。

#finalize、压缩与 hash marker

多个文件拼接后，CSS 规范要求 @charset 最先、外部 @import 位于其他规则之前。hoistAtRules() 先屏蔽 注释，再：

  • 按原顺序把所有 @import 移到开头；
  • 删除重复 @charset，只把第一个放在最前。

随后按 build.cssMinify 使用 esbuild 或 Lightning CSS。inline CSS 去掉尾换行，普通 asset 确保一个尾 换行；这个细节会影响 HTML 内联和内容 hash。

viteHashUpdateMarker 是只参与 hash 的临时字符串。Vite 5.4.3 改变 CSS link 的 crossorigin 请求属性 后，Chromium 可能复用旧内容 hash 缓存并阻止加载；marker 强制生成新 hash，发射最终 CSS 前再删除。 背景见 Issue #18038。

#Sourcemap

每层 map 分别产生：

任一层只有空 mappings 时，组合结果也退化为空 map，不能伪造精确映射。PostCSS 相对 sources 以输入 文件目录规范为绝对路径；<input css ...> 虚拟 source 加 null byte，防止后续读取磁盘。

#测试怎样映射源码

#css.spec.ts

  • cssUrlRE：空白、嵌套函数、函数名后缀、转义括号。
  • CSS Modules：composes alias 与普通/direct scoped name 一致。
  • hoist：引号内分号、注释伪规则、多 charset。
  • convertTargets：ES 年份与 browser 版本编码。
  • getEmptyChunkReplacer：ESM/CJS、无换行、逗号链、赋值边界和等长结果。
  • preprocessCSS：PostCSS/Lightning 统一 API、external URL 的 $。
  • Sass resolver：忽略 package main，命中根 index.scss。
  • library CSS 名：三层优先级。
  • injectInlinedCSS：IIFE/UMD wrapper、嵌套 name、多注入、ES shebang。

#cssPreprocessorTeardown.spec.ts

SCSS transform 启动 sass-embedded 子进程，server.close() 返回时活动句柄中不再有 Sass worker。它验证 的是 server → Environment → PluginContainer → buildEnd/worker.dispose 整条关闭链。

#playground/css

同一 fixture 在 serve/build 下对照：

  • 开发：复用编辑前 DOM 元素，证明 CSS HMR 未 reload；
  • 构建：读取 asset 内容/文件名，证明抽取、顺序、minify、tree-shaking；
  • 预处理器：imports、alias、additionalData、变量 URL 与 HMR；
  • URL：空格、image-set、PostCSS 后注入、query、Less data-uri；
  • async/scoped/module CSS：sidecar、cascade 顺序和删除未使用样式。

用例中 bundledDev 的 skips（#22863/#23028）是明确能力缺口，不应误读成普通 CSS 管线也不支持。
