01. CLI 与启动链路

CLI 负责尽早处理进程参数、把命令转成 InlineConfig，再把控制权交给 Node API。

证据基线：v8.2.1commit 421615865dad约 5 分钟查看 Markdown 原稿

本页重点

CLI 负责尽早处理进程参数、把命令转成 InlineConfig，再把控制权交给 Node API。

推导边界

这里解释命令分派，不把 CLI 当成配置解析器或 HTTP Server 本体。

证据口径

正文保留目标版本中的真实源码、状态说明与代表性测试映射。测试源码用于锁定设计契约；本轮没有执行测试命令。

#阅读目标

本模块只解决一个问题：终端中的 vite、vite build、vite optimize、 vite preview 怎样进入对应 Node API。

读完应能区分两个层次：

  • bin/vite.js 是前置引导层：必须在加载其他 Vite 模块前设置调试环境、启动 CPU Profiler、记录启动时间并启用 Node.js 编译缓存。
  • src/node/cli.ts 是命令分发层：注册参数，把 CLI 值整理成 InlineConfig，然后调用 createServer()、createBuilder()、optimizeDeps() 或 preview()。

CLI 不负责模块解析、转换或构建算法。对应实现会在后续模块继续追踪。

#主调用链

开发源码位于 src/node/cli.ts，发布前会被打包成 dist/node/cli.js。bin 入口导入后者， 因此不能把源码路径和运行时产物路径误认为两套 CLI。

#关键对象

#global.__vite_start_time

入口执行第一时间记录。Dev Server 成功监听后，cli.ts 用它计算包含模块加载、配置解析 和服务器创建在内的总启动耗时。若只在 createServer() 内开始计时，会漏掉 CLI 前置成本。

#global.__vite_profile_session

--profile 模式必须先启动 V8 Inspector，再加载 CLI 主模块，否则采样会漏掉模块求值和 配置加载。会话通过全局变量跨越 bin 与打包后的 CLI chunk。

#容易忽略的场景

#调试参数必须提前处理

Vite 模块在首次加载时创建带命名空间的调试函数。因此 DEBUG 必须早于 import('../dist/node/cli.js') 设置。已有 DEBUG 还需合并，不能覆盖其他工具的调试 命名空间。相关修复：PR #6504。

#Node.js 编译缓存需要提前写出

module.enableCompileCache() 缓存 Node.js 对 Vite 自身模块的编译结果，不是 Vite 的 依赖预构建缓存。Node.js 默认在进程结束时写缓存，但开发服务器可能长期运行或直接 process.exit()；所以入口在 10 秒后主动 flush，并对定时器调用 unref()。

  • 启用编译缓存：PR #18323
  • 提前 flush：PR #19537

#重复参数取最后一个

输入 vite --port 3000 --port 4000 时，cac 会返回数组。Vite 配置只接受单值， filterDuplicateOptions() 按常见 CLI 规则保留最后一个值。相关修复： PR #10474。

#数字 host 与特殊 base

cac 会推断纯数字参数类型：--host 0 得到 number，但服务器需要字符串 host； --base 0 则是历史上表达空 base 的特殊写法。两者在 option type hook 中归一化。

  • host 修复：PR #14013
  • base 修复：PR #14283

#--watch 不能破坏配置文件

CLI 的 --watch 是 boolean，构建 API 的 watch 是对象。显式传入时应转换成 {}； 未传入时应保持 undefined，让配置文件中的 build.watch 正常参与后续合并。相关修复： PR #18390。

#推荐断点

  1. packages/vite/bin/vite.js 的 start()。
  2. src/node/cli.ts 中 dev action 的 createServer()。
  3. build action 的 createBuilder()。
  4. filterDuplicateOptions() 和 cleanGlobalCLIOptions()。
  5. playground/cli/__tests__/serve.ts 的 execaCommand()。
