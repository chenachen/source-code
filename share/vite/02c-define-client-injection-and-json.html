#Define 的三条执行路径

Environment 执行位置 原因
bundled build/bundled-dev Rolldown transform.define / 原生插件 bundler 已解析 AST，避免重复转换
SSR unbundled dev definePlugin.transform → Oxc Node/Runner 需要实际替换后的模块
client unbundled dev client injection + import analysis 避免每个浏览器模块启动 Oxc

这三条路径必须共享语义，但不共享执行位置。define.spec.ts 特意用同一 helper 构造 SSR dev 与 native build 路径，防止一个分支修复后另一个仍旧错误。

#为什么不是字符串替换

以下源码只应改表达式位置：

Oxc/Rolldown define 能区分字符串文本、模板表达式、属性访问与标识符边界。它还生成 sourcemap；对象值 造成位置变化时 map 仍要与上游插件合成，相关修复见 PR #15805。

transform 前先跑快速正则。正则 key 来自实际 define 表，并把属性点扩成可选问号加点，所以 process?.env 也能命中。未命中直接返回，不启动 AST transform；这项优化见 PR #14788。

#process.env 与库模式

非库构建默认定义：

client dev 只替换具体 process.env.NODE_ENV 表达式，不创建全局 process shim。否则依赖可能在 dev 看到 一个对象、build 又看到编译期常量，产生环境差异。

库构建完全跳过默认 process.env 替换。库是给下游应用消费的中间产物，不能固化库作者机器上的 mode， 也不能替最终宿主决定 Node/browser polyfill 策略。

#import.meta.env

bundled 环境把 config.env 展开为静态点属性，并补：

  • import.meta.env.SSR：按当前 Environment consumer 计算；
  • import.meta.hot：生产 build 默认 undefined，便于 tree-shaking；
  • import.meta.env.*：未知静态属性为 undefined；
  • 裸 import.meta.env：序列化成完整稳定对象。

同一 resolved config 可同时创建 client/server Environment，SSR 不能在插件创建时提前固定。define 表由 Environment WeakMap 惰性缓存，既避免串值，也让环境关闭后自然回收。

用户 define['import.meta.env.X'] 同时进入点属性替换和裸 env 对象。serializeDefine() 对 key 排序，保证 输出与 hash 稳定；相关稳定性修复见 PR #17748。字符串值按 “源码表达式”处理，而不是自动 JSON stringify，因此可以写 undefined、window 或兼容标识符；普通对象 和数值才 JSON 序列化。

计算属性 import.meta.env['UNKNOWN'] 不由静态通配规则消去，因为运行时 key 可能来自变量；静态 .UNKNOWN 才可确定为 undefined。用户可以用“同值 define”明确保留某个访问。

#Client injections

clientInjectionsPlugin() 只应用于 unbundled Environment。buildStart 先解析 hostname，再生成一个闭包， 把 client.ts/overlay/env.ts 中的占位符替成：

  • mode、base、server host；
  • WebSocket protocol/hostname/port/path/direct fallback；
  • HMR timeout、overlay 开关、配置文件显示名；
  • WebSocket token；
  • forward-console 配置；
  • 非 import.meta.env 的用户 define。

用函数作为 String.replace replacer，避免序列化值中的 $&、$1 被解释成替换模板。

HMR 端口优先级：

directTarget 使用显式 ws host/port，否则回到已解析 server hostname/port；path 再与 dev base 拼接。 bundled-dev 读取 bundledDevClient.ts 后走同一配置 replacer，保证两种 client 连接语义一致；Rolldown runtime 无法额外 import @vite/env，所以内联前删除该副作用 import。

因此同一注入代码可在页面、Web Worker 与旧宿主中执行。每个 define key 按点拆段，逐层创建对象，最后 写叶值。它只负责全局 define；正常 import.meta.env 已在模块转换阶段静态处理。

#JSON 模块

Vite 当前把 JSON 转换委托 Rolldown 原生插件，但仍由 JsonOptions 定义公共语义：

  • namedExports=true：顶层对象属性成为命名导出，可 tree-shake；
  • stringify=true：生成 JSON.parse("...")，大对象解析更快；
  • stringify='auto'：仅大于 10 KiB 时采用上述形式；
  • 数组不强制 stringify，避免输出与语义退化；修复见 PR #18541。

.json/.json5 带 query 仍可识别为 JSON 模块；但 ?url 与 ?raw 会在更前面的资源语义分支接管。 playground 同时区分：

写法 结果
import data 完整对象 default
import { key } 顶层 named export
import() 含 default/named 的 namespace
fetch('/x.json') 原始 HTTP JSON
?url 资源 URL，build 时可能 data URL
?raw 原文件文本
CJS require(json) Node 风格对象，不额外套 default

JSON 模块没有 HMR accept 边界时，编辑走 full reload；用例验证刷新后对象内容确实变化。
