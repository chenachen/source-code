13B. Asset、Worker 与 Wasm

Asset、Worker、Wasm 通过 URL、占位符、独立子构建和 runtime 胶水进入 JavaScript 图。

证据基线：v8.2.1commit 421615865dad约 17 分钟查看 Markdown 原稿

Worker 进入独立子构建；Asset URL 和 Wasm glue 通过资源占位符接入主产物。

#阅读边界

本章研究三类“不是普通 JS、最终却要进入 JS 模块图”的资源：

CSS 中的 URL 怎样进入 asset 流水线见 13A；第 14 章会从完整 build 生命周期继续解释 renderChunk、文件名、manifest 和 public base。本章只关心资源插件自己的协议。

读完应能回答：

  1. 为什么开发态返回真实 URL，构建态却先返回 __VITE_ASSET__...__？
  2. public 文件为什么不调用 emitFile()，又怎样进入最终 URL？
  3. ?inline、?no-inline、inline limit、SVG fragment 和 Git LFS pointer 如何共同决定内联？
  4. 动态 new URL(`./${name}.png`, import.meta.url) 为什么能转成 glob，动态 worker 为什么不能？
  5. ?worker 导入和 new Worker(new URL(...)) 最终怎样汇合？
  6. worker 为什么是一次嵌套的完整构建，而不是把源文件直接复制出去？
  7. worker 缓存怎样避免重复构建，又怎样只让受影响入口失效？
  8. classic、module、ignore 三种 worker type 分别怎样注入 /@vite/env？
  9. IIFE worker 为什么必须改写 import.meta，SharedWorker 内联为什么不用 blob URL？
  10. .wasm?init 与直接 .wasm 导入分别生成什么 API？
  11. Wasm Global 为什么需要 instance/wrapper 两层模块？
  12. SSR Wasm 为何还要把资产占位符换成相对当前 chunk 的运行时 URL？

#推荐阅读顺序

  1. asset.ts 的 query 正则、占位符正则和 assetPlugin()。
  2. fileToUrl() → fileToDevUrl() / fileToBuiltUrl()，先理解开发与构建分叉。
  3. shouldInline()、assetToDataURL()、svgToDataURL()，补齐内联策略。
  4. renderAssetUrlInJS()，看占位符怎样在已知 chunk 文件名后落地。
  5. assetImportMetaUrl.ts，对比静态 URL 与动态模板 glob。
  6. workerImportMetaUrl.ts，重点读 options 的静态 type 提取。
  7. worker.ts 的 webWorkerPlugin.load/transform，再读 bundleWorkerEntry()。
  8. WorkerOutputCache、renderChunk、generateBundle、watchChange，串起缓存与发射。
  9. webWorkerPostPlugin()，理解 IIFE 的 import.meta 兼容层。
  10. wasm.ts：先读 plugin load 分支，再读 parseWasm() 和两种 glue generator。
  11. 最后按单元测试的算法边界、playground 的 dev/build 对照复盘。

#总调用图

主线只有一个原则：transform 阶段通常不知道最终输出文件名，所以先建立资源引用关系并写占位符； 等 renderChunk 拿到 importer 与 asset 的最终文件名后，再计算 base、相对路径或运行时表达式。

#Asset 请求身份

写法 开发态 构建态
import url from './a.png' root URL、public URL 或 /@fs/ URL data URL 或 asset 占位符
?url 强制按 URL 模块处理 仍受合法的内联/发射规则影响
?inline 直接读取并生成 data URL 强制内联
?no-inline 保留独立 URL 强制 emit asset
?raw 导出文件文本并登记 watcher 导出文本
public 根路径 原根 URL public hash 占位符，不进入 emitFile()
root 外文件 /@fs/<absolute> 正常参与构建资产图
standalone asset entry 普通开发 URL 发射 asset，删除只作代理的空 JS entry chunk

query 是插件之间的身份协议。cleanUrl() 只用于文件系统解析，不能过早丢弃 postfix：SVG fragment、用户 query 和 ?no-inline 的控制语义都可能仍需保留。

#开发态 URL：把文件映射到服务器协议

fileToDevUrl() 的决策顺序：

/@fs/ 不是简单暴露磁盘。后续静态中间件仍会执行 server.fs.allow/deny 校验。asset 插件只负责选择 服务器协议，访问权限属于第 06 章的请求流水线。

asset 对应的 ModuleNode 已失效时，开发 URL 会附带 HMR timestamp。浏览器即使缓存了图片，也会因为 查询串变化重新请求；历史修复见 PR #13371。

#构建态：内联、emit 与占位符

fileToBuiltUrl() 先处理 public 请求，再查当前 Environment 的 assetCache。相同完整 ID（包括 query/postfix） 被 JS、CSS、HTML 多次引用时复用已生成 URL；不同环境和不同 query 不共用这条缓存。

#内联优先级

shouldInline() 可按下面顺序理解：

没有 build plugin context 时只跳过 lib/entry 判断，仍会执行其余规则，所以开发态 SVG 也能按阈值内联。 显式 query、lib 与用户回调都先于最后的 LFS 检查；lib 内联 LFS pointer 时会给出警告。

Git LFS 未拉取时磁盘内容只是 pointer 文本。默认大小分支不内联它，否则页面得到的会是 LFS 元数据；跳过逻辑 来自 PR #9795。

SVG 带 fragment 往往引用内部 symbol。将它转成 data URL 会改变复用与 fragment 行为，因此保持外置。 普通 SVG 从 Vite 5 开始可按阈值内联，见 PR #14643；若包含单双引号组合、<text>、 <foreignObject> 等高风险内容，则回退 MIME + base64，避免文本编码改变语义。

#两种占位符

普通构建资源调用 emitFile()，得到 referenceId：

public 资源已经由 publicDir 复制流程管理，不能再 emit 一份。因此只在 config 级 map 中保存 hash → 原 public URL：

renderAssetUrlInJS() 扫描两类占位符：普通资源通过 getFileName(referenceId) 取得最终文件名，public 资源 通过 cache 还原原 URL，然后统一交给 toOutputFilePathInJS()。此时才具备：

  • 当前 chunk 文件名；
  • asset 最终文件名；
  • output format；
  • base 是否相对；
  • experimental.renderBuiltUrl 是否返回运行时表达式。

因此占位符不是字符串替换技巧，而是跨 plugin hook 传递“尚未落地的资源引用”。

#new URL(..., import.meta.url)

assetImportMetaUrlPlugin 只作用于 client Environment，并避开 client runtime 与 preload helper。

#静态字面量

插件以 importer 目录解析文件，支持相对路径、alias/package 解析、public 根路径与无扩展文件，然后调用 fileToUrl()。普通本地文件存在时登记 watcher；取得 URL 失败时警告一次，保留原 URL 值供运行时解析。 最终表达式仍会规范为 new URL(url, '' + import.meta.url)。非 bundled 开发态的 fileToDevUrl 通常只映射路径， 不读取普通资源文件，因此缺失文件可能直到浏览器请求时才返回 404。 只观察真实文件避免把目录或尚不存在路径交给 watcher，修复见 PR #20507。

#动态模板

转换概念结果：

连续动态表达式合并成一个 *，模板顶层 query 单独进入 glob query；${condition ? a : b} 内部的问号 不能被误当 URL query，相关修复见 PR #13034 与 PR #13121。若 pattern 从 * 开始，插件无法确定安全搜索根， 保持原表达式。完全动态 URL 的边界见 PR #10549。

/* @vite-ignore */ 明确要求保持运行时语义；支持该逃生口见 PR #16590。

#Worker 的两个入口语法

Vite 支持两条表面不同的路径：

前者由 webWorkerPlugin.load() 生成包装模块，开发态固定使用 module；后者先由 workerImportMetaUrlPlugin 识别构造器和入口 URL，保留用户 options，并默认按 classic 判断入口类型。 两者在 bundled 模式最终都进入 bundleWorkerEntry()，所以 worker plugins、target、format、资源发射和缓存 行为一致。

?sharedworker 选择 SharedWorker 构造器；bundled 模式的 ?inline 选择内联包装，非 bundled 开发态仍使用服务 URL。 ?url 选择外置 worker URL 导出。若同时带 ?inline，bundled 分支先返回内联构造器，所以该组合导出的是构造器。

#Worker options 为什么只关心 type

浏览器 options 中 name 可以动态计算，但 type 决定 Vite 用 ESM import 还是 classic importScripts 注入 运行时，因此必须静态确定。

解析策略：

  1. 用 stripLiteral() 屏蔽字符串与注释，定位当前 Worker 调用闭括号；
  2. 尝试 evalValue() 静态求值完整 options；
  3. 失败时解析 AST，只提取 ObjectExpression 的 type；
  4. 无 type 且无 spread，安全回退 classic；
  5. spread 位于 type 之后时拒绝，因为它可能覆盖已读到的 type；
  6. options 中的 @vite-ignore 返回 ignore，跳过静态 type 求值；入口 URL 仍照常转换。

动态 name 支持见 PR #19010，字符串插值修复见 PR #19476，type 检测边界见 PR #19462。尾逗号、注释和多行 URL 是括号定位算法的回归面， 可沿 PR #10211、 PR #10226、 PR #20644 阅读。

普通 asset 动态模板可以枚举候选 URL；worker 入口却必须静态，因为每个候选都意味着一次独立构建、运行时 type 和嵌套 bundle chain。当前实现直接拒绝带 ${} 的 worker 模板；即使 options 有 @vite-ignore，这项 URL 校验仍先执行。

#Worker 独立子构建

worker 不是把源码复制成文件。它可以 import npm 依赖、CSS、资产、动态 chunk，甚至创建下一层 worker， 因此 bundleWorkerEntry() 创建新的 BuildEnvironment（内部名仍为 client），用 config.worker.plugins() 和 worker.rolldownOptions 执行完整 Rolldown 构建。

关键配置继承/覆盖：

  • build.target 传给 worker transform，修复见 PR #22404；
  • define 仍由 Vite define 插件处理，并转发给子构建，修复见 PR #22408；
  • format 来自 worker.format；错误消息也把 Rolldown 的 output.format 改写成用户认识的配置名；
  • entry/chunk/asset 默认命名放在 build.assetsDir，用户 worker output 命名选项可覆盖；
  • sourcemap 作为关联 worker asset 交给主构建发射。

bundleChain 保存当前嵌套 worker 入口链。若下一入口已经在链中，报告带完整 import chain 的循环；合法的 运行时自引用另有特殊分支改写为 self.location.href。循环检测与自引用支持见 PR #16103，依赖中的 URL 自引用修复见 PR #17846。

#WorkerOutputCache

缓存挂在 ResolvedConfig 的 WeakMap 上；嵌套 Environment 通过 mainConfig 共享主构建缓存。

已完成的同一 worker bundle 被多个入口引用时复用缓存；缓存不保存构建中的 Promise。watchChange 不清空全部缓存，只扫描 watchedFiles 标记受影响 bundle；该入口下次被请求时才删除旧 bundle，并只回收不再被其他 bundle 引用的 assets。按影响范围重建 来自 PR #20559。

worker 子构建产生的资源最终由主构建 generateBundle 统一发射：

  • legacy/modern 共享缓存，避免重复；
  • 嵌套 worker 构建不重复发射；
  • 主 bundle 已有同名同内容资源时复用；
  • 同名不同内容给出覆盖警告，见 PR #19591；
  • worker 引用遗漏的历史回归见 PR #21074。

bundled-dev 的 HMR patch 不经过常规 generateBundle，所以 emitWorkerAssetsForBundledDev() 会在 load/transform 阶段补发缓存资源；worker 文件更新支持见 PR #23068。

#内联 Worker 与 SharedWorker

普通 inline Worker 优先用 blob URL，构造失败时回退 data URL；代码放入 Blob 时会在 worker 启动后回收 object URL，不能提前回收，否则 WebKit 无法加载，修复见 PR #20460。Unicode 内容不再先做 base64，相关修复见 PR #15866。

SharedWorker 以 URL 作为共享身份；每次创建新 blob URL 会得到多个实例，所以 inline SharedWorker 固定使用 data URL，见 PR #12014。

#Wasm 的两种 API

#.wasm?init

插件返回显式初始化函数。浏览器端 helper：

  • data URL：解 base64 后 WebAssembly.instantiate()；
  • URL 且 MIME 为 application/wasm：instantiateStreaming()；
  • MIME 不正确：读取 ArrayBuffer 再 instantiate，兼容配置不完整的静态服务器。

SSR 端 helper 不 fetch，而用 new URL(file, import.meta.url) + readFile()。SSR ?init 支持来自 PR #21102。

#直接 .wasm ESM 导入

parseWasm() 在构建机读取并编译二进制，通过 WebAssembly.Module.imports/exports 得到静态模块接口， 生成：

  1. 依赖模块的 ESM import；
  2. WebAssembly import object；
  3. 顶层 await 实例化；
  4. 对 Wasm exports 的 ESM 命名导出。

非法 JS 标识符或保留字不能直接声明绑定，胶水代码会生成内部占位名，再用字符串模块导出名重导出。 直接导入实现见 PR #21779。

JS String builtins 等保留模块由 WebAssembly 引擎提供，不能生成普通 JS import；旧 Node 即使在 imports 列表中报告它们，也会由 wasmReservedModules 显式过滤。

#Wasm Global 的两层胶水

Wasm-to-Wasm 导入 Global 时需要 WebAssembly.Global 对象本身，以共享同一个可变或不可变 Global；JS 使用者 通常期望拿到 .value。同一导出无法同时满足两种形态，所以包含 Global 导出的 Wasm 拆成：

外层只在初始化时读取一次 .value，并不订阅可变 Global 的后续变化；Wasm-to-Wasm 则继续共享底层 Global 对象。 export * 不包含 default，所以 default 显式重导出，且即便 default 是 Global 也不解包。v128 Global 没有可读 JS 值，读取会抛错； wrapper 捕获后令其保持 undefined。两层设计、Global 解包与 string builtins 用例扩充见 PR #22674。

#SSR Wasm 占位符

普通 asset 占位符面向浏览器公开 URL；SSR 的 ?init 与直接导入都需要相对 server chunk 的文件 URL。因此 load 阶段 把 __VITE_ASSET__ 标记改为 __VITE_WASM_INIT__，renderChunk 再：

  1. 由 referenceId 取得 Wasm 输出文件名；
  2. 把它登记到 chunk importedAssets metadata；
  3. 生成相对当前 server chunk 的运行时表达式；
  4. 交给 new URL(..., import.meta.url) 在 Node 中定位文件。

使用全局正则 .test() 前必须重置 lastIndex。否则连续 Wasm 资产中第二个可能因旧游标起点漏掉替换并在运行时报 ENOENT；修复与最小回归用例见 PR #21780。

#单元测试

assetImportMetaUrl.spec.ts 直接调用 transform：

  • 变量位于路径段或扩展名前时的 glob pattern；
  • 连续动态表达式只生成一个 *；
  • 模板从变量开始时保持不变。

workerImportMetaUrl.spec.ts 重点不是浏览器，而是代码边界：

  • 无 options / SharedWorker 默认 classic；
  • identifier/literal type 都能识别；
  • 动态 name 保留、静态 type 仍能提取；
  • spread 可能覆盖 type 时必须报错；
  • 多行、尾逗号、注释、内部括号不破坏参数定位。

worker.spec.ts 对同一 ?worker&url 做 client 与 SSR 构建，要求提取出的 worker hash URL 相同。

wasm.spec.ts 故意先复现 /g 正则的 lastIndex 缺陷，再验证每次归零后的修复。
