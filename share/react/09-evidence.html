为什么改用 Hermes 审计

React 源码使用 Flow exact object、variance、opaque type、component syntax 等语法。 全局 TypeScript 解析会产生大量诊断，若忽略诊断继续统计，分母本身就是错的。本任务新增 audit-flow-comment-coverage.mjs， 用 hermes-parser@0.36.1 解析 JS/JSX，并坚持“有解析诊断即失败”。

聚合表使用无原型对象，避免声明类别 constructor 命中 Object.prototype.constructor 并污染计数。 React 的 TS/d.ts 最终门禁在独立验证环境中固定使用 TypeScript 5.9.3 Compiler API；它不同于 package.json 的 ^5.4.3 声明下限和 yarn.lock 的 5.7.3，复现终验时应显式安装 5.9.3。CoffeeScript 用 coffee-script 1.12.7 编译后再交 Hermes 解析，并人工逐类/方法核对。

“有注释”之外的质量门禁

  1. 职责。每个命名声明说明输入、输出、所有权或生命周期；薄包装说明它跨越的环境/包边界。
  2. 机制。关键状态机写明 true/false、进入/退出、异常/清理；Feature Flags 逐项说明两态与 fork 差异。
  3. 测试。每个 it/test 有邻近中文场景；关键用例写 Given、When、Then、验证机制与对应源码。
  4. 英文残留。普通解释性英文翻译为中文；仅保留 license、Flow/eslint/prettier/gate 指令、URL、协议字面量与注释代码。
  5. 解析。Hermes/TypeScript/CoffeeScript 对应输入无诊断；不把无法解析的文件从分母静默移除。
  6. 语义。逐文件比较编辑前后去注释 AST 与 token；TypeScript 比较 removeComments printer；CoffeeScript 比较编译后的去注释 AST。

语义等价意味着什么

PROVES

代码结构与 token 未变

对 JS/Flow，去除注释后 AST 哈希相同，非注释 token 序列相同；能捕获字符串、标识符、操作符、字面量或语句结构的意外修改。

DOES NOT PROVE

不替代所有运行环境测试

它不验证浏览器/Node 行为、时序、构建器或未解析资源；本次只改注释，因此把解析与语义等价作为更直接门禁，而不声称重跑了全量 Jest。

最终分片均在编辑前冻结基线，编辑后逐文件复核；门禁还会规范化比较 @gate、Flow/ESLint/TypeScript、覆盖率、webpack 与 pure/noinline 等工具指令签名， 避免“业务 token 没变、但工具语义注释被误删”的漏报。可用 audit-comment-only-semantics.mjs 对当前树与只读基线重跑相同门禁。reconciler tests 78/78 共 298,676 个非注释 token； dom-bindings 的 client/events/server/shared 四分区和 react-dom 224 文件也按同一规则终验。任何不等价文件都必须定位并修复后才能计入上表。

教程代码框也有证据身份门禁

教程不能只“长得像源码”。每个深色代码框必须明确属于以下一种身份：

标签门禁可以得出的结论
连续原码 / 连续测试原码HTML 解码、去展示标签后，必须是链接文件的连续子串可按首尾行在当前源码逐字复核
删节源码本地证据文件必须存在；正文必须说明删掉了什么只表达被保留的控制路径，不冒充完整函数
教程代码 / 教程伪代码 / 教程命令明确声明不属于仓库连续源码只用于手算状态或复现实验

本任务新增两个无网络依赖的门禁：源码摘录证据审计检查标签和连续匹配； HTML 完整性审计检查标签闭合、唯一结构、链接、fragment 与从首页可达性。

分享文档门禁

终态教程正文（排除 pre 源码块）超过 3.6 万汉字，含 240 个主题 section、94 张状态/对照表、22 条流程链与 157 个源码框。 其中 47/47 个生产连续原码、11/11 个连续测试原码逐字匹配；86 个删节源码和 13 个教程代码/命令均明确标出证据身份。

  • 18 个 HTML 页面（首页 + 17 个主题页）共享本地 CSS，不依赖 CDN 或网络字体。
  • 页面间上一页/下一页、顶栏、本页锚点和源码链接均按本地相对路径解析。
  • 桌面为正文 + sticky 目录；900px 以下目录回到文流；620px 以下单列卡片、隐藏长顶栏，并保留页尾导航。
  • 代码中的 <、>、& 已转义；HTML 使用 UTF-8；无教程自身的未完成标记、填充文本或外部资源；逐字源码摘录中的上游 TODO/FlowFixMe 原样保留。
  • 最终以 HTML5 解析器、全链接/锚点遍历和浏览器桌面/窄屏截图复核。

明确限制

  • 不覆盖 packages/react-server 的完整 Fizz request/task/segment 算法；只标出 ReactDOM 与 DOM server config 的边界。
  • 不声明源码对应某个不可验证的 Git commit/tag；只声明仓库内版本与初始内容指纹。
  • 不把内部 Feature Flag 的当前值解释为未来稳定公开承诺。
  • 不把测试文件位置当机制所有权；react-dom 内的事件测试可以为 bindings 提供证据。
  • 不自动提交或推送；所有修改留在当前工作区供审阅。

最终自检

  • 任取一个声明，是否能从覆盖表回到文件中的中文职责说明？
  • 任取一个教程结论，是否同时有实现入口、状态变化和测试断言，而非只引用 API 文档？
  • 任取一个异常路径，是否说明谁清理、谁重试、谁拥有剩余状态？
  • 删去全部新增注释后，源码 AST/token 是否回到编辑前基线？
