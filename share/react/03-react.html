先分清三种对象

ELEMENT

一次 render 的描述记录

type + key + props 表达“想要什么”；它不是 Fiber，也没有调度状态。

WRAPPER

类型级行为标记

memo、lazy、forwardRef 用 shared Symbol 包装目标，让 reconciler 在 tag 分派时采取不同策略。

FACADE

Hooks 只做动态转发

useState 读取当前 dispatcher；真实 mount/update 状态机在 reconciler 的当前 render 中。

所有权边界：React 可以创建一个元素对象，但从它被交给 renderer 起， 是否复用旧 Fiber、怎样比较 children、何时执行 effect，都由 renderer/reconciler 决定。

元素工厂：身份稳定，开发信息可裁剪

JSX 工厂先抽取保留字段，复制普通 props，处理 children/key，再交给内部 ReactElement。 生产记录保留 renderer 所需字段；开发记录额外保存 owner、debug stack/task、key 校验状态并冻结形状。 两者都依靠 shared 的 REACT_ELEMENT_TYPE 品牌字段，而不是 instanceof。

不要把摘录当逐字完整实现：上面折叠了 DEV 分支。 真实源码中 DEV 的 ref 兼容 getter、_owner 与冻结逻辑很重要；链接可直接核验。

key 只在同一父节点的 children 协调中表达身份；它不会自动成为 props，也不保证跨父节点搬迁时复用。 ref 在当前版本以 props.ref 为事实来源，元素上的兼容读取路径正处于迁移边界。

Children：扁平遍历同时重写身份路径

ReactChildren.js 处理单元素、数组、iterator、thenable 与 lazy， 递归生成稳定的 key path。map 不只是数组 map：回调返回数组时还会继续展开，并把用户 key 与原路径组合， 让 reconciler 能在扁平结果中保留身份线索。

输入遍历语义容易误判之处
null / boolean按空 child 处理，回调位置仍按实现规则计数不是可见文本节点
string / number / bigint作为叶子交给回调转换成 DOM 文本发生在 Host renderer
ReactElement / Portal按一个叶子处理并组合 key此处不展开组件返回值
Array / Iterable递归展开；开发态检查 keyMap entries 有专门警告，不是通用 children 形状
Thenable / Lazy按可用状态解包或抛出以挂起恢复与 Suspense 重试属于 reconciler

Hooks：同一个函数名，mount/update/rerender 三套行为

公共 useState 只读取 ReactSharedInternals.H 并转发。 reconciler 在执行函数组件之前安装 mount、update 或 rerender dispatcher，执行后恢复为防误用 dispatcher。 因此 Hooks 顺序规则不是语法偏好：位置就是当前 Fiber 单向 hook 链的寻址协议。

Context、memo 与 lazy：给 reconciler 的分派提示

CONTEXT

双 renderer 值槽

createContext 建立带品牌的对象和当前值槽；Provider 入栈/出栈、依赖传播与 Lane 标记由 reconciler 完成。

MEMO

比较策略包装

memo(type, compare) 保存目标与可选比较器。是否 bailout 还取决于 ref、context、Lane 与内部状态，不是单独一次浅比较。

LAZY

有状态模块 payload

initializer 把 Uninitialized → Pending → Resolved/Rejected；挂起时抛出 thenable，失败时重抛原因，重试由 Suspense 管线接管。

Transition：标注更新来源，不替它完成调度

startTransition 暂存当前 transition 对象、降低更新优先级边界并调用用户 scope；异步返回值会被纳入完成/错误跟踪。 随后真正的 state dispatch 仍需 reconciler 请求 Lane、入队并调度 root。React 包提供上下文，Lane 纠缠、pending 状态和 tracing 则跨入 reconciler。
