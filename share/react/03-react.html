react：创建元素，连接 renderer 协议

packages/react 创建元素、Context、ref、lazy/memo 包装和 Hooks 门面。 它定义“用户写下什么”，却不保存组件实例的 hook 链、不选择 Lane，也不触碰 DOM。

React 19.3.083 个目标文件 元素工厂 / dispatcher / 类型描述符

先分清三种对象

ELEMENT

一次 render 的描述记录

type + key + props 表达“想要什么”；它不是 Fiber，也没有调度状态。

WRAPPER

类型级行为标记

memo、lazy、forwardRef 用 shared Symbol 包装目标，让 reconciler 在 tag 分派时采取不同策略。

FACADE

Hooks 只做动态转发

useState 读取当前 dispatcher；真实 mount/update 状态机在 reconciler 的当前 render 中。

所有权边界：React 可以创建一个元素对象，但从它被交给 renderer 起， 是否复用旧 Fiber、怎样比较 children、何时执行 effect，都由 renderer/reconciler 决定。

元素工厂：key 与 props 分开，ref 保留在 props 中

自动 JSX 工厂从独立参数或配置对象提取 key，再交给内部 ReactElement。 配置对象没有 key 字段时，jsx 直接把它用作 props；存在该字段时才复制其余属性。 createElement 可由用户手工调用，因此始终创建新 props 对象，并把位置参数中的 children 写进去。 生产记录保留 renderer 所需字段；开发记录额外保存 owner、debug stack/task 与 key 校验状态。 两者都依靠 shared 的 REACT_ELEMENT_TYPE 品牌字段，而不是 instanceof。

DEV 元素保存 _owner，便于 key 警告指出创建者。非空 element.ref 是不可枚举的兼容 getter， 读取会提示改用 props.ref；空 ref 则直接定义为不可枚举的 null。 支持 Object.freeze 时，元素与 props 被浅冻结；key 校验状态放在仍可修改的 _store.validated 中。 生产分支不执行冻结。

key 只在同一父节点的 children 协调中表达身份；它不会自动成为 props，也不保证跨父节点搬迁时复用。 ref 在当前版本是普通 prop；公开工厂还保留 element.ref 的兼容读取形式。 cloneElement 先浅复制旧 props，再覆盖新字段；未传位置 children 时保留旧 children，传一个 undefined 则覆盖为空值。 新 ref 为 undefined 时保留旧 ref，而 null 会清空它。

Children：扁平遍历同时重写身份路径

ReactChildren.js 处理单元素、数组、iterator、thenable 与 lazy， 递归生成包含层级信息的 key path。map 不只是数组 map：回调返回数组时还会继续展开；返回 ReactElement 时， 它会把原 child 路径与映射结果新增的 key 组合。没有显式 key 的层级仍依赖索引，移动位置会改变路径。

输入遍历语义容易误判之处
null / undefined / boolean集合里的空值按叶子计数，回调接收 null；最外层 null/undefined 直接返回count([null, false]) 为 2，count(null) 为 0
string / number / bigint作为叶子交给回调转换成 DOM 文本发生在 Host renderer
ReactElement / Portal按一个叶子调用回调；映射结果是 ReactElement 时重写 keyPortal 原样保留；此处不展开组件返回值或 Fragment 内部 children
Array / Iterable递归展开；映射会保留缺 key 的校验信息，交给 renderer 报警Map 风格 entries 会输出不支持警告，之后仍按 iterable 遍历
Thenable / Lazy按可用状态解包或抛出以挂起恢复与 Suspense 重试属于 reconciler

例如 Children.map([<i key="a" />], () => <b key="b" />) 的结果 key 是 b/.$a： b/ 保留回调新增的 key，.$a 保留输入元素路径。 toArray 沿用映射遍历，但会过滤空值，所以同一输入的“叶子计数”与最终数组长度可以不同。 Children.only 检查参数本身是否是一个 ReactElement；只含一个元素的数组仍会抛错。

Hooks：同一个函数名，mount/update/rerender 三套行为

公共 useState 只读取 ReactSharedInternals.H 并转发。 reconciler 在执行函数组件之前安装 mount、update 或 rerender dispatcher，执行后恢复为防误用 dispatcher。 useState、useEffect 等按调用位置消费当前 Fiber 的单向 Hook 链，因而必须保持顺序。 useContext 不占这个链表槽位，但仍受普通 Hook 的调用顺序规则约束；use 则允许条件调用。 公开 API 名称与 Fiber 状态槽并非一一对应。

Context、memo 与 lazy：给 reconciler 的分派提示

CONTEXT

双 renderer 值槽

createContext 用默认值初始化两套槽；renderer 按 isPrimaryRenderer 选一套。Provider 指向 Context 自身，Consumer._context 也指回它；值栈与传播由 reconciler 完成；Context 到 memo 消费者的真实链路继续追踪。

MEMO

比较策略包装

memo(type, compare) 保存目标与可选比较器。是否 bailout 还取决于 ref、context、Lane 与内部状态，不是单独一次浅比较。

LAZY

有状态模块 payload

首次解析时调用加载器。订阅后尚未落定才进入 Pending；同步兑现或拒绝可直接进入终态。Pending 抛 thenable 以挂起，Rejected 抛原因交给错误处理，Resolved 返回模块默认导出。

同一个 lazy 描述符共享同一 payload。加载器或 then 订阅在落定前同步抛错时，payload 仍是 Uninitialized， 下次解析会重新启动；thenable 回调一旦登记 Rejected，无论同步或异步拒绝都被缓存，后续读取重抛同一原因。 因此 Suspense 的数据等待与错误边界的错误恢复是两条不同路径。

Transition：标注更新来源，不替它完成调度

startTransition 保存旧 ReactSharedInternals.T，安装新 transition 对象并立即同步执行用户 scope。 scope 返回后，renderer 的 S 钩子立即取得返回值；若它是 thenable，reconciler 把它登记为异步 action， React 公共包也订阅拒绝并报告全局错误。finally 随同步调用栈恢复旧 T，既不等待 thenable，也不返回这个 Promise。 此函数自身不设置 Lane；scope 内的 state dispatch 读取 T，才由 reconciler 选择 transition Lane、入队并调度 root。

await 后执行代码时，公共包的 T 已恢复，因此这时的 setter 要再次放进 startTransition 才能取得 transition Lane。 异步 action 的等待与 Lane 纠缠继续由 reconciler 跟踪；useTransition 的 pending 状态也保存在对应 Fiber Hook 中。 addTransitionType 找不到当前 T 时会另建隐式 transition，它不会恢复原先的同步调用栈。
