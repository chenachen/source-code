先看结论

描述 ≠ DOM

源码事实JSX 先产生不可执行的 ReactElement 描述；render 阶段构造 work-in-progress Fiber 与真实但尚未接入容器的 DOM，commit 才让副作用可见。

优先级 ≠ 执行器

源码事实lane 决定 React 选哪批工作；Root Scheduler 决定走 microtask 同步冲刷还是创建 Scheduler task；Scheduler 再管理 host task、超时与 continuation。

Render 可弃，Commit 原子

源码事实current 在 render 中保持旧树；mutation 完成后才令 root.current = finishedWork。layout 随后同步执行，passive 另行调度。

源码事实本 Demo 的两条真实调度分支不同：普通脚本中的首次 root.render 解析为 DefaultLane，microtask 后创建 Normal-priority Scheduler task；但当前 includesBlockingLane 包含 DefaultLane，进入任务后走 renderRootSync。点击由 dispatchDiscreteEvent 设置离散优先级，useState 得到 SyncLane；microtask 末尾直接 flushSyncWorkAcrossRoots_impl，不创建额外 Scheduler callback。

“Concurrent Root”表示渲染器具备并发能力，不保证每次更新都 time-slice。Transition/Retry/Idle 等非 blocking lane 才可能在未过期时走 renderRootConcurrent。

术语与推荐阅读地图

术语本教程中的精确定义不要混同
ReactElementJSX runtime 或 createElement 返回的描述对象：核心字段为 $$typeof/type/key/props，DEV 还保留 _owner 与调试字段。不是 Fiber，不含 DOM，不会自行执行组件。
Fiber一次组件/Host 节点的可变工作单元；含树指针、输入/已确认状态、lane、flags 与 alternate。不是 ReactElement；函数组件 Fiber 的 stateNode 通常为空，Host Fiber 才指 DOM。
FiberRoot一个渲染根的所有者：容器、current、pending/suspended/pinged/expired lanes、callback 与根调度链指针。不是 HostRoot Fiber；二者通过 root.current 与 fiber.stateNode 双向相连。
Hook函数组件 Fiber 的 memoizedState 上按调用顺序串联的单链表节点。不要和函数组件的 updateQueue（effect 等）混同；useState queue 位于 Hook 节点。
Update queueHostRoot 的 class-style queue 与每个 state Hook 的 queue 是两套结构；二者都用 pending 环形链表达新更新。不是 Scheduler 的 taskQueue。
Lane / Lanes31 位优先级与批次位集；一个 Lane 是单 bit，Lanes 是并集。低位数值更小、优先级更高。不是线程；也不等于 Scheduler priority。
Flag / subtreeFlagsrender 记录待提交副作用；subtreeFlags 是后代 flags 的聚合索引。不是 lane：lane 选择“做哪批工作”，flag 说明“提交什么副作用”。
Scheduler task带 start/expiration/sortIndex/callback 的最小堆节点，可返回 continuation。不是 Fiber work unit，也不是浏览器线程抢占。

推荐顺序：ReactElement → DOM Root → FiberRoot/Fiber/两套 update queue → lane 与 Root Scheduler → Scheduler heap/host loop → begin/complete 与 child reconciliation → commit/DOM → 事件委托回到 Hook dispatch。先理解对象所有权，再跟控制流；否则三个“queue”和两个“scheduler”最易混淆。

模块依赖图与核心对象关系

链 A：首次客户端挂载，从描述到容器 DOM

源码事实根创建与 UI 描述是两条先后发生的支线：createRoot(container) 先建立 FiberRoot、HostRoot、容器标记和事件委托；JSX 产生 ReactElement；随后 root.render(element) 才把描述入队。把 JSX 作为 createRoot 第二参数是错误用法，DEV 源码会给出警告。

描述1. JSX runtime 建立 ReactElement

packages/react/jsx-runtime.js 暴露 jsx/jsxs；生产分支的 jsxProd 把 key 从 config 分离，得到 props，调用 ReactElement。owner 只记录创建者上下文，不参与本主链的匹配。

建根2. createRoot 建立循环所有权

createContainer 固定 hydrate=false、initialChildren=null。createFiberRoot 创建 FiberRoot 与 HostRoot Fiber，令 root.current=hostRoot、hostRoot.stateNode=root，初始化 RootState 与 HostRoot UpdateQueue。

DOM API3. 标记容器并安装根级监听

markContainerAsRoot 把 HostRoot Fiber 缓存到容器；listenToAllSupportedEvents 按 listening marker 去重，为支持的 native events 安装 capture，且除 non-delegated events 外也装 bubble。此时没有 App DOM。

入队4. root.render 产生 HostRoot Update

updateContainer 取 container.current 并请求 lane。普通模块调用无显式事件优先级，resolveUpdatePriority 回退 Default；createUpdate 的 payload 被设为 {element}，先进入 concurrent staging buffer。

调度5. scheduleUpdateOnFiber 标记 root

markRootUpdated OR 进 root.pendingLanes；ensureRootIsScheduled 把 root 去重加入全局 root 单链表，并只安排一个处理该链的 microtask。

异步6. microtask 创建 Scheduler callback

processRootScheduleInMicrotask 调 scheduleTaskForRootDuringMicrotask。DefaultLane 不是真正的 SyncLane，映射成 Normal Scheduler priority，callback 是 performWorkOnRootViaSchedulerTask.bind(null, root)。

任务7. Scheduler host loop 运行根 callback

ready task 按 expirationTime 的最小堆排序。host callback 取堆顶，调用 React callback。若 React 返回 continuation，同一 Task 节点保留 callback 并让出本 host task；本次 Default 主链通常完整 render/commit 后返回 null。

Render8. DefaultLane 进入 renderRootSync

performWorkOnRoot 同时检查 forceSync、blocking 和 expired。当前 includesBlockingLane 包含 DefaultLane，因此本例调用 renderRootSync。只有非 blocking、未过期 lane 才进入可让出的 renderRootConcurrent。

双缓冲9. prepareFreshStack 建 WIP HostRoot

createWorkInProgress(root.current, null) 首次懒建 alternate 并互指；finishQueueingConcurrentUpdates 把 staging 中的 update 接成 shared.pending 环。旧 root.current 仍权威。

Begin10. HostRoot queue 变成元素子树

updateHostRoot clone/process queue，令 WIP RootState 的 element 成为 App ReactElement；reconcileChildren 创建 FunctionComponent Fiber。HostRoot 有 current，所以即使首次内容也用追踪副作用的 reconcileChildFibers，顶层 App 得到 Placement。

Hooks11. 函数组件建立 Hook 链

renderWithHooks 安装 mount dispatcher，调用 App；两个 useState 依次调用 mountWorkInProgressHook，追加到 App Fiber 的 memoizedState 单链。每个 queue 初始 pending=null，dispatch 绑定 Fiber 与 queue。

Complete12. 自底向上组装脱离 DOM

HostText/HostComponent 的 completeWork 调 DOM host config 建节点、设初始属性，并由 appendAllChildren → appendInitialChild 在脱离容器的 parent 上组树。bubbleProperties 聚合 children 的 lanes 与 flags。

Commit13. before-mutation 与 mutation

纯客户端初挂 HostRoot 带 Snapshot，before-mutation 清理容器既有内容。mutation 遍历带 MutationMask 的子树；App Placement 向下找到首层 host 节点，最终由 appendChildToContainer 接入 live container。

发布14. finishedWork 成为 current

finishedWork 先保存到模块级 pendingFinishedWork。mutation 完成后才执行 root.current=finishedWork；layout 在新 current 上同步运行；passive 如存在则由后续调度处理。容器至此显示 App。

链 B：一次 click 如何回到 Hook，再更新 DOM

Demo 点击同时执行 setCount(c => c + 1) 与 setItems(["C","A","B"])。两次 dispatch 位于同一离散事件 wrapper，均选择 SyncLane；root microtask 到来前它们已经进入同一 Fiber 的两个 Hook queue。

委托1. 根 listener 接收 native click

listenToAllSupportedEvents 已在 root 创建时安装 wrapper。getEventPriority("click") 返回 DiscreteEventPriority；wrapper 选择 dispatchDiscreteEvent，临时把 DOM renderer 的 current update priority 设为 SyncLane。

定位2. DOM target 映射回 Fiber

findInstanceBlockingEvent 的普通非 hydration 分支借 getClosestInstanceFromNode 从 DOM 节点缓存得到最近 Host Fiber；dispatchEventForPluginEventSystem 校准它所属 root/portal 边界。本教程只走同一普通 root。

提取3. SimpleEventPlugin 建 dispatch queue

dispatchEventsForPlugins 创建空数组；SimpleEventPlugin.extractEvents 把 click 映射为 onClick 与 SyntheticMouseEvent，沿 Fiber return 链收集当前 props 中的 listener，按 capture 或 bubble 阶段入队。

调用4. bubble 队列执行 onClick

单阶段 listener 从 target 向 root 收集；bubble 依数组正序执行，capture 则逆序。executeDispatch 在调用时设置 event.currentTarget，finally 式清空；stopPropagation 可提前停止后续实例。

Hook5. 公共 useState dispatch 已绑定 Fiber/queue

首次 mount 时 mountState 创建 dispatch，绑定当时的 App Fiber 与具体 queue；测试证明后续 render 仍返回同一 updater。点击无需再次调用公共 useState 才能派发，而是直接调用闭包中的 dispatch。

入队6. dispatchSetState 构造 Hook Update

update 含 lane/revertLane/action/hasEagerState/eagerState/next。队列空且 Fiber 无 lane 时可先用 lastRenderedReducer 求 eager state；若 Object.is 相等则入队但不调度。本 Demo 状态确实改变，继续调度。

传播7. concurrent staging 标记 Fiber 与 root

enqueueConcurrentHookUpdate 先把两个 update 分别暂存，立即 OR 到 App current/alternate 的 lanes，并沿 return 找 FiberRoot；scheduleUpdateOnFiber 再 OR 到 root.pendingLanes、去重 root 与 microtask。

同步入口8. SyncLane 不建 Scheduler task

root microtask 中 scheduleTaskForRootDuringMicrotask 发现 includesSyncLane，取消旧 callback、置 callbackNode=null，返回 SyncLane。遍历完所有 roots 后，flushSyncWorkAcrossRoots_impl 直接调用 performSyncWorkOnRoot(forceSync=true)。

Reducer9. updateState 处理两个 pending 环

renderWithHooks 选择 update dispatcher；updateState 走 updateReducer(basicStateReducer)。pending ring 合并到 baseQueue；当前 SyncLane 属 renderLanes，所以 action 不跳过：函数 action 得到 1，数组 action 得到 [C,A,B]。

协调10. button 更新，keyed children 重排

新 button props 与旧 props 不同，HostComponent 在 complete 标 Update；列表前缀首项 key 不匹配，转入 key map。C 复用且不标移动，A/B 复用并各标 Placement；没有剩余 map 项，所以无 Deletion。

DOM11. commitUpdate 与 commitPlacement

button 的 commitUpdate 调 updateProperties 更新文本/属性，再用 updateFiberProps 刷新事件 props cache。A/B 的 Placement 对已存在 DOM 节点执行 append/move，最终次序成为 C,A,B。

收尾12. current 与优先级恢复

mutation 完成后切换 root.current；layout 随后同步。native wrapper 的 finally 恢复旧 current update priority 与 transition。下一事件不会继承本次 Sync 优先级。

算法一：Lane 选择与 Root 调度

问题、输入、输出

问题：多个 root、多个优先级、挂起与过期并存时，决定下一批 render lanes，以及用 microtask 同步 flush 还是 Scheduler task。

输入：pending/suspended/pinged/warm/expiredLanes、wipLanes、pending commit、当前时间、事件/transition 上下文。

输出：nextLanes；root 的 callbackNode/priority；sync flush 或带 Scheduler priority 的 callback。

核心不变量

  • lane bit 不因“过期”改名；过期只额外写入 expiredLanes，从而关闭 time slicing。
  • non-idle 全部完成前不选 idle；unblocked → pinged → prewarm。
  • 已有 WIP 只有遇到真正更高优先级才通常被打断；Default 不打断 transition WIP。
  • 一个 root 在相同 callback priority 下复用 callback；优先级改变才取消并重建。
  • 取消 Scheduler task 是 lazy cancel：置 callback=null，不从 heap 任意删除。

第 1 层：requestUpdateLane

1 · 特殊模式

legacy 非 Concurrent → Sync；render-phase update → 当前 render lanes 中任取。二者都不是本 Demo 主分支。

2 · Transition

存在 current transition → 轮转分配 transition lane。Transition 是并发能力示例，不由本 Demo 触发。

3 · 事件优先级

普通路径取 resolveUpdatePriority。无事件 → Default；click wrapper 已显式设 Discrete → Sync。

第 2 层：getNextLanes

1. 空集退出

pendingLanes===NoLanes 立即返回，无 callback；microtask 可把 root 从调度链移除。

2. non-idle 选择

先取 nonIdlePending & ~suspended；为空再取 nonIdlePending & pinged；仍为空且没有 pending commit，才取未 warm 的 lanes 做 prewarm。

3. idle 选择

只有 non-idle 全空才对 idle 集合重复 unblocked → pinged → prewarm 顺序。

4. 与现有 WIP 比较

若已有不同 WIP lanes，低/同优先新工作保留现有 WIP；更高优先才切换。源码还特判 Default 不打断 transition。

5. 同优先级分组

getHighestPriorityLanes 不总是只返回一个 bit。当前版本先返回所有 pending SyncUpdateLanes；transition update/deferred 也各按组返回。

完整手推 A：普通首次 root.render

t0 · enqueue

pending=0。无 event/transition：requestUpdateLane → Default(0b100000)；markRootUpdated → pending=0b100000；安排 root microtask。

microtask · 建任务

首次 starvation 扫描设 expirationTimes[5]=now+5000ms。getNextLanes → Default；不含 Sync，创建 Normal Scheduler task。

host task · render

performWorkOnRootViaSchedulerTask 重算 lanes；通常 forceSync=false，但 includesBlockingLane(Default)=true，故 renderRootSync。

当前实现推断这解释了“API 返回异步”与“render 是否可中断”并非一回事：首次 root.render 不在当前调用栈完成，但它启动后仍可能是一口气完成的 sync work loop。

完整手推 B：Default callback 尚未运行时 click 到达

输入：pending = Default | Sync = 0b100010。SyncUpdateLanes = Sync | InputContinuous | Default = 0b101010。

选择：pending & SyncUpdateLanes = 0b100010，所以 getHighestPriorityLanes 返回 Sync 与 Default 两条 lane。它不是只返回最低 bit。

结果：includesSyncLane(nextLanes) 成立；Root Scheduler 取消尚未执行的 Normal task，不建新 task；同一个 root microtask 同步 render 两条 lane。被取消 task 的 heap 节点待到堆顶后因 callback=null 被 lazy pop。

完整手推 C：Transition 饥饿与过期

t=0

TransitionLane1 pending；microtask 设置 lane expiration 为 t+5000ms，安排 Normal Scheduler task。

多次 yield

renderRootConcurrent 在 Fiber unit 间调用 Scheduler shouldYield；callback 尾重算 root schedule，若同 callback node/priority 仍有效则返回 continuation。

t≥5000

markStarvedLanesAsExpired 执行 expiredLanes |= TransitionLane1。bit 本身不变；下次 includesExpiredLane 关闭 time slicing，走 renderRootSync。

Scheduler 的 Normal task 也有 5000ms timeout；它影响 heap 排序与传给 React 的 didTimeout，当前配置下可令 forceSync=true。两个 5000ms 是独立机制：一个在 FiberRoot lane map，一个在 Scheduler Task。

Scheduler 的两个堆、超时与 continuation

ready taskQueue

sortIndex=expirationTime。Immediate/UserBlocking/Normal/Low/Idle timeout 分别为 -1/250/5000/10000/1073741823ms。heap 先比 sortIndex，再比递增 id，稳定处理同 deadline。

delayed timerQueue

sortIndex=startTime。advanceTimers(now) 把到时 timer 移入 taskQueue，并把 sortIndex 换成 expirationTime。push/pop 为 O(log n)，peek 为 O(1)。

源码事实Scheduler 是协作式而非线程抢占：只有 callback 主动返回、React 在 Fiber unit 边界检查 shouldYieldToHost，或 callback 返回 continuation，浏览器才重新获得控制。continuation 写回同一 Task 节点，强制结束当前 host work loop，下一次 MessageChannel task 再继续。

复杂度、退出与重新调度

  • lane 扫描上限固定 31 bits，可视为 O(31)；root microtask 为 O(已调度 roots)。
  • Scheduler heap 插入/弹出 O(log n)，查看堆顶 O(1)。取消只置 null，O(1)。
  • render 完成、yield、被更高优先更新打断后都会重新 ensureRootIsScheduled 或在 callback 尾重算。
  • callback node 未变且优先级仍相同：返回 React continuation；node 变更、无工作或优先级变化：返回 null，由新任务接手。

算法二：Keyed 数组协调，手推 [A,B,C] → [C,A,B]

目标与输入

在同一 parent Fiber 下，用新 ReactElement 数组与旧 sibling Fiber 链对齐；尽量复用身份与 DOM，输出新 sibling 链及 Placement/Deletion flags。

本输入假设 A/B/C 的 element type 相同、key 各自稳定、当前是 update，因此 shouldTrackSideEffects=true。

核心不变量

lastPlacedIndex 是已处理且可保持原相对顺序的最大旧 index。新 Fiber 的旧 index 小于它，说明该节点必须移动到此前已处理节点之后，故标 Placement；否则更新 lastPlacedIndex。

复用身份要求同一 parent 协调范围 + 同 key + 兼容 type，只满足 key 不够。

function placeChild(newFiber, lastPlacedIndex, newIndex) {
  newFiber.index = newIndex;
  const current = newFiber.alternate;
  if (current !== null) {
    const oldIndex = current.index;
    if (oldIndex < lastPlacedIndex) {
      newFiber.flags |= Placement;
      return lastPlacedIndex;
    }
    return oldIndex;
  }
  newFiber.flags |= Placement | PlacementDEV;
  return lastPlacedIndex;
}

import {useState} from "react";
import {createRoot} from "react-dom/client";

const INITIAL_ITEMS = ["A", "B", "C"];
const ROTATED_ITEMS = ["C", "A", "B"];

function App() {
  const [count, setCount] = useState(0);
  const [items, setItems] = useState(INITIAL_ITEMS);

  function handleClick() {
    setCount(value => value + 1);
    setItems(ROTATED_ITEMS);
  }

  return (
    <main aria-label="React client rendering demo">
      <button id="advance" type="button" onClick={handleClick}>
        count: {count}
      </button>
      <ul>
        {items.map(id => (
          <li key={id} data-id={id}>{id}</li>
        ))}
      </ul>
    </main>
  );
}

function assert(condition, message) {
  if (!condition) {
    throw new Error("Assertion failed: " + message);
  }
}

function listOrder(container) {
  return Array.from(container.querySelectorAll("li"), node => node.dataset.id);
}

function waitForMutation(container, predicate, label, timeoutMs = 2000) {
  return new Promise((resolve, reject) => {
    const first = predicate();
    if (first) {
      resolve(first);
      return;
    }

    let observer;
    const timer = setTimeout(() => {
      observer.disconnect();
      reject(new Error("Timed out waiting for " + label));
    }, timeoutMs);

    observer = new MutationObserver(() => {
      const result = predicate();
      if (result) {
        clearTimeout(timer);
        observer.disconnect();
        resolve(result);
      }
    });
    observer.observe(container, {
      subtree: true,
      childList: true,
      characterData: true,
      attributes: true,
    });
  });
}

async function main() {
  const container = document.createElement("div");
  container.id = "root";
  document.body.appendChild(container);

  const root = createRoot(container);
  try {
    root.render(<App />);

    const button = await waitForMutation(
      container,
      () => container.querySelector("#advance"),
      "initial mount",
    );
    assert(button.textContent.trim() === "count: 0", "initial count");
    assert(listOrder(container).join(",") === "A,B,C", "initial list order");

    const nodesBefore = new Map(
      Array.from(container.querySelectorAll("li"), node => [
        node.dataset.id,
        node,
      ]),
    );

    button.dispatchEvent(new MouseEvent("click", {bubbles: true}));

    await waitForMutation(
      container,
      () => button.textContent.trim() === "count: 1",
      "click update",
    );
    assert(listOrder(container).join(",") === "C,A,B", "rotated list order");
    assert(container.querySelector("#advance") === button, "button reused");

    for (const id of ROTATED_ITEMS) {
      assert(
        container.querySelector('[data-id="' + id + '"]') === nodesBefore.get(id),
        "key " + id + " preserves its DOM node",
      );
    }
  } finally {
    root.unmount();
    assert(container.childNodes.length === 0, "root unmounted synchronously");
    container.remove();
  }
}

await main();

设计权衡、提交阶段、失败路径与范围边界

三类提交阶段：只保留主干

Mutation

源码事实消费 Placement/Update/Deletion 等 host 副作用，修改 live DOM。旧 current 在此阶段保持，以支持 unmount 语义；完成后切换 root.current。

Layout

源码事实在新 current 已发布后同步运行 layout effects、refs 与 class mount/update；可读取刚提交的 DOM。此阶段仍属于同一 commit。

Passive

源码事实若 PassiveMask 存在，通常以 Normal Scheduler callback 后续 flush；在下一次根工作前也可能先被冲刷并改变待选 lanes。

失败、提前退出与重新调度

公开 API / Hook

  • createRoot 收到非 DOM container：抛 Target container is not a DOM element.
  • public root 已 unmount 再 render：抛 Cannot update an unmounted root.
  • render 窗口外调用 Hook：dispatcher 为空，DEV 报 Invalid hook call。
  • update 时条件调用导致 queue 缺失或 Hook 数变化：抛内部一致性错误/DEV Hook 顺序诊断。
  • setState eager state 与 current 相同：环形入队保留 rebase 可能，但不安排 render。

协调 / DOM

  • key 改变、type 不兼容或旧 child 未被 Map 消费：Deletion + 新建，组件 state 重置。
  • 重复 key：DEV 警告，身份结果不受支持。
  • 外部手工删掉 React 管理 DOM 后再 unmount：Root 测试预期 removeChild 错误；React 不为任意外部 mutation 修复所有不变量。
  • 事件 target 不属于该 root 或跨 portal：边界校正可能重定向或退出；hydration 阻塞/replay 不在本教程展开。

Lane / Root Scheduler

  • 无 next lanes、等待数据或 pending commit：取消 callback，等新 update/ping/commit。
  • 更高优先 update 到达：可中断 WIP，重建 fresh stack；低/同优先通常保留 WIP。
  • 被 starvation 标成 expired：lane bit 不变，下次以 sync work loop 完成。
  • callback priority 未变：复用；改变：lazy cancel 旧 task，创建新 task。

Render / Commit

  • concurrent render yield：保留 WIP，React callback 返回 continuation 或另行调度。
  • 外部 store 在 concurrent render 间变化：当前实现可丢弃候选并同步重渲，避免提交不一致快照。
  • render 抛错、Suspense、commit 延迟与 recovery 有独立分支；本教程只标边界，不解释恢复算法。
  • commit 中不得重新进入 render/commit；WorkLoop 对重入直接抛内部错误。
