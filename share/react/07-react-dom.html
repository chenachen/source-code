createRoot：创建 FiberRoot，但不渲染首棵树

  1. 校验。只接受 Element、Document、DocumentFragment，以及特性开关允许时的注释容器。
  2. 归一化。读取 strict mode、identifierPrefix、错误回调、transition callbacks 等 options。
  3. 建根。createContainer 创建 ConcurrentRoot 的 FiberRoot 与 HostRoot Fiber。
  4. 关联。markContainerAsRoot 在容器上缓存 HostRoot，供事件/DOM 查询反向定位。
  5. 监听。在实际事件容器调用 listenToAllSupportedEvents，一次安装委托监听器。
  6. 返回。公开 ReactDOMRoot 只保存 _internalRoot；首次工作等 root.render。

root.render 与 unmount 都只是 Root Update

root.render(children) 检查句柄未释放后调用 updateContainer。 root.unmount() 则先把句柄置 null，提交 element=null 的 SyncLane 更新，flush 同步工作，再移除 container 的 root 标记。

为什么 unmount 先清句柄：提交删除会运行用户 cleanup/lifecycle；其中若重入调用同一 root，必须立刻看到“已释放”， 不能把正在销毁的根重新投入使用。

hydrateRoot：创建时就携带初始子树

普通 createRoot 把容器视作待管理边界；hydrateRoot 则把 initialChildren 传给 createHydrationContainer， 初始 hydration Lane 在建根时已经入队。它还可接收 server formState、hydration callbacks，并暴露 unstable_scheduleHydration 提高指定目标的恢复优先级。

Portal：改变宿主父级，不改变 React 父级

createPortal(children, container, key) 校验目标后创建带 REACT_PORTAL_TYPE 的 portal 记录。 reconciler 生成 HostPortal Fiber，commit 时把宿主 descendants 插入目标 container；context、错误边界和事件冒泡仍沿原 Fiber return 链。 因此 Portal 不是第二个 root，也不会拥有独立 root.render/unmount 生命周期。

flushSync：临时建立离散优先级边界

flushSync(fn) 保存 transition 与当前 update priority，把 priority 设为 DiscreteEventPriority，执行回调，最后恢复上下文并 flush sync work。 若在 render/commit 生命周期内部调用，不能安全地同步重入，DEV 会警告。

它不是“让所有异步变同步”：flushSync 只确保边界内及为满足一致性而连带的同步工作在返回前提交； Suspense、数据 promise、passive effect 与其他根可能带来额外 flush 或 fallback。

form/resource API：公开 facade，实际 DOM 行为在 bindings

FORM

useFormStatus / useFormState / requestFormReset

公开函数经 dispatcher 或 DOM internals 进入 action 状态与表单 reset；submit 提取、FormData、受控恢复由 event/client bindings 执行。

RESOURCE

preconnect / prefetchDNS / preload / preinit

公开 API 校验参数后调用当前 DOM dispatcher；服务端收集资源，客户端创建/复用 resource 节点，避免 React 包依赖浏览器。

Node 的 renderToPipeableStream 创建 request 后启动工作；pipe 只允许绑定一次 Writable，drain 恢复流动，error/提前 close 中止 request。 Browser/Edge 用 ReadableStream controller；Bun 有独立 destination 适配。static 入口返回 prelude 与 postponed state，resume 路径重新构造 request。

Legacy 与现代入口并存，但语义不要混写

render/hydrate/unmountComponentAtNode/findDOMNode 等 legacy API 由特性开关和构建 fork 管理。 现代 client root 使用 ConcurrentRoot 与显式 root 句柄；legacy root 保留同步批处理、callback 和容器复用兼容。阅读测试时要先确认入口与 feature flags， 否则会把 legacy 时序误套给 createRoot。
