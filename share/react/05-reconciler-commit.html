05 · Fiber engine / commit

reconciler：把 finishedWork 变成唯一现实

commit 不再决定组件“应该渲染什么”。它按 flags 遍历 finishedWork，先保存修改前快照，再执行宿主 mutation， 切换 current，最后运行能观察新宿主树的 layout 与后续 passive effects。

为什么 commit 不能像 render 一样任意中断

CONSISTENCY

用户只能看到旧树或新树

mutation 中途长时间让出会暴露一半更新的 DOM、ref 与生命周期状态。

ORDER

每类 effect 有固定观察窗口

snapshot 读旧宿主树；layout 读新宿主树；passive 不阻塞当前可见提交。

OWNERSHIP

current 切换是逻辑提交点

它晚于 mutation、早于 layout，使卸载读旧 current，挂载/更新读新 current。

“原子”是框架观察语义，不是数据库事务：DOM API、用户生命周期或 ref 回调仍可能抛错。 React 捕获并调度最近错误边界或根错误处理，但不会回滚已经完成的浏览器 mutation。

commitRoot 先把根状态收口

commitRoot 计算 remaining lanes，合并 render 期间并发进入的更新，调用 markRootFinished， 清理 callback 状态，并在真正 effect 前安排可能存在的 passive flush。然后才进入 before-mutation 与 pending-effects 状态机。

View Transition 启用时，mutation/layout/after-mutation 可能由宿主 transition callback 驱动；未启用时同步连续 flush。 无论哪条分支，pendingEffectsStatus 都防止阶段重复或乱序进入。

mutation：flags 决定动作，HostConfig 决定怎样写宿主

ReactFiberCommitWork.js 遍历带 MutationMask 的子树。 父 Fiber 的 deletions 先处理，再递归 child mutation，最后处理当前 Fiber 的 Placement/Update/Ref/Visibility 等。

为什么删除不是简单 parent.removeChild：删除子树中可能有 portal、class、hook effect、ref、cache 与隐藏边界。 reconciler 必须先按 Fiber 语义清理，再让 HostConfig 移除正确宿主根。

effect 顺序：先清旧，再装新

每个 effect 节点持有环形 effect list。layout 更新通常先执行上一次 destroy，再执行本次 create；passive 也分 unmount 与 mount 遍历， 确保同一提交的旧订阅先解除。Deletion 的 passive 清理可能等到后续 passive 阶段，但 Fiber/DOM 关联会在安全窗口断开以便 GC 与事件查询不再误认。

LAYOUT

同步观察新布局

useLayoutEffect、class didMount/didUpdate 与 ref attach 在 paint 前执行；其中同步更新可能让 passive 被提前冲刷。

PASSIVE

默认不阻塞当前提交

useEffect 由 Normal Scheduler callback 或后续强制 flush 运行；它可以产生新更新，因此有 nested passive update 保护。

ref：detach 与 attach 分属不同观察窗口

更新 ref 时，旧 ref 在 mutation 路径 detach，新的 ref 在 layout attach。 对象 ref 写入 current；函数 ref 返回的 cleanup 会被保存，下一次 detach 优先调用 cleanup，否则以 null 调用 ref。 这样新 ref 回调看到的 host tree 已完成 mutation，且 root.current 已是新树。

错误隔离：继续遍历，但不假装回滚

  1. 捕获。生命周期、effect、ref 或 HostConfig 调用抛错时，safe wrapper 记录 source Fiber。
  2. 定位。沿 return 寻找 class error boundary 或 HostRoot。
  3. 排队。构造 capture update，选择 SyncLane 并重新调度根。
  4. 继续。当前 commit 尽量完成其余必要清理，避免宿主树永久卡在半阶段状态。
  5. 恢复。下一轮 render 产生 fallback 或根级空树；已发生的 mutation 不被事务式撤销。

passive 结束后，根才真正释放本轮缓存

flushPassiveEffects 降到不高于 DefaultEventPriority，清空 pending root 指针，再执行 passive unmount/mount。 组件在 effect 中已有机会 retain 所需 cache 后，root pooled cache 才按 remaining lanes 释放。若 effect 调度同步工作，循环会继续 flush，直到没有待处理 passive/sync work。
