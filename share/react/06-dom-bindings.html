06 · DOM host implementation

DOM bindings：创建节点、提交变化、处理浏览器事件

packages/react-dom-bindings 是 DOM renderer 的实现层：client HostConfig 创建与提交节点，events 建立委托与插件派发， server HostConfig 把 Fizz 输出格式化成 HTML/指令流，shared 保存两端共用规范化规则。

React 19.3.092 个手写 JS 目标client 28events 31server 16shared 17

它在两个引擎与浏览器之间

CLIENT HOST CONFIG

服务 Fiber render 与 commit

实现 create/append/update/remove、selection、hydration、resources、visibility 与 View Transition 能力。

EVENT SYSTEM

把 DOM 输入还原成 Fiber 路径

根委托监听、事件优先级、hydration 阻塞、插件提取与两阶段 listener 累积都在这里。

SERVER HOST CONFIG

服务 Fizz 格式化

把标签/属性/资源与指令编码为 chunk；请求、task、Suspense 状态机属于范围外的 react-server。

与 react-dom 的区别：react-dom 管公开入口与环境适配；bindings 管浏览器机制。 业务调用 createRoot 不会直接 import HostConfig，但 reconciler 的 DOM fork 会静态接入它。

Client HostConfig：一次节点从创建到提交

  1. 上下文。getRootHostContext/getChildHostContext 传播 HTML/SVG/MathML namespace，并在 DEV 维护 DOM nesting 祖先信息。
  2. 创建。createInstance 选择 createElement/createElementNS，缓存 Fiber 指针与 props；finalizeInitialChildren 在新子节点组装后设置初始属性，整个过程仍属于 render 的 complete 阶段。script 使用不可执行创建路径。
  3. 离线组树。appendInitialChild 把新宿主 descendants 组装到尚未进入 container 的父节点。
  4. 提交准备。prepareForCommit 保存 selection/active instance 并暂时关闭事件；mutation 后 resetAfterCommit 恢复。
  5. 写入。appendChild/insertBefore/removeChild/commitUpdate/commitTextUpdate 执行 reconciler 已确定的动作。

这里没有返回“DOM patch 列表”。completeWork 已决定 HostComponent 有 Update flag；commit 时 HostConfig 直接比较 old/new props 并写节点。

属性系统：property、attribute、style 与受控表单不是同一条路径

类别写入策略额外不变量
普通 DOM property/attribute按名称映射、安全性与值类型选择赋 property、set/removeAttribute拒绝非法名称；DEV 诊断未知/错误大小写
boolean / overloaded boolean根据属性语义决定存在性，而非一律字符串化aria/data 保持自定义属性规则
style 对象逐项比较，清旧值再写新值；数字按单位规则转换custom property 与 unitless property 分开
dangerouslySetInnerHTML校验 {__html} 后写 innerHTML不能同时提供 children
input/select/textarea专用 init/update/restore 函数同步 value、checked、default*受控/非受控切换、radio group 与选项顺序

ReactDOMComponent.js 是属性分派主干； ReactDOMInput.js、ReactDOMSelect/Textarea 分别维护表单不变量。 事件结束后 controlled state restore 会把浏览器临时值重新对齐 committed props。

插件：从原生输入得到 React 事件

插件输入输出/职责
SimpleEventPluginclick、key、pointer、mouse 等映射选择 SyntheticEvent 子类，过滤浏览器特殊值

EnterLeaveEventPluginmouseover/out、pointerover/out根据 from/to Fiber 合成 enter/leave 路径
BeforeInputEventPlugincomposition、keypress、textInput归一 composition/beforeInput 字符数据
FormActionEventPluginsubmit解析 action、FormData 与 transition/action 状态

SimpleEventPlugin 按原生 capture/bubble 阶段分别累积；Change、Select、BeforeInput 则只在普通 bubble 路径提取，一次把 capture 回调放到列表前端、bubble 回调追加到末尾。dispatchQueue 再执行这些已排好的列表。 最外 batchedUpdates 结束时，若有受控恢复目标，先冲刷同步更新，再按最终 props 恢复控件。

Hydration：匹配既有 DOM，同时保留事件因果顺序

  1. 进入。hydration root 保留 initial children，HostRoot 进入 hydration state。
  2. 匹配。begin/complete 路径用 canHydrate*、hydrateInstance/Text 寻找并校验既有节点。
  3. 差异。普通属性差异在 DEV 记入诊断表，通常不改写该属性；不兼容的文本或结构交给 reconciler 的 mismatch 路径，放弃受影响边界并客户端重建。
  4. 阻塞事件。若 native target 位于尚未 hydration 的边界，离散事件可尝试同步 hydration；连续事件按类型排队/合并。
  5. 重放。边界提交后 retryIfBlockedOn 解锁匹配的连续槽；重放时重新查 blocker，克隆原生事件经 DOM 派发，由 listener 按事件类别设置更新优先级。同步 hydration 仍受阻的离散 click 不进入该连续队列。

属性差异不会一概“自动修好”：hydration 的安全目标是连接 server DOM 与 Fiber；某些不匹配只在 DEV 报告， 结构性不匹配则放弃该边界。不要把 hydration 描述成普通 client diff。

Server HostConfig：HTML 与恢复指令的编码层

ReactFizzConfigDOM.js 定义 createResumableState/createRenderState、标签/文本序列化、资源 hoist/preload、Suspense 指令与 destination 写出。 但 createRequest/startWork/abort/resume 的任务状态机来自 packages/react-server，不在本次范围。

bindings 负责react-server 负责（范围外）
HTML escaping、标签与属性格式遍历 React tree、创建 request/task/segment
DOM resource hint 与 hoist 规则Suspense 边界完成、错误与 abort 状态
客户端恢复指令的 DOM 编码何时把哪些 completed queue 交给 destination
按 DOM 格式调用已注入的 chunk 写出函数工作调度、背压处理与 request 生命周期

生成文件 ReactDOMFizzInstructionSetInlineCodeStrings.js 由构建脚本产生，明确不作为手写注释目标。
