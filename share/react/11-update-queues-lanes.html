Update Queue 保存因果顺序，Lane 决定这一遍消费哪些更新

调用 setState 并不会立即“改掉 state”。React 先创建 Update、选择 Lane、把 Lane 从源 Fiber 传播到根； 根在微任务中选出下一批 Lanes，render 再从 base state 按原顺序重放符合资格的 Update。

先抓住三个互相独立的维度

WHAT

Update 是“做什么”

Root/Class 的 payload 描述 element 或 state 变换；Hook 的 action 交给 reducer。Update 还携带 lane、callback/eager state 等执行元数据。

WHEN

Lane 是“哪一遍做”

Lane 是位；Lanes 是集合。renderLanes 与 update.lane 做集合包含判断，决定应用、跳过、保留还是回退。

ORDER

base queue 是“按什么历史重放”

若中间跳过低优先级更新，后续已执行更新也会以 NoLane 克隆进新基线队列，保证未来从正确历史重算。

与上一页的连接：Fiber 对象模型解释 current/WIP；本页解释为什么候选树可以丢弃， 更新本身却仍能从 current 的 queue 确定性恢复。

Root.render 与 setCount：payload 不同，入根调度相同

HostRoot：把下一棵 React element 放进 payload

HostRoot 的 memoizedState.element 是根 children 基线；处理这个 Update 后，beginWork 才拿新 element 协调 child Fiber。

Hook：把 action 和可选 eager 结果放进 Update

setCount(1) 的 action 是值 1；setCount(c => c + 1) 的 action 是函数。权威队列消费发生在 render；但 source Fiber 与 alternate 都没有待处理 Lane，且 queue 有 lastRenderedReducer 时， dispatchSetStateInternal 可用 lastRenderedReducer 提前计算 eagerState，并因相同 state 快速退出。这是可缓存的预计算优化，不改变 Update 需保留可重放语义。

render-phase 更新是特例：当前组件 render 内对自身 Hook 的更新写入 queue.pending；模块标记促使 renderWithHooks 再运行组件，rerender dispatcher 单独消费这批更新； 它不代表普通事件 dispatch 会同步递归 render。条件 Hook、跨组件 render 更新仍是错误或受警告的路径。

从叶 Fiber 到根：lanes 标自己，childLanes 标路径

并发入口先把四元组 fiber, queue, update, lane 写入模块级缓冲，并同步标源 Fiber 与 alternate 的 lanes。 缓冲统一收口时，把 Update 接进 pending 环，并沿 return 路径更新父级 childLanes。

这段删节源码止于父链循环中的 alternate 标记；后续还检查隐藏 Offscreen，并在顶点为 HostRoot 时返回 node.stateNode。 同时标两面很重要：当前树和正在进行的候选树都不能因只看自己那一面而错误 bailout。

beginWork 的 bailout 因而有两层：当前 Fiber 自身没有匹配 lanes，仍需检查 childLanes；只有子树也无匹配工作，才可整段跳过。

FiberRoot 的 Lane 状态机：pending、suspended、pinged 不是同义词

集合含义进入离开/改变
pendingLanes根上尚未完成的全部工作新更新、spawned deferred/retrycommit 后以 remainingLanes 重写
suspendedLanes尝试过但被数据/Action/资源阻塞markRootSuspended新非 Idle 更新保守清空；完成时重算
pingedLanessuspended 中已有 wakeable 解决，可重试markRootPinged 与 suspended 取交集再次挂起时移除；完成时重算
warmLanes本轮已探索完整树，无需仅为预热 sibling 再跑完整挂起尝试ping 或新非 Idle 更新清理
expiredLanes等待过久，应防止继续饥饿微任务调度前按 expirationTimes 标记完成时清理
entangledLanes新 render 扩展为相关批次共同处理transition/async action 纠缠相关 Lane 全部完成后清理

“新更新清空 suspended”并非表示 Promise 已解决，而是保守地允许新输入重新尝试此前阻塞的子树；新 props/context 可能绕开旧阻塞。 ping 则严格只唤醒当前仍 suspended 的 Lane，过期 wakeable 不能凭旧回调复活已完成工作。

getNextLanes：先未阻塞，再 ping，再预热

getHighestPriorityLanes 先取候选集合与 SyncUpdateLanes = SyncLane | InputContinuousLane | DefaultLane 的交集；只要交集非空，就返回其中全部 Lane。例如 Sync 与 Default 都未阻塞时，两者同批 render，并非先做 Sync、再单独做 Default。这一步发生在纠缠扩展之前。

随后 getNextLanes 处理只剩 Idle 的同类分支、无候选退出，以及已有 WIP 是否应被中断，然后返回调度候选。它本身不展开 entanglement： prepareFreshStack 后续调用 getEntangledLanes(root, lanes)，才扩展新 render 的资格集合；已经进行中的 render 不会因新 entanglement 立即重新检查。Scheduler callback 优先级仍由未扩展的 nextLanes 决定。 中断规则也不是“只要来了新 Lane 就重启”：只有更紧急工作，或当前 WIP 自己已挂起，才值得丢弃已有进度；当前实现还特意让 Default 更新不打断未挂起 transition。

Lane 到 Scheduler：不是一一对应的优先级枚举

根进入全局 scheduled-root 链后，通常由一个微任务统一运行 scheduleTaskForRootDuringMicrotask。它调用 getNextLanes、取消或复用旧 callback， 最后才把 Lane 组映射到 Scheduler priority。不支持微任务的宿主使用 Immediate task 承接同一调度流程。

nextLanes 主类React 根侧处理Scheduler task
包含 SyncLane 或 SyncHydrationLane，且非 prerender标 callbackPriority = SyncLane；调度轮末同步 flush，同批候选可含 Continuous/Default不新建普通 task
离散 / 连续事件最高 Lane 写 callbackPriorityUserBlockingPriority
不含同步 Lane 的 Default / Transition / 常见 Retry按候选 Lane 组安排根 callback通常映射 NormalPriority
Idle仅无更高未完成工作时选择IdlePriority

root.callbackPriority 保存的是最高优先 Lane，不是 Scheduler priority。这样同为 Normal task 的不同 React Lane 仍可判断能否复用 callback； Lane 承载选择、挂起、纠缠和重放语义。Scheduler priority 负责 host task 的排序、时间预算与过期；callback 的 didTimeout 还可能让根工作以 forceSync 完成，但它不会替 React 选择或重放组件更新。

核心算法：跳过后为什么必须复制“已经执行”的更新

假设 state 初始为 1，队列按调用顺序是低优先 transition T: +10，随后同步 S: ×2。 当前 renderLanes 只有 S。若只跳过 T、执行 S 并把 T 留下，未来从 state=2 再算 T 会得到 12；但按原始因果顺序应是 (1 + 10) × 2 = 22。

这段是 Hook 实现的删节源码，止于普通更新的 NoLane clone。Class/HostRoot 的 processUpdateQueue 使用同一基线思想，但 base queue 是普通单链， 并处理 ReplaceState、callback 与 CaptureUpdate。

NoLane 不表示“删掉更新”：这里的 clone 表示该更新已经在较高优先提交中生效，未来 rebase 必须再次计算它以保持顺序； 设为 0 让所有 renderLanes 都把它视为可执行，Class/HostRoot 的已执行 clone 还会清空 callback，避免未来重放再次触发提交副作用；Hook Update 没有 callback 字段。

真实优先级测试：连续事件能打断 transition

Given：transition 已渲染 A2 但未完成；When：连续事件 Lane 写入隐藏更新；Then：隐藏结果先提交，恢复的 transition 看到子树已隐藏并成为无操作。 这对应 getNextLanes 的“真正更高优先级才中断”规则。反向边界由 ReactTransition-test.js · should not interrupt transitions with normal pri updates 作证：当前实现刻意不让普通 Default 更新抛弃未挂起 transition 的已有进度。

把一次 setCount 串成一屏

异步边界在“根调度微任务 / Scheduler callback”，状态资格边界在“queue 与 renderLanes 的集合判断”，已提交 Fiber 身份边界在“commit 切换 current”；宿主可见写入发生在此前的 mutation。 三者分离，让 React 能同时实现事件优先、可中断计算和确定性状态历史。
