Fiber 不是虚拟 DOM 节点，而是一份可恢复的工作记录

同一个逻辑组件通常有 current 与 work-in-progress 两枚 Fiber。current 是已提交事实，WIP 是可暂停、重启或丢弃的候选； alternate 把两者配对，root.current 则在 commit 中决定哪一面是新的事实。

child / sibling / return：用单链结构编码多叉树

对 App 的三个 child，只在第一个 child 上保存父到子的入口，再用 sibling 串起其余节点。工作循环下钻 child；一个节点完成后，先尝试 sibling， 没有 sibling 才沿 return 回溯。它能把“递归遍历组件树”拆成可暂停的逐 Fiber 状态机。

return 不是 DOM parent：函数组件、Fragment、Context、Suspense 都有 Fiber 却没有对应 DOM；Portal 的宿主容器也可跳出普通父 DOM。 commit 插入节点时必须另行寻找 HostComponent/HostRoot/HostPortal，而不能直接使用 fiber.return.stateNode。

current ↔ WIP：同一逻辑树的已提交面与候选面

从 current 建候选根：中断后可重新开始

  1. 清旧栈。取消未提交的 timeout/pending commit 后，重置模块级工作游标；它不会把半成品设为 current。
  2. 从权威基线起步。createWorkInProgress(root.current, null) 总是以已提交根为输入；旧 WIP 对象可以被复用覆盖。
  3. 绑定本轮 Lane。workInProgressRootRenderLanes 决定队列中哪些更新有资格在这一遍被处理。
  4. 逐 Fiber 推进。beginWork 返回 child 表示下钻；completeWork 完成后走 sibling/return。yield 以 workInProgress 保存下一 Fiber 入口，同时保留 workInProgressRoot、renderLanes、退出/挂起原因以及 Host/Context/Suspense 等显式栈；重启时再沿 return unwind 这些栈。
  5. 退出分类。完成得到 finishedWork；挂起等待 ping；更高优先级到来可重新调用 prepareFreshStack 丢弃本次候选进度。

可中断的真正含义：不是在任意 JavaScript 指令中间暂停，而是在 Fiber 工作单元边界保存下一节点；用户组件的一次函数调用仍是普通同步调用。

因此“双缓冲”不代表两棵树同时对用户生效。只有一个 root.current；alternate 是计算与恢复机制，不是第二套公开 UI。

两种“不要这棵候选树”：放弃 render 与提交删除

ABORT

未提交 WIP 被放弃

更高优先级更新可从 current 重新建 WIP。render 不修改已提交宿主树，所以旧 current 与旧 DOM 继续有效；completeWork 可能已创建并组装未挂载的宿主实例，但它们仍属可丢弃候选。动态 flags、deletions 会在复用时重置。

DELETE

已提交树中的节点被删除

mutation 先断 return，阻止已卸载 Fiber 继续连接祖先；child/sibling/alternate 等要等 passive 清理完成后再断，保证 effect cleanup 仍能遍历。

这不是重复清理：mutation 阶段需要尽早让节点“不再属于已挂载树”，passive 阶段前又不能破坏 effect 遍历所需关系。后半函数还会清 stateNode、dependencies、props/state 与 updateQueue；本页只展示支撑两阶段边界的连续开头。

六条不变量，串起 Fiber 原理

  1. 单一事实：每个根只有 root.current 指向已提交树。
  2. 最多两面：同一协调身份通常复用 current/WIP 两枚 Fiber；alternate 双向配对。
  3. 结构可暂停：child/sibling/return 把递归树展开为可保存游标的工作链。
  4. render 保留已提交宿主树：WIP props/state/flags 和新建的脱离容器实例可反复覆盖；已提交宿主的变更在 commit 执行。
  5. 切换有观察窗口：current 在 mutation 后、layout 前切换。
  6. 清理分阶段：删除先断挂载身份，再等 passive 工作结束后断开完整对象图。
