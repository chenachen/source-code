04 · Fiber engine / render

reconciler：构造一棵可丢弃的候选树

render 阶段把 root 上的更新与当前 Fiber 树合并，生成 work-in-progress 树和 effect flags。 它可以暂停、重启或放弃；真正可见的宿主变更必须等 commit。

双缓冲不等于两棵独立业务树：alternate 把 current 与 work-in-progress 对应节点配对。 render 可反复覆盖 WIP；只有 commit 切换 root.current 后，它才成为下一轮基线。

Root Update：描述第一次获得 Lane

ReactDOMRoot.render 调用 updateContainer。后者读取 HostRoot current，按执行上下文请求 Lane， 构造 payload 为 {element} 的 Update，挂进 root fiber 队列，再调用 scheduleUpdateOnFiber。

  1. 选择。离散输入、transition、render-phase 或默认更新得到不同 Lane 来源。
  2. 入队。并发队列先暂存更新，统一收口时把环形 pending 链并入目标 queue。
  3. 向上。从 source Fiber 沿 return 标记 childLanes，定位 FiberRoot。
  4. 标根。markRootUpdated 合并 pendingLanes，并清理与本次更新冲突的 suspended/pinged 状态。
  5. 调度。root 进入全局 scheduled-root 链；同步 Lane 请求微任务，其他 Lane 映射为 Scheduler callback。

Lane 是集合代数，不是单个数字优先级

Lane 用位表示更新组，Lanes 是位集合。选择下一批工作时还要综合 suspended、pinged、warm、expired、entangled 与正在 render 的 lanes。 Scheduler Priority 只在最终 host callback 边界出现；两者不能一一替换。

ROOT VIEW

pending → suspended / pinged

root 记录哪些 Lane 待处理、哪些因数据挂起、哪些已被 thenable ping 唤醒，以及哪些为防饥饿已过期。

FIBER VIEW

lanes + childLanes

节点自身 Lane 与子树 Lane 共同决定 beginWork 能否 bailout；只比较 props 会漏掉后代或 context 更新。

callbackPriority 保存的是代表本次回调的 Lane。若最高优先 Lane 未变，可复用 callback；若变化，取消旧 Scheduler task 并登记新任务。 同步工作不等待普通 Scheduler callback，而是在微任务末尾统一 flush，避免同一事件中重复提交。

工作循环：下钻 beginWork，回溯 completeWork

beginWork 按 Fiber tag 分派：HostRoot 处理根队列、FunctionComponent 执行 Hooks、ClassComponent 管实例与生命周期、 HostComponent 协调 children、Suspense 决定 primary/fallback。返回 child 表示下钻；返回 null 才开始 complete 回溯。

completeWork 对宿主节点创建/复用 instance、设置初始属性或标记更新，并向父级冒泡 subtreeFlags、lanes 与 profiler 时长。 新建 DOM 此时通常仍在脱离文档的树中；插入真实容器要等 mutation。

children 协调：复用由 type + key + 位置语义共同决定

情况主要动作flags / 结果
同 key、兼容 type复用 alternate，更新 pendingProps保留 state，后续按 Lane 决定是否深入
同 key、不同 type删除旧 Fiber，创建新 Fiber旧子树 Deletion；新节点 Placement
无 key 顺序列表先按位置快速匹配，失配后建 Map插入/移动可能改变局部 state 所属
显式稳定 key 列表Map 以 key 查旧 Fiber，并比较旧 index能识别移动，但跨父节点仍不是同一身份域
剩余旧 child加入父 Fiber deletionscommit 前仍未改真实宿主树

源码核心位于 ReactChildFiber.js。 “没有 DOM diff 对象”是一个重要事实：协调直接构造 Fiber 关系与 flags，HostConfig 在 complete/commit 边界接收具体节点操作。

函数组件 render：dispatcher、hook 链与 render-phase 更新

ReactFiberHooks.js 根据 current hook 是否存在安装 mount/update dispatcher。 每次 hook 调用沿 current 链克隆或创建 WIP hook；state queue 保存 pending 更新、base queue 与最后一次 reducer/state。 dispatch 闭包绑定 Fiber 与 queue，调用时请求 Lane；若在当前 render 内更新，会进入 render-phase 队列并有限次重渲染函数组件。

eager bailout 不是“完全没有更新”：当队列空且 reducer 可立即算出相同 state 时，更新可走快速路径； 但它仍必须保留足够信息，应对稍后高优先级工作或队列重放。

挂起：抛出的 thenable 被转换成根状态

  1. 捕获。组件读取未就绪资源并抛 thenable；work loop 找到可捕获 Suspense 边界。
  2. 标记。边界切换 fallback 或保留旧内容，根记录 suspended lanes；wakeable 被放进 ping cache。
  3. 退出。当前 render 可能完成 fallback、延迟提交、继续 prerender，或返回 RootSuspended/InProgress。
  4. 唤醒。thenable settle 调用 ping listener，把对应 Lane 标为 pinged 并重新安排 root。
  5. 重试。新的 render 从 current 基线建立 WIP；被放弃的半成品不会写进宿主容器。

render 的出口不只有“成功/失败”

退出状态含义下一步
RootInProgress时间片用尽或并发循环 yield保留 WIP，下个 callback 恢复
RootCompleted候选树完成检查外部 store 一致性、准备 commit
RootSuspended / WithDelay等待资源且提交策略可能延迟标根挂起、等 ping 或 timeout
RootErrored并发尝试失败但可同步恢复选择恢复 Lane，重新 render
RootFatalErrored根级不可恢复错误清理 WIP，交给根错误路径
