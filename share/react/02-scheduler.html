scheduler：把工作切成 host 可接受的片段

Scheduler 接收“带优先级、可延迟、可 continuation”的回调，用两个最小堆排序， 再通过环境可用的 host API 分批执行。它调度的是函数，不知道 Fiber、Lane 或 DOM。

先纠正三个常见误解

NOT FIBER

它不选择 React 更新

reconciler 先把根级工作归约成回调与 Scheduler Priority；Scheduler 只决定哪个 callback 先获得 CPU。

NOT PREEMPTION

它不能强行中断 JavaScript

只有 callback 主动返回，或 React 在工作单元边界检查 shouldYield，控制权才回到 host。

NOT DEADLINE ABORT

“过期”不是取消

过期任务会绕过时间片让步并尽快执行；取消则把 callback 置空，之后由堆顶路径惰性清理。

同一 Task 在任一时刻最多属于一个堆。迁移时才把排序键从 startTime 改成 expirationTime； 这让延迟任务不会因“最终很高优先级”而在可运行之前挡住 ready work。

算法一：稳定的数组最小堆

push 把节点放到数组末尾并向上修复，pop 用末尾节点替换根再向下修复，均为 O(log n)；peek 为 O(1)。 比较器先看当前队列的主排序键，再用单调递增 id 保持同键 FIFO。

为什么取消不在任意下标删除？当前 Task 没有维护 heap index；查找并修复任意节点会增加状态与热路径成本。 把 callback 置 null 是 O(1)，代价是取消节点会占内存到它接近堆顶。

算法二：delay 与 priority 共同决定队列

schedule 先得到 startTime，再按优先级加超时预算：Immediate 为 −1ms、UserBlocking 250ms、Normal 5000ms、 Low 10000ms、Idle 用最大 31 位整数。未知优先级按 Normal 预算计算，但 Task 仍保留调用方原值。

work loop：让步、continuation 与重新竞争

workLoop 总是查看 ready 堆顶。未过期任务在 host 要求让步时停止；过期任务继续执行。 执行前先把 callback 置 null，防止错误或重入把同一函数重复消费。返回函数时把它写回同一 Task， 但立即结束本轮 slice，让 continuation 在新的 host task 中重新与更高优先级工作竞争。

shouldYieldToHost 先考虑 renderer 的 paint 请求，再比较本轮已占用时间与 frameInterval。 默认 5ms，WWW fork 为 10ms；这只是 Scheduler slice，不承诺与显示器帧边界对齐。

模块初始化时捕获原生 setImmediate/setTimeout 引用，避免之后的 polyfill 或 fake timer 偷换调度语义。 默认优先 setImmediate，其次 MessageChannel，最后才用 setTimeout，后者可能受到嵌套 timer clamp。

这里故意不 catch 并吞掉用户错误。初始 hasMoreWork=true 意味着 flush 抛错时 finally 仍发送下一条 host message， 原错误照常离开当前 task，后续队列也不会永久滞留。

手工推演：高优先级工作如何插入 continuation

假设默认超时，虚拟时间从 0 开始，Normal 工作 A/B/C/D 每段都在 yield 边界返回同一个 continuation：

  1. t=0。Normal Task N 入 ready 堆，expiration=5000，id=1；host message 被登记一次。
  2. 第一轮。N 输出 A 后返回 continuation；callback 写回 N，expiration 与 id 均不变，本轮返回 true 并登记新 host message。
  3. 插队。新的 UserBlocking Task H 入 ready 堆，expiration=当前时间+250；其排序键小于 N 的 5000，成为堆顶。
  4. 第二轮。workLoop 重新 peek，先执行 H；完成并 pop 后才再次看到 N。
  5. 恢复。N 继续输出 B/C/D。continuation 保留原到期时间，但没有不可中断特权。

完整流程图：一次 callback 的所有出口

  1. 创建：根据 delay 计算 startTime，根据 priority 计算 expirationTime。
  2. 分流：未来任务进 timerQueue；立即任务进 taskQueue；只为最早 timer 或首批 ready work 唤醒 host。
  3. 迁移：timeout 到点调用 advanceTimers；取消节点被丢弃，到期节点改排序键后进 ready 堆。
  4. 执行：未过期且应 yield → 保留堆；callback 抛错 → 原样传播；返回函数 → 保存 continuation；否则完成并 pop。
  5. 续发：仍有 ready work → 新 host task；只有未来 timer → 设最早 timeout；两堆皆空 → 关闭 message loop。
  6. 外部取消：任何时刻 cancel 只清 callback；真正释放发生在堆顶扫描，profiling 记录则即时更新 queued 状态。
