先拿走三个结论

01 / CONTRACT

React 先描述，不直接改 DOM

react 产生带类型标记的元素与上下文描述；是否创建、复用或删除宿主节点，由 reconciler 在后续阶段决定。

02 / STATE MACHINE

Fiber 把计算与副作用分开

render 阶段计算候选树和 flags；complete 阶段可创建和设置脱离容器的 DOM；commit 才修改可见宿主树。放弃候选 render 时，当前 DOM 仍保持已提交状态。

03 / HOST BOUNDARY

DOM 细节集中在 bindings

reconciler 只调用 HostConfig 契约；属性、表单、事件、hydration 等浏览器语义由 react-dom-bindings 落地。

范围与证据边界

本指南覆盖仓库中的 packages/shared、scheduler、react、 react-reconciler、react-dom-bindings 与 react-dom。 版本来自各包 package.json 和 ReactVersion.js；当前快照没有可验证的内层 Git tag/commit，因此不推断上游身份。

SSR 边界：ReactDOM 的流式与静态入口会进入 packages/react-server 的 Fizz 状态机， 但该包不在本次六包范围内。服务端页面只解释 ReactDOM 环境适配层，不把它误称为完整 Fizz 内核。

客户端主线：控制权怎样移动

  1. 描述。JSX 运行时调用 ReactElement 工厂，使用 shared symbol 标记一个不可与普通对象混淆的元素记录。
  2. 入根。react-dom/client 校验 container，创建 ReactDOMRoot，并让 reconciler 创建 FiberRoot。
  3. 入队。root.render(element) 进入 updateContainer，选择 Lane，把 Update 挂到 HostRoot 的 update queue。
  4. 调度。RootScheduler 汇总根的最高优先级；并发工作通过 scheduler 注册 host callback，离散同步工作走同步队列。
  5. render。beginWork 消费 props/update queue 并协调 children；completeWork 创建或复用脱离文档的 DOM 实例并汇总 flags。
  6. commit。before-mutation → mutation → current 指针切换 → layout；DOM bindings 在 mutation 子阶段执行属性和树结构写入。
  7. 收尾。passive effects 在后续边界 flush；unmount 用同一更新管线提交删除并断开 Fiber/DOM 关联。

两个“优先级”不要混为一谈：Lane 是 reconciler 的更新集合与根级调度状态；Scheduler Priority 决定 callback 的过期时间和排序；时间片是否让出还要看 host deadline 与 render 条件。 reconciler 在边界处做映射，但 scheduler 从不读取 Fiber。
