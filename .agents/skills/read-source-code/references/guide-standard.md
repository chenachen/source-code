# 分享级源码教程标准

把源码证据整理成可独立阅读、可分享的教程。读者即使不打开仓库，也应理解系统解决什么问题、为何这样设计、核心机制怎样运行。

## 默认交付

除非用户指定其他格式，完整教程交付一个自包含的单 HTML 文件。

- 内嵌必要样式、脚本和图形，避免依赖 CDN 或网络资源。
- 提供目录、锚点、清晰层级、可读代码块和窄屏布局。
- 保证离线打开仍可完整阅读。
- 追求简洁、优雅和高信息密度，不用装饰代替解释。
- 放入项目约定的文档目录，统一命名和管理，不散落临时版本。

## 内容结构

按以下顺序组织；可合并简单章节，但不得遗漏其信息。

### 1. 结论、范围与阅读地图

- 说明系统目标、核心机制和教程边界。
- 标明仓库版本、tag 或 commit。
- 给出模块地图、依赖关系和推荐阅读路径。

### 2. 问题与设计演进

- 从原始问题、约束和失败模式讲起。
- 解释当前方案解决什么、付出什么代价。
- 历史只写有源码、测试、提交记录或官方资料支撑的内容。
- 没有历史证据时标为“从当前实现推断”，不虚构演进过程。

### 3. 核心对象与系统全景

- 解释关键类型、实例、状态容器及职责。
- 说明创建者、持有者、生命周期和对象关系。
- 先定义共同词汇，再进入模块细节。

### 4. 分模块讲解

按依赖或运行顺序讲模块，不按文件名机械罗列。每个模块至少说明：

- 负责什么、不负责什么；
- 上游输入和下游输出；
- 核心对象、入口函数和关键状态；
- 不变量、边界与错误路径；
- 关键源码怎样实现；
- 测试证明什么；
- 设计原因与权衡。

先讲清各模块，再串联全局调用链。

### 5. 跨模块调用链与状态变化

- 从真实入口追踪到最终结果或副作用。
- 覆盖入口、分派、核心处理、状态写入、外部效果、返回或清理。
- 标明同步/异步边界、条件分支、缓存、错误和提前退出。
- 把关键状态写成“变化前 → 触发动作 → 变化后”。
- 不在串联章节突然引入未解释的新对象。

### 6. 复杂算法深挖

- 先说明目标、输入、输出和约束。
- 再解释数据结构、不变量和主要步骤。
- 用小规模真实输入手工走完整过程。
- 展示支撑结论的最小完整源码片段，并逐段解释职责与原因。
- 补充复杂度、边界、失败模式和替代方案。
- 对项目核心算法单设章节，不埋在普通模块简介中。

### 7. 真实、经典、完整用例

- 优先选仓库测试、官方示例或真实 issue 中能代表主机制的场景。
- 包含 import、准备、输入、调用、中间状态、结果、断言和必要清理。
- 将每一步映射到对应模块、函数和状态变化。
- 明确区分“仓库源码摘录”“教程可运行示例”和“解释性伪代码”。

### 8. 完整执行流程图

至少提供一张以同一个完整 Demo 为主线的端到端流程图。覆盖：

- 当前执行模块、对象和函数；
- 数据与控制权流向；
- 关键条件分支；
- 缓存、标志、版本或其他状态变化；
- 最终结果、异常和清理路径。

图后必须配逐阶段文字解释。关系图不能代替执行流程图。存在三个以上关键状态时，再补状态图或状态表。

### 9. 结论、边界与继续阅读

- 汇总核心设计与关键权衡。
- 指出适用边界、未覆盖分支和版本差异。
- 给出关键源码与测试索引，方便继续深读。

## 源码解释规则

- 每段源码注明文件和符号；行号稳定时再标行号。
- 只摘录支撑当前结论的最小完整片段，避免大段代码倾倒。
- 按“问题 → 源码 → 机制解释 → 对调用链的影响”组织。
- 解释职责、控制流、数据流、状态和设计原因，不逐行翻译语法。
- 重要结论至少由源码、测试或官方资料之一支撑。
- 推断显式标记并说明依据。

## 源码与测试证据门禁

交付前建立“章节 → 源码 → 测试”证据表并逐项核对：

- 每个承担关键机制的模块章节至少包含一段真实源码摘录，覆盖该模块的决定性分支或状态写入；不能只列文件和符号。
- 每条被称为“完整”的端到端调用链至少展示入口、决定状态或副作用的核心实现、异常或清理路径，并映射一个能证明关键机制的真实测试。
- 复杂算法必须给出最小完整实现片段和真实输入推演；纯伪代码或流程图不能替代源码。
- 因篇幅省略的分支必须列入边界与未覆盖范围；不能用“完整指南”掩盖只覆盖主线的事实。
- 源码片段数量不是目标；片段必须足以让读者核验正文中的控制流、数据流和状态结论。

任一关键章节只有概述、文件索引或调用链文字而无源码证据时，教程未完成。

## 全文 QA

交付前检查整份文档，而非只检查最后修改的章节。

- **事实**：文件、符号、调用方向、状态变化和版本信息与源码一致。
- **结构**：模块先分别讲清，再跨模块串联；术语在使用前定义。
- **证据**：设计结论有源码、测试或资料依据；推断已标记。
- **证据门禁**：关键章节和完整调用链均已映射真实源码与代表性测试，不存在纯概述章节。
- **源码**：摘录完整、转义正确；原码、改写和伪代码边界明确。
- **用例**：真实、经典、完整，从输入到断言形成闭环。
- **图示**：与正文一致，覆盖主链和关键异常路径。
- **一致性**：术语、对象名、示例数据和结论全文统一。
- **独立性**：不了解仓库的读者能复述核心对象、主调用链和状态变化。
- **HTML**：离线可打开，无缺失资源、断链、占位符或 `TODO`；目录、锚点、代码块和窄屏布局正常。
- **最终复读**：从头到尾阅读一次，修正局部改动造成的矛盾、跳跃和重复。
